# Changelog

This file records the changes to Rowbly that users can see.

- `### Pre Release` holds the changes for the next release. The `Changelog` Stage of the factory
  adds one entry for each Story.
- The release workflow changes `### Pre Release` to the version, for example `### 1.12.0`. Then it
  adds a new empty `### Pre Release` section above it.

### Pre Release

- Changed: The factory start is faster. Recovery of the Threads now writes `.rowbly/state.json` a maximum of one time, and does not write it when no attempt changed. (ROW-142)
- Added: In the Hosts section of the TUI Settings, push `a` or click the "Add host" button to add a worker host with a form for the ID, the SSH target and the worker limit. Rowbly installs the build on the host, runs the check and shows the new host in the list. (ROW-141)
- Added: In the main view of the Factory controls (`f`), `↑/↓` and the mouse wheel scroll the `Attention` list, and a `↑ n more` row shows the hidden rows above. The new `Dismiss all` button (`d`) dismisses all warnings that you can dismiss, after a confirmation. (ROW-143)
- Added: In the TUI, drag the border between the Stage sidebar and the tag sidebar up or down to change the height of the tag sidebar. The tag sidebar has a new `+ New Tag` button, and `n` in the tag sidebar opens the New Tag form. (ROW-144)
- Changed: The `✕` icon of a Modal and the `⤢`, `⤡` and `✕` icons of the Story sidebar now use one shared TUI component. Their look and their click actions do not change. (ROW-154)
- Changed: The TUI uses one tab component for the Story modal tabs and the `View` and `Edit` tabs of the full screen editor. The tabs look the same as before. (ROW-153)
- Changed: The Custom Field, Tag, Prompt and Stage forms of the TUI now use one shared form component. Their titles, fields and messages do not change. (ROW-155)
- Changed: The status line and the result line of a Thread in the Threads tab of a Story and in the Factory view now use shared TUI components. The text, the colours and the layout do not change. (ROW-152)
- Changed: The rows of the Tags, Custom Fields, Prompts, Stages, AI checks and AI models sections of the TUI Settings now use one shared row component. Their look and their click actions do not change. (ROW-150)
- Changed: The Threads tab of the Story modal and the Story sidebar of the Factory view now use one shared TUI component for the Thread details, the conversation and the steering input. Their look and their keys do not change. (ROW-151)
- Changed: The searchable select field and the searchable multi-select field of the TUI forms now use one shared code path to open the picker. Their keys, hints and modal titles do not change. (ROW-148)
- Changed: The Stage headings of the Story list and the section headings of the Factory view now use one shared TUI component. The count of a selected Stage heading now uses the muted colour, as in the Factory view. (ROW-149)
- Changed: The Story finder of the TUI and the picker of the searchable select fields now use one shared fuzzy search component. Their keys, texts and look do not change. (ROW-147)
- Changed: The Tags and Custom Fields sections of the TUI Settings now use one shared list component. Their text, keys and hints do not change. (ROW-146)
- Changed: The Threads screen and the Threads tab of a Story are faster with many Threads, because the TUI now shows only the Thread rows that are in view. (ROW-145)
- Changed: The `Tags` field of the new Story form and of the General tab now works the same as `Depends on`. Each chosen tag shows on its own line with a `✕`, and `+ add` opens the `Add Tags` picker with fuzzy search. (ROW-160)
- Changed: The TUI updates the board faster when a different process, for example a factory worker, changes a Story file. It reads only the changed Story and not the full board. (ROW-157)
- Fixed: In the TUI, a drag of the right edge of the tag sidebar now changes the width of the Stage sidebar and of the tag sidebar, the same as a drag of the right edge of the Stage sidebar. (ROW-162)

### 0.20.0

- Added: The new Hosts section in the Factory group of the TUI Settings shows the worker hosts and their last check, and sets the placement of new workers. It turns a host on or off for this Project or for all Projects, changes the worker limit and runs the check, and the new `rowbly host update <id> [--max-workers <n>] [--enable | --disable]` command changes a host from the CLI. (ROW-103)
- Added: The paste key of the TUI (`ctrl+v`, or `alt+v` on Windows) and `rowbly add-attachment <story> --from-clipboard` now attach a file that you copied in a file manager, with its name and bytes. On Wayland, a JPEG, GIF or WebP image on the clipboard also attaches. (ROW-109)
- Added: The host agent on a worker host can now run workers. The new hidden `rowbly host prepare`, `rowbly host cache-missing` and `rowbly host cache-put` commands send a copy of the `.rowbly/` files and the attachments to the host, and `rowbly host attach` sends the state of each run, but no command of the main machine uses them yet. (ROW-92)
- Added: Each new Story file has a `uid` frontmatter key with a permanent UUID that does not change when the Story ID changes, and `rowbly --json story get` and `rowbly --json story search` show it. `rowbly doctor` shows a warning for a Story without a `uid` and `--fix` adds one, `rowbly doctor` shows an error for an invalid `uid`, and a custom field cannot use the key `uid`. (ROW-112)
- Added: `rowbly host attach` now also sends the new lines of the session file of each remote worker, so that a later version can show the conversation of remote Threads on the main machine. (ROW-111)
- Fixed: When two Story files have the same Story ID and the same `uid`, for example in two Stage folders, `rowbly doctor --fix` and the TUI board load now remove the old copy and keep the copy with the newest `updatedAt`, for example `ROW-78: removed the old copy in DONE`. If the copies have different content, `rowbly doctor` shows an error and Rowbly does not change a file. (ROW-114)
- Changed: New factory attempts in `.rowbly/state.json`, worker Threads, outbox entries of worker hosts and attachment records in `.rowbly/attachments/<ID>/manifest.json` now keep the `storyUid` of their Story. Rowbly finds the Story of these records by its `uid` first and then by the Story ID, so old records stay valid. (ROW-113)
- Added: A worker that the host agent runs on a worker host now has the `run_check` tool, and runs each check of the `checks` config in its worktree on that host. `rowbly host attach` sends the status of the checks of each run, and a stop or cancel of the run also stops its checks. (ROW-93)
- Added: The factory can now send a worker to a worker host, follow its run, apply the outbox of the host to the board before the Thread completes, and skip the Story with `waiting for host sync` until the host is synchronized. The hidden `rowbly host outbox`, `rowbly host outbox-ack` and `rowbly host blob` commands accept a project id, and the new hidden `rowbly host run-paths` command gives the run paths of the host, but the factory does not use real worker hosts yet. (ROW-96)
- Fixed: When two different Stories (different `uid`) have the same Story ID, `rowbly doctor --fix` and the TUI board load now give the newer Story a new number also when the two Stories have factory state. The re-numbered Story keeps its worktree, branch, attempts, Threads and attachments, and `rowbly doctor --fix` lists the references that stay with the Story that keeps the ID. (ROW-115)
- Added: `rowbly factory run` now sends workers to the worker hosts in `~/.rowblyrc.json` that are on and that use the Project. The factory checks each host in the background, installs the same Rowbly version on the host when it is different, and does not send new workers to a host that is not ready. (ROW-116)
- Added: The new `rowbly get-attachment <story> <id>` command shows an attachment and the absolute path of its file. On a worker host, it gets a file that is not on the host from the main machine through `rowbly host attach`, and gives `CONFLICT` with the reason when the host is offline or the main machine cannot send the file. (ROW-110)
- Fixed: When a worker host disconnects while the factory runs, its remote Threads keep their status, and the factory sends no new workers to the host. A stop or cancel of a remote Thread waits in `.rowbly/runtime/hosts/<host>/commands.json` until the host reconnects, `rowbly factory stop` also stops the workers on the worker hosts, and the new hidden `rowbly host ping` command shows that a host is alive. (ROW-97)
- Added: `rowbly factory status --json` and `status.json` now give the last contact time and the latency of each worker host, and the factory shows an attention entry when a worker host is disconnected or cannot connect. `rowbly thread list`, `rowbly thread show` and `rowbly status` show `connection lost` for each running remote Thread whose host is not connected, with the time since the last contact. (ROW-100)
- Added: Peek, `rowbly thread log` and the `inspect_worker` tool of the supervisor now show the conversation of a remote Thread from a copy of its session file on the main machine, also while the worker host is offline. After a reconnect and at the end of a run, the factory gets the missing session lines from the host with the new hidden `rowbly host session-bytes` command. (ROW-101)
- Added: A change of the `.rowbly/` files on the main machine, for example a new Story, a changed Story field, an attachment or a Stage prompt, now goes to the copy of each running remote Thread with the new hidden `rowbly host inbound` command. A value that the worker changed in its copy stays, and the updates wait in `.rowbly/runtime/hosts/<host>/threads/<thread-id>/inbound.json` while the host is offline. (ROW-98)
- Added: When you cancel a remote Thread while its worker host is offline, the factory stops the worker first on reconnect and holds the later changes of that Thread in `.rowbly/runtime/hosts/<host>/held/<thread>/`, and does not apply them to the board. An attention entry shows the held changes, and the new `rowbly thread held <id> [--apply | --discard]` command lists, applies or deletes them. (ROW-99)
- Added: The new `factory.fallbackWorkerModels` setting gives an ordered list of worker models, and `rowbly factory configure --fallback-worker <provider/model>` (repeat the flag) sets it and `--clear-fallback-workers` removes it. When the provider of the worker model is paused, the factory starts the worker with the first model of the list whose provider is not paused, or skips the Story with `provider paused`. (ROW-121)
- Fixed: After a restart of the factory, remote Threads keep their status, and the new factory follows their runs on the worker host with the new hidden `rowbly host runs` command. A remote Thread now resumes only on its own worker host, and a resume gives `CONFLICT` when that host is not connected or has no free slot. (ROW-117)
- Added: When a worker reports blockers or problems, or fails with an error that is not a network error, the factory shows the attention entry `worker:<ID>` with the Stage, the Thread, the outcome and the first blockers and problems. A later worker of the Story that ends without problems removes the entry, and the factory also removes it when the Story leaves that Stage or is deleted. (ROW-122)
- Changed: New end-to-end tests run the factory with worker hosts in the test process. They check a full remote run, a cancel while a host is offline, the changes of the board that go to a running remote Thread, the placement of workers and the attachments in the two directions. (ROW-104)
- Added: The TUI shows the worker hosts and the remote Threads. Factory controls show a `Hosts` list with the state, the used slots and the last contact of each worker host, the `▶` marker and the Thread rows show the host of a remote worker and `connection lost` when the host is not connected, and in the Threads tab of a Story, `a` applies and `d` discards the held changes of an abandoned Thread. (ROW-102)
- Changed: The factory now sets the class of each Stage by a fixed rule and not by the supervisor: a Stage with an empty prompt is `invalid`, the first and the last Stage of the board are `hold`, and all other Stages are `work`, so a new Stage with a prompt gets workers at once. A middle Stage that the supervisor classified as `hold` is now `work` until you set `factory.stageClasses` with `rowbly factory configure --stage <key> --class hold`, and `--clear-class` removes the setting. (ROW-120)
- Changed: The TUI renders fewer parts of the screen on each key. For example, an arrow key on the board renders only the Story list and the footer again, and not the header, the Stage sidebar or the overlays. (ROW-130)
- Changed: The Story list of the TUI now builds its rows faster on a large board, and a key that only moves the cursor does not build the rows again. (ROW-131)
- Changed: The TUI does less work on each key in a long list or form, because only the selected row or the active field measures its size. The selected row continues to scroll into view. (ROW-127)
- Changed: The TUI now loads React in production mode, so the board renders faster. When you set `NODE_ENV`, Rowbly keeps your value, and the processes that Rowbly starts do not get a changed `NODE_ENV`. (ROW-126)
- Added: The new `rowbly thread release <id>` command stops a worker on a worker host as a cancel, but the Story does not wait for you or for that host, so the factory can start a new worker for the Story, for example on the main machine. When the host is offline, the Thread becomes abandoned with the reason `release`, and its later changes are held as for a cancel. (ROW-119)
- Changed: The README has a new "Remote worker hosts" section that tells how to add, log in, use and check a worker host with `rowbly host` and how to set the placement with `rowbly factory configure --placement`, and the README no longer says that more than one machine is not supported. The contributor documentation has a new overview page of the remote worker hosts. (ROW-105)
- Changed: The `Depends on` field of the new Story form and the edit Story form now opens faster on a large board, because the TUI finds the Stories that you can select in one pass and only when the Stories change. (ROW-132)
- Changed: The factory now starts the workers itself from its rules and the factory settings, without a supervisor session, so it makes no model call when no worker runs. The new `rowbly factory release <story-id>` command releases a parked Story in the running factory, and `status.json` no longer has `supervisorThreadId`, the holds or the notes. (ROW-124)
- Changed: In the TUI, a Stage move, a save or a delete of a Story now shows on the board at once, and Rowbly reads the Story files one time for each action, not two times. The TUI repairs duplicate Story IDs only when it first loads a Project, not on each refresh. (ROW-133)
- Changed: All spinners in the TUI now share one animation clock, so the TUI redraws one time for each spinner frame, and no spinner timer runs when no spinner shows. (ROW-128)
- Changed: The TUI board now refreshes faster on a large Project, and Rowbly reads `.rowbly/state.json` again only when the file changed. (ROW-134)
- Changed: The TUI does less work on each mouse move, because it measures only the parts of the screen that use the move, and it measures each part one time for each frame. Clicks, hover, drag and drop, resize and the mouse wheel operate as before. (ROW-135)
- Added: When the Project has tags, the left sidebar of the TUI has a new "Tags" Panel below the "Stages" Panel. Select a tag in it to show only the Stories with that tag, together with the Stage filter. (ROW-138)
- Changed: An idle TUI now renders less often. The run time of a running Thread updates each second only while the Factory view, the Thread pane or the Threads tab shows it, and the 5 s factory status poll causes no render when the status did not change. (ROW-129)
- Changed: The TUI and the factory now watch only the Story, attachment, Spec, Stage and prompt folders and the state files of `.rowbly/`, and share one watch for each folder. A write of session data or logs in `.rowbly/runtime/` no longer wakes the TUI or the factory. (ROW-136)
- Removed: The supervisor model setting, the `--supervisor` and `--supervisor-thinking` flags of `rowbly factory configure`, the Supervisor prompt, the live supervisor view of the Factory modal and the supervisor model of the AI settings. `rowbly prompt get supervisor` and `rowbly prompt set supervisor` give a `VALIDATION` error, `rowbly init` no longer creates `.rowbly/prompts/SUPERVISOR.md`, and `rowbly doctor` shows a warning for an old `factory.supervisorModel` key (`--fix` removes it) and for an old `SUPERVISOR.md` file. (ROW-125)
- Added: The new `factory.tagWorkerModels` setting selects the worker model for the Stories with a tag, in all Stages. `rowbly factory configure --tag <value> --worker <provider/model>` sets a rule and `--clear-worker` removes it, a Story override has priority over a tag rule and a tag rule has priority over a Stage override, and `rowbly doctor` shows a warning for a rule of a tag that is not in the Project. (ROW-123)
- Changed: The TUI page of the contributor documentation has a new Performance section. It gives the method to profile the TUI again, and the numbers before and after the performance changes, for example 1.0 s of CPU time in place of 6.6 s in a 12 s board session. (ROW-137)
- Changed: The TUI now starts with less CPU work in the background, because the Pi SDK preload also uses the compile cache in `<XDG_CACHE_HOME>/rowbly/compile-cache`. With a warm cache, the background Pi load uses 716 ms of CPU time and not 871 ms, and `NODE_COMPILE_CACHE` and `NODE_DISABLE_COMPILE_CACHE` also apply to it. (ROW-140)
- Changed: The TUI now loads the Settings Modal, the Factory Modal, the Checks Modal and the onboarding steps only when they open, so that the board shows sooner at launch. (ROW-139)

### 0.19.0

- Added: In the Factory view, a Thread that is open in the Story sidebar has an `Open Story` button with the key `o`. The button shows the Story list and opens the Story of the Thread in the Story sidebar. (ROW-70)
- Added: Each Stage in `.rowbly/rowbly.config.json` can have the optional `expandedByDefault` key. When it is `false`, the section of that Stage in the All Stages view of the TUI is collapsed when a Project opens. (ROW-72)
- Changed: Each Story file is now in the folder of its Stage, for example `.rowbly/stories/BACKLOG/ROW-1.md`, and Rowbly moves the file when the Stage of the Story changes. Rowbly still reads Story files directly in `.rowbly/stories/`, `rowbly doctor` shows a warning for a Story file that is not in the folder of its Stage, and `rowbly doctor --fix` moves it. (ROW-69)
- Added: When the connection to an AI provider fails, the factory pauses that provider for 1 minute, and doubles the pause for each new connection failure up to 15 minutes. The factory then continues the stopped Threads automatically, the Factory controls show `Provider <id> is paused (network)`, and `rowbly factory status --json` has the new `connectivity` field (`online`, `degraded` or `offline`). (ROW-71)
- Added: The TUI shows the connection state of the factory. The Factory button in the header shows `Factory offline` or `Factory degraded`, a Thread that stopped because of a network failure shows `waiting for network`, and a queued Story whose provider is paused because of the network shows `waiting for the network until <time>`. (ROW-73)
- Added: The Story sidebar of the TUI has an expand button and the key `ctrl+o`, which make the Story sidebar cover the Story list and then collapse it again. The new "Story sidebar" option in the Display section of the Settings (`display.storySidebar` in `.rowbly/rowbly.config.json`) sets how the Story sidebar opens: `regular`, `expanded` or `remember`. (ROW-77)
- Changed: In the Factory view, the mouse wheel scrolls the conversation of a Thread in the Story sidebar also when the Story sidebar does not have the focus, and moves the focus to the Story sidebar, as the Story list does. (ROW-74)
- Added: Stories can have tags. The new `rowbly tag list|add|update|remove` commands manage the tags in `tags` of `.rowbly/rowbly.config.json`, `rowbly story create|update` have the `--tag`, `--add-tag` and `--remove-tag` flags, `rowbly story search --tag` shows only the Stories that have all the given tags, and `rowbly tag remove` also removes the tag from each Story. (ROW-79)
- Added: In the Factory view and in the Threads tab of a Story, `ctrl+f` shows the conversation of the open Thread over the full terminal. `ctrl+f`, `esc` or the `✕` closes the full-screen view, and the Thread stays open. (ROW-75)
- Added: You can send a message to a running worker Thread. In the Threads tab of a Story and in the Factory view, push `m` to type in the input under the conversation and push `enter` to send the message, or use the new `rowbly thread steer <id> --message <text>` command. (ROW-76)
- Added: The TUI shows and changes Story tags. The new "Tags" section of the Settings adds a tag, changes its label and removes it, the new Story form and the edit Story form have a "Tags" field, and each Story row in the Story list shows the labels of the tags of the Story. (ROW-80)
- Fixed: When two Story files have the same Story ID, `rowbly doctor --fix` and the TUI board load give the newer Story the next free number and show a notice, for example `ROW-77 → ROW-79: duplicate ID`. The older Story and a Story that the factory works on keep the ID. (ROW-81)
- Changed: In each Stage, the TUI board, `rowbly story search` and `rowbly story get` show the Stories in the order of their `updatedAt` time, with the most recently changed Story first. `rowbly story update` does not have the `--position` flag any more, and in the TUI, `shift+↑/↓` and a drag move a Story only to a different Stage. (ROW-78)
- Added: Each worker Thread records the host that runs it, for now always `local`. `rowbly thread list` and `rowbly thread get` show the host, and `rowbly factory status --json` has the new `host` field on each Thread. (ROW-83)
- Changed: Rowbly has a new internal SSH transport for the connection from the main machine to remote worker hosts. No command uses it yet. (ROW-85)
- Changed: The factory now starts, stops, cancels and steers each worker through one executor interface, so that a later version can run workers on a different host. The behavior of the factory does not change. (ROW-82)
- Added: The new `rowbly host add <id> --ssh <target> --max-workers <n>`, `rowbly host list` and `rowbly host remove <id> [--purge]` commands record the remote worker hosts in the `hosts` key of `~/.rowblyrc.json`. `rowbly host remove` refuses to remove a host while a Thread of a known Project is active on it. (ROW-84)
- Added: When the `ROWBLY_OUTBOX` and `ROWBLY_THREAD_ID` environment variables are set, each Story change that a `rowbly` command makes adds one line to `$ROWBLY_OUTBOX/outbox.jsonl`, and Rowbly refuses all other changes to the Project with a `CONFLICT` error. A later version uses this outbox to send the changes of remote workers to the main machine. (ROW-90)
- Added: When the `ROWBLY_OUTBOX` and `ROWBLY_THREAD_ID` environment variables are set, `rowbly add-attachment` and `rowbly remove-attachment` also add one line to `$ROWBLY_OUTBOX/outbox.jsonl`, and each added PNG is kept in `$ROWBLY_OUTBOX/blobs/`. The new hidden `rowbly host blob <sha256>` command writes one of these PNG files to stdout. (ROW-91)
- Added: The new `placement` key in the `factory` section of `.rowbly/rowbly.config.json` and the new `rowbly factory configure --placement <policy>` flag set how the factory selects the host of a worker: `prefer-local` (the default), `most-free` or `prefer-remote`. `rowbly factory status --json` has the new `hosts` list with the worker slots of each host, and the supervisor can request a host for a worker. (ROW-95)
- Added: In the Story list of the TUI, you can select more than one Story. Push `space` on a Story, move the cursor with `↑/↓` and push `space` again, or use `shift+click`, then push `shift+↑/↓` to move all selected Stories to the previous or next Stage, and push `esc` to clear the selection. (ROW-106)
- Added: `rowbly host add` now checks that the host has Node 22.19.0 or later, and installs the exact Rowbly version of the main machine in `~/.local/share/rowbly/versions/<build-id>/` on the host when that version is missing. If the check or the install fails, `host add` fails and does not change `~/.rowblyrc.json`, and the JSON result has the new `install` object. (ROW-86)
- Added: The main machine can apply the outbox entries of a remote worker host to the Story files, and keeps a conflicting PNG in `.rowbly/runtime/hosts/<host>/conflicts/`. The new hidden `rowbly host outbox` and `rowbly host outbox-ack` commands read and remove the outbox entries on the worker host. No command of the main machine uses this yet. (ROW-94)
- Added: The new `rowbly host use <id> [--path <dir>]` command turns a worker host on for the current Project and clones the `origin` repository into `~/.local/share/rowbly/projects/<project-id>/repo` on the host, or uses the existing clean clone at `--path`. The new `rowbly host unuse <id>` command turns the host off for the Project and keeps the clone on the host. (ROW-88)
- Added: In the General tab of the Story sidebar of the TUI, a click on a Story in the `Depends on` list or the `Blocks` list opens that Story in the Story sidebar. If the form has unsaved changes, the TUI asks before it discards them. (ROW-107)
- Added: The new hidden `rowbly host serve`, `rowbly host submit` and `rowbly host attach` commands run the host agent on a worker host, but no command of the main machine uses them yet. The host agent keeps the commands of the main machine with receipts, limits the workers of all Projects on the host with `~/.local/share/rowbly/slots/limit.json`, and stops when it has no work. (ROW-89)
- Added: The new `rowbly host check <id>` command shows if a worker host is ready: SSH, Linux, `flock`, Git, Node, the Rowbly version, the Pi login, the worker models, the clone, Git push access, `gh`, the Git identity and local commits that are not on `origin`. The new `rowbly host login <id>` command logs in to Pi on the host in a terminal, and `rowbly host add` now shows the items that you must do. (ROW-87)
- Added: `rowbly add-attachment <story> <file>` and the "New file" button of the Attachments tab in the TUI attach a file of any type of 10 MiB or less to a Story, for example a PDF, a JPEG or a text file. `--from-clipboard` and the paste key of the TUI still read only a PNG image. (ROW-108)

### 0.18.0

- Added: Story files can have a `dependsOn` list of upstream Stories. `rowbly story delete` removes the deleted Story from each `dependsOn` list and shows a warning for each changed Story. (ROW-59)
- Added: `rowbly doctor` finds bad `dependsOn` lists in Story files, for example unknown IDs, self dependencies, duplicates and cycles. `rowbly doctor --fix` repairs the safe problems. (ROW-61)
- Added: `rowbly story create` and `rowbly story update` have the `--depends-on` flag, and `rowbly story update` has `--add-dependency` and `--remove-dependency`. `rowbly story get` shows `Depends on`, `Blocks` and `Blocked`, and `rowbly story search` has the `--blocked` and `--ready` filters. (ROW-60)
- Added: The factory does not start a worker for a blocked Story. When the worker limit applies, the factory starts the upstream Stories first. (ROW-62)
- Added: The message of a factory worker lists the upstream Stories of its Story, with the ID, the title, the Stage and each `url` field, for example `pull_request`. A rule tells the worker not to do the work of the upstream Stories again. (ROW-64)
- Added: The factory supervisor sees the dependencies of each Story, and the factory shows an attention entry when an upstream Story of a blocked Story cannot progress, for example in Backlog, parked or in a hold Stage. (ROW-63)
- Added: The TUI shows and changes the `Depends on` list of a Story in the new Story form and in the General tab, and the General tab shows the `Depends on` and `Blocks` lists. A blocked Story row on the board shows `⊘`, and a blocked Story in a work Stage shows `waiting for <IDs>`. (ROW-65)
- Added: The new factory setting `dependencies.pullUpstream` moves a stuck upstream Story from Backlog to the first work Stage, so that its blocked downstream Stories can continue. The setting is off by default, and `rowbly factory configure --pull-upstream on|off` and the "Pull upstream Stories" card on the Settings › AI › Limits tab change it. (ROW-66)
- Changed: `pnpm lint` accepts the TanStack Router file names in `website/src/routes/`, for example `__root.tsx`, `$story-key.tsx` and `(legal)/`. The Biome config file is now `biome.jsonc`. (ROW-58)
- Added: The new `website/` folder has the base of the rowbly.com website, made with TanStack Start, Tailwind CSS and shadcn/ui. The new `pnpm website:dev` and `pnpm website:build` scripts run and build it. (ROW-45)
- Added: The new `website.yml` workflow deploys the website to GitHub Pages at `https://rowbly.com` when `main` changes, and only builds it for a pull request. The website has a branded 404 page. (ROW-46)
- Added: The rowbly.com website has a header, a footer, a favicon and a web manifest on each page, and placeholder pages for `/how-it-works` and `/install`. It also has shared components for the terminal frame, the install command with a copy button, the keycap, the page section and the agent tag. (ROW-47)
