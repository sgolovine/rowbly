## Goal

A TUI user can filter the Story list by tag. Today the TUI has only the Stage filter in the left sidebar. ROW-79 added tags and `rowbly story search --tag`. ROW-80 added tags to the TUI, but a filter by tag was not in its scope.

Original request of the author:

- Whenever a user has tags defined, we split the sidebar on the left hand side into two components.
- The top component should be the stage filter.
- The bottom should be a tag filter.

## Scope

In scope:

- When the Project has one or more tags (`projectTags(board.project).length > 0`), the left sidebar has two Panels: the Stage sidebar ("Stages") at the top and a new tag sidebar ("Tags") at the bottom.
- When the Project has no tags, the sidebar is the same as today (only the Stage sidebar).
- The tag filter limits the Story list to the Stories that have the selected tag. It works together with the Stage filter (a Story must agree with both filters).
- The focus, keys, mouse, footer hints and help text of the tag sidebar.
- The update of `docs/architecture/tui.md` and of the doc comment of `Shell` (`src/tui/shell/shell/shell.tsx`) in STE.

Not in scope:

- A filter by tag in the Story finder.
- A filter by tag in the Factory view (the Threads list).
- A selection of more than one tag.
- Changes to the tag service, the config, the Story service or the CLI.
- An add, edit or remove of a tag from the tag sidebar (Settings does this).
- TUI tests (the repository does not test TUI components).

## Acceptance criteria

- [ ] In a Project with no tags, the left sidebar shows only the "Stages" Panel, the same as before this change. A person examines this in the TUI.
- [ ] In a Project with one or more tags, the left sidebar shows the "Stages" Panel at the top and a "Tags" Panel below it, in the same column and with the same width. The "Tags" Panel has the entry "All Tags" first, then one entry for each tag in config order, with the tag label. A person examines this.
- [ ] "All Tags" is selected at the start. With "All Tags", the Story list is the same as before this change.
- [ ] When the user selects a tag, the Story list shows only the Stories whose `tags` include the value of that tag. This works with "All Stages" (sections with headings) and with one Stage selected. A person examines this.
- [ ] The title of the Story panel shows the tag: `<project> › <Stage label or All Stages> › <tag label>` while a tag is selected. Without a tag, the title is the same as before.
- [ ] The empty text of the Story list names the tag when a tag is selected, for example `No Stories with the tag <label>.` (with a Stage: `No Stories in <Stage> with the tag <label>.`).
- [ ] `tab` moves the focus in this order: Stage sidebar, tag sidebar, Story list, Story sidebar (when open). `shift+tab` goes in the opposite order. When the tag sidebar is not shown, the order is the same as before.
- [ ] While the tag sidebar has the focus, `↑/↓` (and the keys of `moveDelta`) select the previous or next entry, and `esc` gives the focus to the Story list. The Stage keys (`n`, `e`, `shift+↑/↓`) do nothing in the tag sidebar. `[`/`]` still change the Stage filter from all panes.
- [ ] A click in the tag sidebar gives it the focus. A click on an entry selects that entry. The wheel selects when the entries do not fit (the same behavior as the `Sidebar` component today).
- [ ] The footer and the help Modal show the keys of the tag sidebar while it has the focus (for example `↑/↓ filter by tag`, `tab`, `esc`).
- [ ] `ctrl+b` hides and shows both Panels together.
- [ ] When the selected tag is removed in Settings, the filter goes back to "All Tags" (the list shows all Stories again) and the app does not crash. When the last tag is removed, the tag sidebar disappears; if it had the focus, the Story list gets the focus.
- [ ] When a Story opens from the Story finder, from a Thread or from a dependency link, or after a save, and the Story does not have the selected tag, the tag filter goes back to "All Tags" so that the Story shows in the list (the same as the Stage filter in `reveal`).
- [ ] A Project switch resets the tag filter to "All Tags".
- [ ] In a narrow terminal (stacked layout), both Panels show above the Story list and the Story list keeps at least half of the main area. A person examines this.
- [ ] `docs/architecture/tui.md` describes the tag sidebar, in STE.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

- Panes: `Pane` in `shell-state.ts` is `"stages" | "stories" | "story"`. Add `"tags"`. Update `paneOrder`, `focusedPane`, `cyclePane` and `escapeKey` in `shell-keys.ts`, and add a `tagSidebarKey` for `↑/↓`. Route the keys in `paneKey`.
- View: `src/tui/shell/shell/shell-view.ts` — `ShellView` gets `tags` (the `TagConfig[]` of the Project, from `projectTags(board.project)` in `src/services/config/config.ts`), `tag` (the selected `TagConfig`, or `undefined` when the value is not in the config, which also covers a removed tag), `tagIndex` (0 for All Tags), `tagSidebar` (sidebar shown and tags exist) and `tagSidebarFocused`. `listFocused` must be false while the tag sidebar has the focus. `sidebarFocused` stays the Stage sidebar.
- Rows: `shellRows` (`shell-view.ts`) gets the tag value and filters `visibleStories` with `story.tags.includes(tag)` before `storyListRows`. Pass all Stories as the `all` argument, so the dependency index stays complete. Pass only a tag that exists in the config. Update the `useMemo` that calls `shellRows` (find it in `use-shell-data.ts` or `use-shell.ts`).
- Selection: `src/tui/shell/shell/shell-selection.ts` — add `selectTag(env, index)` and `filterTag(env, id)` (an `ALL_TAGS` id, for example `"*"`, the same as `ALL_STAGES`). - Props: `src/tui/shell/shell/shell-props.ts` and `use-shell-props.ts` — add `tagEntries(tags)` (All Tags, then `{ id: tag.value, label: tag.label }`; not editable, not movable) and `tagSidebarProps`, with no button. - Render: `src/tui/shell/shell/shell.tsx` — when the tag sidebar shows, put the two `Sidebar` components in one column `Box` (beside layout) with the width of the sidebar. Only the Stage sidebar keeps `onResize`; the resize changes the width of both.

- `n` in the list creates a Story in the Stage of the filter, as today. It does not add the selected tag.
- Do not change `src/tui/components/sidebar/sidebar.tsx` if it is not necessary. Use only `theme` colours. Read the `rowbly-tui-design` and `rowbly-code-style` skills first.

## Assumptions

- The user can select only one tag at a time, with an "All Tags" entry first. Reason: this is the smallest scope, it is the same as the Stage filter, and the `Sidebar` component selects one entry.
- "All Tags" is the first entry and the default. Reason: the Stage sidebar has "All Stages" in the same place, and with no filter the list must be the same as today.
- `tab` goes Stages → Tags → Story list → Story sidebar; `↑/↓` select in the tag sidebar; `esc` gives the focus to the list; a click gives the focus. Reason: this is the same as the Stage sidebar, and the tag sidebar is between the Stage sidebar and the list on the screen.
- `[`/`]` stay Stage keys, and no new global tag key is added. Reason: smallest scope; no free key was requested.
- A selected tag that is no longer in the config acts as "All Tags". When no tags remain, the tag sidebar hides and the focus goes to the list. Reason: the Stage filter already acts like this for a Stage that is gone (`ShellView.stage`).
- The tag filter does not apply to the Factory view. Reason: the author asked for a filter of the Story list only, and Threads do not have tags.
- A new Story does not get the selected tag, and `reveal` clears the tag filter when a Story does not have the tag. Reason: smallest scope, and the same behavior as the Stage filter in `reveal`.
- The tag sidebar has no button. Reason: the user adds tags in Settings (ROW-80).
- The tag sidebar shows the tag label, not the value. Reason: ROW-80 shows labels on the Story rows.
