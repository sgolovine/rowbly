## Goal

`src/tui/components/spinner/spinner.tsx` starts its own `setInterval` of 80 ms for each mounted `Spinner`. Each tick is a React commit, and each commit lays out the full tree (see the Story about row measurement). The `Spinner` is used directly by `ToastLine` (pending toasts) and through `Loading` in approximately 20 screens. When more than one Spinner is visible, the TUI does one commit for each Spinner on each tick.

The result for the user: all Spinners share one clock, so the TUI does a maximum of one spinner commit for each tick. When no Spinner is mounted, no spinner timer runs.

## Scope

In scope:

- A new shared frame clock module, outside `src/tui/`, with no import of `react` or `ink`. It holds a subscriber count, starts one timer at the first subscriber and stops the timer when the last subscriber leaves.
- A test of the clock module next to it.
- `Spinner` reads the frame from the shared clock with `useSyncExternalStore`, and does not have its own `setInterval`.
- The public API of `Spinner` and `Loading` (`src/tui/components/spinner/index.ts`) does not change. No call site changes.

Not in scope:

- A change of the frame interval. Keep 80 ms (see Assumptions).
- The 1-second `setNow` timers in `checks-modal.tsx`, `use-threads-tab.ts`, `use-thread-pane.ts` and `use-factory-view.ts`.
- Row measurement and other performance work (other Stories of the `performance` tag; ROW-137 profiles the result).

## Acceptance criteria

- [ ] `src/tui/components/spinner/spinner.tsx` has no `setInterval` and no `setTimeout`. Examine with `grep -n "setInterval\|setTimeout" src/tui/components/spinner/spinner.tsx` (no output).
- [ ] A Vitest test of the clock module, with fake timers (`vi.useFakeTimers()`), shows that two subscribers cause exactly one timer (`vi.getTimerCount() === 1`).
- [ ] The test shows that with no subscribers there is no timer (`vi.getTimerCount() === 0`), before the first subscribe and after the last unsubscribe.
- [ ] The test shows that a subscriber that unsubscribes while other subscribers stay does not stop the timer, and that a subscribe after the timer stopped starts a new timer.
- [ ] The test shows that after one interval each subscriber is called and the frame index advances by one, and that the index wraps to 0 after the last frame.
- [ ] Unsubscribe two times with the same function does not make the subscriber count negative (the test examines that a later subscribe still starts the timer).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
- [ ] Manual (person only): in the TUI, a pending toast and a `Loading` line spin together, at the same speed as before.

## Technical notes

- Current code: `src/tui/components/spinner/spinner.tsx` (the `Spinner` and `Loading` components, `FRAMES` has 10 braille frames, 80 ms).
- Put the clock in `src/services/frame-clock/frame-clock.ts` with `src/services/frame-clock/frame-clock.test.ts`. Reason: `docs/architecture/testing.md` forbids tests in `src/tui/`, and the Story requires a test of the clock. The module must not import `react`, `ink` or `commander` (service-layer rule).
- Suggested API: `createFrameClock({ frameCount, intervalMs })` that gives `{ subscribe(listener): () => void; frame(): number }`, plus one module-level shared instance for the Spinner, or export the factory and create the shared instance in `spinner.tsx`. The factory makes the test independent of the shared instance.
- `subscribe` and the snapshot function must have stable identities, as `useSyncExternalStore` needs. Use the same pattern as `src/tui/hooks/toasts.ts` (`useSyncExternalStore(store.subscribe, store.list)`).
- Keep the state in a `Store` from `src/services/store/store.ts` (`withMember` / `withoutMember` for the listener set), as the `rowbly-code-style` skill requires. The subscriber count is the size of the listener set; a `Set` also makes a second unsubscribe safe.
- Do not call `timer.unref()`. The timer runs only while a Spinner is mounted, and the TUI must keep it alive.
- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` before the change. Use `.js` extensions in relative imports.
- Run `pnpm knip` to make sure that no new export is unused.

## Assumptions

- Keep the 80 ms interval. Reason: the Story says "consider" a slower rate only if the animation still looks smooth; only a person can judge that, and the shared clock already removes the extra commits. A later Story can change the constant.
- Put the clock under `src/services/` and not under `src/tui/`. Reason: tests in `src/tui/` are forbidden, and the Story asks for a test of the clock next to it.
- All Spinners show the same frame at the same time. Reason: this is the direct result of one shared clock and it agrees with the intent of the Story.
