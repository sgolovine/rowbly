Read the Spec `deterministic-factory`.

## Goal

ROW-124 removed the supervisor session. The factory manager now starts the workers itself. But the word "supervisor" still appears where a user can see it: the settings, the CLI, the TUI, the prompts and the docs. After this Story, it does not appear there. Rowbly only keeps the support for old supervisor Threads and old config keys.

## Scope

In scope:

- **Settings.** Remove `factory.supervisorModel` from `FactorySettings` (`src/services/factory-settings/factory-settings.ts`), from `validSettings`, from `configureFactory` (the `supervisor` role of `chooseRole`, the `Role` type) and from `configuredProviders` (`src/services/factory-manager/connectivity.ts`). A config that still has the key stays valid, with any value. The factory ignores the key.
- **Doctor.** `rowbly doctor` shows a warning when `factory.supervisorModel` is in `rowbly.config.json`. `rowbly doctor --fix` removes only this key, reads the config again first, and keeps all other keys.
- **CLI.** Remove `--supervisor` and `--supervisor-thinking` of `rowbly factory configure` (`src/commands/factory/factory.ts`). `rowbly prompt get supervisor` and `rowbly prompt set supervisor` give a `VALIDATION` error (exit code 1) with a hint that Rowbly no longer uses a Supervisor prompt. `rowbly prompt list` shows only `system` and `worker`.
- **Prompts.** Delete `src/config/prompts/SUPERVISOR.md`. Remove `supervisor` from `PROMPT_NAMES` and the other maps in `src/services/prompts/prompts.ts`. Remove the `supervisor` role from `promptSections` in `src/services/messages/messages.ts`. Change `src/config/prompts/SYSTEM.md` so that it does not name the supervisor (the priority list has "The Worker prompt" in item 3). Change the description of the `system` prompt from "The supervisor and all workers." to a text about all workers.
- **Doctor and prompts.** `rowbly doctor` does not show a warning for a missing `.rowbly/prompts/SUPERVISOR.md`. When the file exists, doctor shows a warning that Rowbly does not use it and that the user can delete it. This warning has no fix. Rowbly never deletes this user file.
- **Init and onboarding.** `createUserPrompts` (used by `rowbly init` and the onboarding steps) does not create `SUPERVISOR.md`.
- **TUI, Factory modal.** Remove the live supervisor conversation: the `supervisor` view, the `FactorySupervisor` component use for the live supervisor, the `enter` key and the `Supervisor` button, and the `Supervisor` row of the overview (`supervisorText`). The `h` history of old supervisor Threads stays. Its title is "Factory › Old supervisor Threads". `enter` in the history shows the conversation of the selected old Thread, read-only, and `esc` goes back to the history.
- **TUI, AI settings.** Remove the supervisor model card, the `s` key and the `supervisor` role of the AI task (`src/tui/screens/settings/`).
- **TUI, text.** `queueReason` in `src/tui/screens/factory/factory-status.ts` says "waiting for a worker start" instead of "waiting for the supervisor".
- **Code names.** Rename `src/services/factory-manager/supervisor-loop.ts` to `factory-loop.ts` and `supervisor-steps.ts` to `factory-steps.ts`, and update the imports. Remove the dead `sendDigest` and its "Supervisor is busy" error in `src/services/pi-runtime/pi-runtime.ts` if no code uses it. Update the comments that name the supervisor as a live part (for example in `factory-activity.ts`, `state-file.ts`, `worker-overrides.ts`, `conversation.ts`, `workspace.ts`, `thread-pane.tsx`).
- **Docs.** Update `docs/architecture/` (README, `domain-concepts.md`, `storage.md`, `tui.md`, `prompts.md`, `cli.md` and the pages in `native-factory/`), the Prompts section of `AGENTS.md`, and `skills/rowbly-reference.md`. Copy the reference to each `skills/<name>/references/rowbly-reference.md`. Write in STE.
- **Tests.** Update the tests of the changed services and commands: `factory-settings.test.ts`, `prompts.test.ts`, `prompt-checks.test.ts`, `messages.test.ts`, `project.test.ts`, `connectivity.test.ts`, `commands/prompt/prompt.test.ts`, `commands/factory/factory.test.ts`, and the other tests that `pnpm test` shows. Add tests for the new doctor checks.

Not in scope:

- A change to the files of this Project in `.rowbly/prompts/`. The user deletes them.
- The removal of the `supervisor` role in `ThreadRecord`, `thread-validate.ts`, `thread-text.ts` and the thread services. Old supervisor Threads stay valid, and `thread list`, `thread show` and `thread log` show them.
- The tolerance for old `state.json` and `status.json` keys that ROW-124 added.

## Technical notes

- ROW-124 (PR #314) is on the base branch. The manager starts the workers in `supervisor-loop.ts` with `reserveWorker` and `selectWorkerModel`. The factory does not read `supervisorModel` or `SUPERVISOR.md` now.
- Doctor checks: `src/services/doctor/prompt-checks.ts` (prompt files) and `src/services/doctor/factory-checks.ts` (the `factory` section). Use `report()` and `noted()` from `doctor-run.ts`. Write the config with `readConfig` and `writeConfig`, like `moveSettings`.
- Do not write `.rowbly/` of the worktree. Use `useTestProject` in tests.
- Follow the `rowbly-code-style` and `rowbly-tui-design` skills. Knip must not find unused exports after the removal.
- Docs follow `docs/contributing/documentation-language.md`.

## Assumptions

- "Usage error" means a `ValidationError` (code `VALIDATION`, exit code 1) with a hint. Reason: Rowbly has no other usage error class, and an unknown prompt name now gives a `NotFoundError`.
- The Factory modal keeps the `h` history of old supervisor Threads with a read-only conversation view. Only the live supervisor view, the `enter` key, the button and the overview row go away. Reason: the Story says that the Thread history still shows old supervisor Threads. The Threads screen shows only worker Threads.
- Any value of `factory.supervisorModel` is valid, and the factory ignores it. Reason: an old config must stay valid, and the factory does not use the key.
- `rowbly factory configure` keeps an old `supervisorModel` key when it writes the config. Only `doctor --fix` removes it. Reason: smallest change, and the user keeps control of the config.
- The doctor warning for an existing `SUPERVISOR.md` has no fix. Reason: the Story says that Rowbly never deletes this user file.
- Rename `supervisor-loop.ts` and `supervisor-steps.ts`. Reason: the grep criterion covers `src/`, and these files no longer have a supervisor.
- `SYSTEM.md` changes, although the Spec puts worker prompt changes out of scope. Reason: this Story puts the prompts in scope, and the text names a role that does not exist.
