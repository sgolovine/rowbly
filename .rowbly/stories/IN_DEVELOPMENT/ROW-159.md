## Goal

The user wants to do the usual operations on a Story with the mouse. A right click on a Story row in the Story list opens a context menu at the pointer. The menu has these items:

- Open (opens the Story in the Story sidebar)
- Move to next Stage
- Move to previous Stage
- Move to Backlog
- Delete
- Force assignment (only when the Story is in a Stage where the factory can assign a worker, see ROW-158)

Original request (kept for reference): "Add a right click context menu to stories. Should have these options: Open (opens the story in the sidebar), Move to next stage, Move to previous stage, Move to backlog, Delete, Force assignment (if in correct column, see ROW-158)".

## Scope

In scope:

- Right-click (`menu` mouse event) dispatch in the mouse registry to the box under the pointer.
- A `ContextMenu` component in `src/tui/components/`, built from the guide `.agents/skills/rowbly-tui-design/components/context-menu.md`.
- The Story context menu on each Story row of the Story list (`stories` view mode, in one Stage and in All Stages), with the six items above.
- Documentation of the menu in `docs/architecture/tui.md`, and the change of status of `ContextMenu` from "Pattern" to "Library" in `.agents/skills/rowbly-tui-design/SKILL.md`.

Not in scope:

- A context menu on a Stage heading row, on a Stage or tag in the sidebars, on a Thread row, in the Factory view (`t`), or in a Modal.
- A context menu for the multi-selection. The menu applies to one Story only.
- New keyboard shortcuts in the Story list (for example a key for "Move to Backlog").
- Changes to the services. All operations use services that exist.

## Acceptance criteria

- [ ] `MouseHandlers` in `src/tui/hooks/mouse.ts` has an `onMenu(x, y)` handler. A `menu` event still ends a drag or a pull in progress. When no drag or pull is in progress, the event goes to the smallest box under the pointer that has `onMenu`. A unit test of `createMouseRegistry` shows both cases.
- [ ] A right click on a Story row in the Story list moves the cursor to that row (it does not clear the multi-selection) and opens the menu with the cell below the pointer as its top-left corner. The menu moves in from the screen edges so that all of it shows. A person examines this in a real terminal.
- [ ] A right click on a Stage heading row, or while a Modal, a confirmation or another overlay shows, does not open a menu.
- [ ] The menu follows the ContextMenu guide: `border-round` frame in `accent`, `overlay` fill, no title, one row for each item, the key of the item right-aligned in `ink-muted`, the highlighted item with the `▌` bar, the `selection` fill and a bold label. The footer shows `↑/↓ select`, `enter run`, `esc close`. A person examines this in a real terminal.
- [ ] The items, in this order, with their keys: `Open` (`enter`), `Move to next Stage` (`shift+↓`), `Move to previous Stage` (`shift+↑`), `Move to Backlog` (no key), `Delete` (`d`), `Force assignment` (`ctrl+r`).
- [ ] An item that does not apply shows in `ink-faint`. The cursor moves past it and a click on it does nothing: `Move to next Stage` for a Story in the last Stage, `Move to previous Stage` and `Move to Backlog` for a Story in the first Stage, and `Force assignment` when `canForceAssignment` (from ROW-158) gives `false`. A unit test of the pure function that makes the items shows each case.
- [ ] `↑/↓` and `j/k` move the highlight. The pointer on an item highlights it. `enter` or a click runs the highlighted item and closes the menu. `esc`, a click outside the menu, or a right click outside the menu only closes the menu, and that click does not go to the box below the menu.
- [ ] `Open` does the same as `enter` on the Story row: the Story sidebar opens the Story.
- [ ] `Move to next Stage` and `Move to previous Stage` do the same as `shift+↓` and `shift+↑` on one Story (`moveStoryStage` in `src/tui/shell/shell/story-changes.ts`).
- [ ] `Move to Backlog` moves the Story to the top of the first Stage of the board (the `backlog` Stage category of `stageCategory`), with the same write path as `moveStoryStage`.
- [ ] `Delete` opens the same delete confirmation as `d` (overlay kind `deleteStory`). The Story is deleted only after the user confirms.
- [ ] `Force assignment` sends the same operation as the ROW-158 Button (`releaseFactoryStory` through `forceAssignment` in `src/tui/screens/stories/force-assignment/`) and shows the same toasts.
- [ ] Before an item runs, the menu makes sure that the Story still exists. If it does not, the menu closes and does nothing.
- [ ] The `?` help overlay (`GLOBAL_KEYS` in `src/tui/keymap.ts`) lists `right click` with the description "open the menu of the Story (in the Story list)".
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- **Base branch.** ROW-158 (PR #345, merge commit `71dc0cf3`) is on `origin/main`, but it is not yet in the base of this worktree (HEAD `5964407a`) or in the local `main`. Merge `origin/main` into the Story branch before the work starts. The `Force assignment` item needs `src/tui/screens/stories/force-assignment/` (`forceAssignment`, `canForceAssignment`, `useForceAssignment`) from ROW-158.
- **Mouse.** `src/tui/mouse.ts` already parses a right-button press as `kind: "menu"` with `x`, `y`. `src/tui/hooks/mouse.ts` maps `menu` to `cancelGesture` only. Add the dispatch to `onMenu` there.
- **Menu component.** Add `src/tui/components/context-menu/` (dash-case, exported from `src/tui/components/index.ts`). Use `position="absolute"` as `ToastArea` and `ModalFrame` do, and render it in the overlay layer of the shell so that it is above all other content. A full-screen transparent box under the menu catches the clicks outside the menu. Reuse the row look of `SelectionRow` / `SelectList` for the items.
- **Shell.** Add an overlay kind, for example `{ kind: "storyMenu"; story: Story; x: number; y: number }`, to `src/tui/shell/overlay.ts` and render it in `src/tui/shell/shell-overlays/` or `src/tui/shell/story-overlays/`. Pass an `onMenu(index, x, y)` handler from `StoryList` (`src/tui/screens/stories/story-list/story-list.tsx`) through `StoryListItem` to `StoryRow`, and add the handler in `panelHandlers` of `src/tui/shell/shell/shell-handlers.ts`.
- **Existing operations.** Open: `editStory` (used by `storyKey` in `shell-keys.ts`). Move: `moveStoryStage(env, story, ±1)` and `placeStory` in `story-changes.ts`. Delete: `env.setOverlay({ kind: "deleteStory", story })`. Force assignment: the eligibility needs the shared factory status (`useSharedFactoryStatus`) and the active Thread state of the Story; reuse `useForceAssignment(ctx, storyId)` in the menu component.
- **Rules.** Front ends stay thin: no domain logic in the component. Do not load Pi. Use only `theme` colours. Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` first. Unit tests only for pure functions (mouse registry, menu items, menu position clamp); no component tests.

## Assumptions

- The menu opens only on Story rows of the Story list, not in the Threads/Factory view and not in the Story sidebar. Reason: smallest scope that agrees with "right click context menu to stories" and with the ContextMenu guide.
- "Backlog" is the first Stage of the board order. Reason: `stageCategory` already defines the first Stage as the `backlog` category, and a Project can rename its Stages.
- `Move to Backlog` has no key, and the menu still shows it. Reason: the author asked for this item explicitly. The guide rule "only actions that keys already do" is relaxed for this item; a new key is not in scope.
- `Force assignment` always shows, in `ink-faint` when it does not apply, and does not hide. Reason: the ContextMenu guide shows an item that does not apply in `ink-faint`, and a fixed item list keeps the menu position stable.
- The `Force assignment` item shows the `ctrl+r` key, although `ctrl+r` works only in an open Story. Reason: it is the existing key of the operation; a new list key is not in scope.
- With a multi-selection, the menu applies only to the Story under the pointer and keeps the selection. Reason: the guide says the menu applies to the row under the pointer; a bulk menu is not in scope.
- The move items keep the current behaviour of `moveStoryStage` (the Story goes to the top of the target Stage). Reason: same result as the keys.
