## Goal

The TUI does not use `React.memo`. Each change of the shell state renders Header, Sidebar, StoryPanel, StorySidebar, ShellOverlays and Footer again. Also, the shell makes new objects on each render, so a `memo` cannot skip a render:

- `src/tui/hooks/use-async.ts:114` returns a new object (`{ ...state, reload, refresh }`) on each render. `src/tui/shell/shell/shell.tsx:54` gives the factory value of it to `FactoryStatusContext`, so each consumer of that context renders again.
- `src/tui/shell/shell/use-shell-data.ts:167` makes a new `data` object, and `withActivity` (line 94) makes a new board object, on each render.
- `src/tui/shell/shell/shell-props.ts` (`headerProps`, `stageSidebarProps`, `storyPanelProps`, `storySidebarProps`, `overlayHandlers`) makes new prop objects, new arrays and new inline closures for each child on each render.
- `shell.tsx:64` gives a new inline object to `LayoutContext`. `src/tui/shell/story-panel/story-panel.tsx:62` gives `inner` to `LayoutContext`, and `inner` is also a new object on each render.

The result for the user: an arrow key on the board renders only the Story list and the footer. The other shell children do not render again, so the TUI does less work on each key.

## Scope

In scope:

- Keep the same reference for the return value of `useAsync` while its state, `reload` and `refresh` do not change (`useMemo`).
- Keep the same reference for the `data` object and the board of `useShellData` while `data`, `activity.data` and the board do not change (`useMemo`). Make `reload` stable (`useCallback`).
- Give stable values to `FactoryStatusContext`, the `LayoutContext` in `shell.tsx` and the `LayoutContext` in `story-panel.tsx` (memoize on `width` and `height`).
- Make the handlers that the shell gives to its children stable. Each handler keeps one reference for the life of the shell, and reads the current `env` from a ref (`useLatest` from `src/tui/hooks/refs.ts`).
- Keep the same reference for each nested prop object and array (for example `project`, `finder`, `factory`, `viewSwitch`, `newStory`, the Sidebar `entries`, `button`, the StoryPanel `inner` and `body`, `expand`) while its values do not change.
- Wrap `Header`, `Sidebar`, `StoryPanel`, `StorySidebar`, `ShellOverlays` and `Footer` in `memo`.

Not in scope:

- The memoization of `shellView` and the linear build of the Story list rows. ROW-131 has that work.
- An equality check in `useAsync` that stops a render after a read that did not change the data, and the 1 s clocks. ROW-129 has that work.
- The local application of board actions. ROW-133 has that work.
- The full profile after all performance Stories. ROW-137 has that work.
- `memo` on components that are not direct children of the shell.

## Technical notes

- Files: `src/tui/hooks/use-async.ts`, `src/tui/shell/shell/use-shell-data.ts`, `src/tui/shell/shell/use-shell.ts`, `src/tui/shell/shell/shell-props.ts`, `src/tui/shell/shell/shell.tsx`, `src/tui/shell/story-panel/story-panel.tsx`, `src/tui/shell/header/header.tsx`, `src/tui/components/sidebar/sidebar.tsx`, `src/tui/shell/story-sidebar/story-sidebar.tsx`, `src/tui/shell/shell-overlays/shell-overlays.tsx`, `src/tui/components/footer/footer.tsx`.
- `env` (`ShellEnv`, built in `use-shell.ts`) is a new object on each render, and `shellView` makes a new view on each render. Thus a handler that closes over `env` changes on each render. Recommended method: in `use-shell.ts`, keep `env` in a ref with `useLatest(env)`. Build the handlers one time from top-level factory functions that take the ref, for example `const handlers = useMemo(() => shellHandlers(envRef), [])` or `useState(() => shellHandlers(envRef))[0]`. Each handler calls the existing top-level function with `envRef.current` (for example `filterStage(envRef.current, id)`).
- Then split each prop builder into the stable handlers and the values. Memoize each nested object or array on its primitive values, or on stable references (`board.stages`, `factory`). `Sidebar` `entries` depends only on `stages`, so it keeps its reference while the board does not change.
- Read the "React components" section of `.agents/skills/rowbly-code-style/SKILL.md`. Rule 4 says: do not put `env` or `actions` in a dependency array. The ref method obeys this rule. Use `writeRef` or `useLatest` to write a ref (rule 8). The memoization of this Story has a performance reason. It is not a change to satisfy a lint rule.
- `memo` uses a shallow comparison. A prop that is a new object or a new closure on each render cancels the `memo`. Examine each prop of each memo child.
- `Footer` gets `shellHints(...)`, which is a new array on each render. Footer can render on each key. The goal lets this. A memo of the hints is optional.
- `StoryPanel` gets `rows` and `marked` from `shellView`, which are new on each render until ROW-131 is done. Thus `StoryPanel` renders on each key. The goal lets this.
- Do not change the behaviour of the shell. Do not write component tests (AGENTS.md rule 4).

## Assumptions

- The Story does not wait for ROW-131. Reason: the goal is that the Story list renders on each arrow key, so the new `rows` of `shellView` do not prevent the acceptance criteria. ROW-131 adds its own memoization later.
- The check of the render count is a manual check with a temporary counter, and it is not committed. Reason: the original "Done when" asks for this method, and AGENTS.md has no tests for the TUI.
- `ShellOverlays` gets `memo` too, although the original "Fix" list did not name it. Reason: the original "Problem" names it as a child that renders again, and the same memo method applies.
- The `LayoutContext` value in `story-panel.tsx` is in scope. Reason: it is the same problem as `shell.tsx:64` and it has a small change.
- Stable handlers read `env` from a ref, and do not use `useCallback` with `env` dependencies. Reason: the code style forbids `env` in a dependency array, and a ref gives one reference for the life of the shell.
