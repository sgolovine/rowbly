## Goal

The attach channel of the host agent (`rowbly host attach`) sends the new lines of the session file of each remote worker. The main machine then can keep a mirror of the session (ROW-101), so that Peek and `inspect_worker` work for remote Threads.

Read the Spec `remote-worker-hosts`, sections "Transport" and "Session mirror".

ROW-92 writes the session files of remote workers on the host. `run.json` of each Thread gives the session file in `session.file`, relative to the runtime folder of the host agent (`agent/runtime/`, `HostAgentPaths.runtime`). A resume continues the same file. This Story adds `session` frames to `rowbly host attach`. Each frame has the Thread id, the byte offset of the first line and the complete lines. Thus the main machine can add each line one time.

## Scope

In scope:

- A `session` frame on the channel of `runHostAttach` (`src/services/host-agent/host-attach.ts`):

  ```json
  { "type": "session", "threadId": "…", "file": "sessions/<thread-id>/….jsonl", "offset": 0, "end": 1234, "lines": ["{…}", "{…}"] }
  ```

  - `file` is the `session.file` value of `run.json`.
  - `offset` is the byte offset in the file of the first line.
  - `end` is the byte offset after the last byte that the frame covers (after the newline of the last line).
  - `lines` are the complete lines, without the newline, as UTF-8 text.
- The rules of the reader:
  - The channel reads the session file of each Thread whose `run.json` has `session.file`.
  - It sends only complete lines (lines that end with `\n`). A part line at the end of the file waits for the next poll.
  - It reads bytes, not characters, so that the offsets are byte offsets and a multi-byte character is never cut.
  - When the channel opens, the start offset of each session file that exists is its current size. The channel sends only the lines that come after this time. A session file that the channel first sees after it opened starts at offset 0. The read of the lines before the channel opened is ROW-101.
  - If the file becomes shorter than the sent offset, or its inode changes, the channel starts again at offset 0 of the file.
  - The frames of one Thread go in offset order, and they have no gap except the gap of an oversize line (see next item).
  - The encoded frame must not be longer than `DEFAULT_LINE_LIMIT` (`host-transport/json-lines.ts`). The channel puts lines in one frame while the encoded frame stays in the limit, and sends more frames for the other lines. A single line whose frame is longer than the limit is not sent: the channel sends a frame with `lines: []`, the `offset` of that line and the `end` after it. ROW-101 gets the bytes of that gap.
  - A poll reads a maximum of 4 MiB of each session file. The remaining lines go in the next polls.
  - A `session.file` that is absolute, that has a `..` part, or that is not below the runtime folder gives no frame and no read. A missing or unreadable session file gives no frame and does not stop the channel.
- The order of the frames in one poll: status, receipts, runs, then session lines. Thus the `run` frame that names a session file comes before its first `session` frame.
- `HOST_PROTOCOL_VERSION` in `src/services/host-transport/host-transport.ts` increases by 1, because the channel has a new frame.
- Tests in `src/services/host-agent/host-attach.test.ts`.
- Documentation in STE: the `session` frame and its rules in the channel section of `docs/architecture/native-factory/host-agent.md`.

Not in scope:

- The mirror on the main machine, the decode and the use of `session` frames on the main machine, and the read of missing lines after a reconnect or after an oversize line (ROW-101).
- A frame from the main machine that gives its mirror offset to the host.
- A change to the Pi session format or to `run.json`.
- The removal of old session files.

## Technical notes

- Files: `src/services/host-agent/host-attach.ts` (add the session reader to `sendChanges`; keep the sent offsets of each Thread in `SentValues` with the `Store`), `src/services/host-agent/host-run-state.ts` (`readHostRun`, `hostThreadIds`), `src/services/host-agent/host-agent-paths.ts` (`HostAgentPaths.runtime`, `threadPaths`), `src/services/host-transport/json-lines.ts` (`encodeFrame`, `DEFAULT_LINE_LIMIT`), `src/services/host-transport/host-transport.ts` (`HOST_PROTOCOL_VERSION`).
- Read the session file with `open` and `read` from the offset (a `FileHandle`), not `readFile`, so that a large file is not read in full.
- Keep the per-Thread state (file, inode, offset) in the channel. It is not written to disk.
- The channel does not load Pi. Do not import `pi-runtime/` or `host-run-executor.ts` from `host-attach.ts`.
- A service does not print. The command `rowbly host attach` (`src/commands/host/host.ts`) stays as it is.
- Follow `.agents/skills/rowbly-code-style/SKILL.md`. Use `.js` extensions in relative imports.

## Assumptions

- The channel starts each session file that exists at open at its current size, and does not send the old lines. Reason: the Spec says that the main machine adds the lines of the live channel and gets the missing lines after a reconnect. ROW-101 owns that read. A send from offset 0 at each reconnect can send many MiB again.
- A frame has an `end` field in addition to the offset of the first line. Reason: with `end`, a frame with no lines can mark the gap of an oversize line, and the main machine can find a gap without a calculation of the byte length.
- A line that is too long for one frame is not split. The frame marks a gap, and ROW-101 reads the bytes. Reason: the Story asks for complete lines, and the frame limit of the transport is fixed at 1 MiB.
- The limit of 4 MiB of each file for each poll. Reason: one poll must not hold the channel for a long time when a large session file appears.
- A truncated or replaced session file restarts at offset 0. Reason: Pi session files are append-only in normal use, and this is the smallest rule that does not send wrong offsets. ROW-101 decides how the mirror uses a frame that starts before its end.
- `HOST_PROTOCOL_VERSION` increases. Reason: the comment of the constant says to increase it for each change of a frame. The two machines must have the same Rowbly version, so the change does not stop a correct setup.
