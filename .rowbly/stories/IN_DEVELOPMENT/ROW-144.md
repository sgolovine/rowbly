## Goal

The tag sidebar below the Stage sidebar in the TUI has a fixed height and no button. The user cannot make it taller or shorter, and must open Settings to add a tag.

The user gets two improvements (see the attached screenshot, which marks the tag sidebar):

1. The user can drag the border between the Stage sidebar and the tag sidebar up or down to change the height of the tag sidebar. This works like the drag of the right edge that changes the width of the sidebars.
2. The tag sidebar has a `+ New Tag` button at the bottom, the same as the `+ New Stage` button of the Stage sidebar. The button opens the existing New Tag Modal (`TagFormModal`). The code uses that component again and does not make a copy.

## Scope

In scope:

- A vertical drag of the top edge of the tag sidebar (the border between the two Panels) that changes the rows of the tag sidebar. The Stage sidebar gets the other rows.
- The `+ New Tag` button at the bottom of the tag sidebar, and the `n` key while the tag sidebar has the focus.
- The New Tag Modal opens from the shell as a shell overlay. After a save, the board reloads and the new tag shows in the tag sidebar.
- Updates to the footer hints, the help Modal hints, `docs/architecture/tui.md` ("The tag sidebar") and the tests of `shell-frame`.

Not in scope:

- A save of the height to disk. The height stays until Rowbly quits, the same as the sidebar width.
- A tag sidebar for a Project with no tags. The tag sidebar still shows only when the Project has one or more tags (`tagSidebar = sidebar && tags.length > 0`).
- Edit or remove of a tag from the tag sidebar. Settings keeps these actions.
- A height drag in the stacked layout (narrow terminal).

## Technical notes

- Sidebar component: `src/tui/components/sidebar/sidebar.tsx`. It already renders an optional `button` at the bottom (`Button` with `keyName="n"` while focused). Give the tag sidebar a `button` in `useTagSidebarProps` (`src/tui/shell/shell/use-shell-props.ts`) with `useMemo`, the same as `useStageSidebarProps`, and pass it in `tagSidebarProps` (`src/tui/shell/shell/shell-props.ts`). `SIDEBAR_CHROME_HEIGHT` (3) already counts one row for the button, so `entriesHeight` does not change.
- Resize: `src/tui/components/resize-edge/resize-edge.tsx` supports only `side: "left" | "right"` and widths. Add a vertical mode (for example `side: "top"`) that uses the `y` of `onPull` and `measureElement(target).y` and the element height, or add a small sibling component. Keep it in `src/tui/components/` with its `index.ts`. The `Sidebar` component needs an optional `onResizeHeight(height)` with `minHeight`/`maxHeight`, or the shell puts the edge on the tag sidebar box. The edge must sit on the top border row of the tag sidebar Panel (the border between the two Panels).
- Height state: add `tagsHeight` state (`number | null`, default `null`) in `src/tui/shell/shell/use-shell-state.ts`, next to `sidebarWidth` and `storyWidth`. Add a `resizeTags` handler in `shell-handlers.ts` next to `resizeStages`. Pass the value to `shellFrame` in `use-shell.ts`.
- Frame: `sidebarHeightsOf` in `src/tui/shell/shell/shell-frame.ts` computes `tagsHeight` today as `Math.min(need, floor(height / 2))` beside the list. With a dragged value, use the dragged value with the limits of the acceptance criteria instead. Add the most rows for the drag to the frame (for example `tagsRoom`) so the edge can limit the drag.
- New tag: add an overlay `{ kind: "newTag" }` to `Overlay` in `src/tui/shell/overlay.ts`. Render `TagFormModal` in `src/tui/shell/shell-overlays/shell-overlays.tsx`, next to `StageFormModal`. Import it from `../../screens/settings/tag-form-modal/index.js`, not from the settings index, so the lazy Settings chunk does not load at start. Add an `openNewTag` handler in `shell-handlers.ts` and a `tagSaved` handler in `OverlayHandlers` that closes the overlay and calls `env.reload()`.
- Keys: `tagSidebarKey` in `src/tui/shell/shell/shell-keys.ts` gets `input === "n"` → `env.setOverlay({ kind: "newTag" })`. Add `{ key: "n", description: "new tag" }` to `tagSidebarHints` in `shell-hints.ts`.
- `TagFormModal` (`src/tui/screens/settings/tag-form-modal/tag-form-modal.tsx`) calls `addTag` of `src/services/tag/tag.ts`. No service change is necessary.
- Read the `rowbly-tui-design` and `rowbly-code-style` skills first. Do not write tests for TUI components. Test only the pure functions (`shellFrame`, hints).

## Assumptions

- "Resize it up/down" means a mouse drag of the border between the Stage sidebar and the tag sidebar, which changes the split of the rows between the two. Reason: the Story says "same as we do with the sidebar left/right", and that is a mouse drag of an edge (`ResizeEdge`).
- The dragged height stays only until Rowbly quits and is not saved. Reason: the sidebar width and the Story sidebar width are also session state only.
- The drag works only beside the list, not in the stacked layout. Reason: the width drag is also off in the stacked layout (`onResize: frame.stacked ? undefined : …`), and this is the smallest scope.
- Each sidebar keeps at least one entry row and its chrome (`SIDEBAR_CHROME_HEIGHT + 1` rows). Reason: a smaller Panel cannot show its title, an entry and its button.
- The tag sidebar still does not show for a Project with no tags, so the button is available only when one or more tags exist. Reason: smallest scope; the visibility rule is documented and tested. A person can request a change later.
- After a save, the shell reloads the board and does not change the tag filter. Reason: the author asked only to open the Modal; the selection of the new tag is not requested.
- The `n` key opens the New Tag Modal while the tag sidebar has the focus. Reason: the shared `Sidebar` button shows `n` while focused, so the key must work, the same as `+ New Stage`.
- The Modal is imported from its own folder in `screens/settings/` and not moved. Reason: `StageFormModal` is also imported from a screen folder; this keeps the change small and the Settings chunk lazy.
