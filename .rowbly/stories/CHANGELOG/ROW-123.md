Read the Spec `deterministic-factory`.

## Goal

The user can select a worker model for the Stories with a tag. For example, the Stories with the tag `bug` get a different model. A rule in the factory settings replaces a model rule in a prompt.

At this time, `factory.storyWorkerModels` and `factory.stageWorkerModels` set a model for one Story in a Stage, or for one Stage. The Project prompt of this Project tells the supervisor which model to use for bug fixes, but the supervisor did not obey it. All 305 starts with a model used the default worker model.

## Scope

In scope:

- A new setting `factory.tagWorkerModels`: a map from a tag value to a model choice (`ModelChoice`). The rule applies in all Stages.
- The order of priority: the Story override, then the tag rule, then the Stage override, then the model of the supervisor (while the supervisor exists), then `factory.workerModel`. The fallback rule of `factory.fallbackWorkerModels` (paused provider) applies to the result, as now.
- When a Story has more than one tag with a rule, the rule of the first such tag in the `tags` list of the Story applies.
- A rule must name a tag of the Project. `rowbly factory configure` refuses an unknown tag. `rowbly doctor` shows a warning for a rule of a tag that is not in the Project.
- CLI options to set and clear a rule: `rowbly factory configure --tag <value> --worker <provider/model> [--worker-thinking <level>]` and `rowbly factory configure --tag <value> --clear-worker`.
- The providers of the tag rules count as configured providers (connectivity) and as worker models (host check), in the same way as the Stage and Story overrides.
- Tests of the selection, the validation, the CLI and the doctor check. The docs of the factory settings.

Not in scope:

- A TUI control for the setting (Settings › AI and the models tab do not change).
- A mix of models by count or by rotation.
- A change to `rowbly tag remove`. It does not remove a rule of the tag. The doctor warning shows the stale rule.

## Assumptions

- The tag rule applies in all Stages, and it has no Stage key. Reason: the Story text defines the setting as "a map from a tag value to a model choice". This is the smallest scope.
- The supervisor model stays between the Stage override and `factory.workerModel`. Reason: the Spec gives the order without the supervisor, because ROW-124 removes it. The current code puts the supervisor model after the overrides.
- `--tag` cannot be used together with `--stage`, `--story` or settings flags other than `--worker`, `--worker-thinking` and `--clear-worker`. Reason: this is the same rule as for a Stage override (`overrideProblem`).
- `rowbly factory configure` refuses an unknown tag, and `rowbly doctor` only warns for a stale rule. Reason: the Story says that a rule must name a tag of the Project. A tag can be removed after the rule was set, so doctor must report it, but a doctor fix that deletes settings could delete user data.
- `rowbly tag remove` does not change the factory settings. Reason: smallest scope. The doctor warning covers it.
- No TUI change. Reason: the Story puts the TUI control out of scope.
- `rowbly factory configure --tag <value> --clear-worker` does not check that the tag is in the Project. Reason: the doctor warning tells the user to remove a stale rule, and the user must be able to do it with the CLI. A new rule must still name a tag of the Project.
- The read, validation and write core of the factory settings moved from `factory-settings.ts` to `settings-file.ts`. Reason: the change made `factory-settings.ts` longer than the 400-line lint limit. `factory-settings.ts` re-exports the functions.
