## Goal

`src/services/story-watch/story-watch.ts` (`watchProjectDir`) and `src/services/thread/thread-watch.ts` (`watchThreads`) open `fs.watch(paths.dir, { recursive: true })` on all of `.rowbly/`. `.rowbly/runtime/` has more than 500 folders and more than 120 MB of session data. On Linux, Node makes a recursive watch with one inotify watch for each folder. Each write in `runtime/` wakes all watchers before the filter ignores it. Each hook instance (`useStoryChanges`, `useFactoryStateChanges`, `useThreadChanges` in the shell, the thread pane, the threads tab and the factory view, and `use-factory-modal`) adds one more recursive watcher.

The result: the TUI and the factory supervisor watch only the paths that they need, and they share the watches of one Project root. A write in `.rowbly/runtime/sessions/` or `.rowbly/runtime/logs/` wakes no watcher.

## Scope

In scope:

- A shared watch registry in the service layer: one `fs.watch` handle for each watched path of each Project root, with a list of subscribers. The registry closes a handle when its last subscriber stops.
- `watchStories`, `watchFactoryState` and `watchThreads` use the registry and watch only these paths:
  - `.rowbly/` with no recursion: `state.json` (and its temporary files `state.json*`), `rowbly.config.json`, and the creation or removal of a child folder (`stories`, `attachments`, `specs`, `stages`, `prompts`, `runtime`).
  - `.rowbly/stories/` recursive (the Stage folders).
  - `.rowbly/attachments/` recursive (one folder for each Story).
  - `.rowbly/specs/`, `.rowbly/stages/`, `.rowbly/prompts/` with no recursion (flat folders). They keep the current behaviour: a change to these files calls the `watchStories` callback.
  - `.rowbly/runtime/` with no recursion, only for `watchThreads`: `status.json`, `factory.lock`, and the creation of `threads/`.
  - `.rowbly/runtime/threads/` with no recursion, only for `watchThreads`.
- A child folder that does not exist when the watch starts: the watch of that folder starts when the parent watch sees its creation. A child folder that is removed: its handle closes with no crash, and it starts again if the folder comes back.
- Keep the quiet time of 100 ms for each subscriber, `persistent: false`, the `includeState` option, the `factory` option and the public signatures of the three functions.
- Update `story-watch.test.ts` and `thread-watch.test.ts`, and add a test for the registry.
- Update the `story-watch/` row of `docs/architecture/service-layer.md`.

Not in scope:

- Changes to the TUI hooks other than the import path, if the service moves.
- The fallback poll of `useThreadChanges` (`FACTORY_POLL_MS`).
- Profiling. ROW-137 records the numbers.

## Technical notes

- Files: `src/services/story-watch/story-watch.ts`, `src/services/thread/thread-watch.ts`, the tests next to them. Put the registry in a new folder, for example `src/services/project-watch/project-watch.ts` with `project-watch.test.ts`. `thread-watch.ts` and `story-watch.ts` import it. A service must not import `ink` or `react`.
- Paths: `projectPaths()` in `src/services/workspace/workspace.ts` gives `dir`, `storiesDir`, `specsDir`, `stagesDir`, `promptsDir`, `stateFile`, `configFile` and `runtimeDir`. `runtimePaths()` gives `threadsDir`, `statusFile` and `lockFile`. `attachments/` has no field in `ProjectPaths`: use the path that `src/services/attachment/` uses, or add an `attachmentsDir` field.
- Key the registry by the absolute watched path. Each entry holds the `FSWatcher` and a `Set` of listeners `(filename: string | null) => void`. Each subscriber keeps its own debounce timer.
- Keep `watcher.on("error", ...)`: without a listener, the error of a removed folder stops the process.
- Users: `src/tui/hooks/use-story-changes.ts`, `use-factory-state-changes.ts`, `use-thread-changes.ts`, `src/tui/screens/factory/factory-modal/use-factory-modal.ts` and `src/services/factory-manager/supervisor-loop.ts` (the daemon, with `includeState: false`). The registry is per process, so the daemon and the TUI each have their own handles.
- Node 24 on Linux makes a recursive watch with one inotify watch for each sub-folder. Non-recursive watches of flat folders cost one inotify watch each.
- Use the `rowbly-code-style` skill. Use `Store` for mutable module state if the style requires it.

## Assumptions

- "At most one recursive watcher per project root" in the original text means: no recursive watch of `.rowbly/` or `runtime/`, and one shared handle for each watched path. Two recursive watches (`stories/` and `attachments/`) stay. Reason: Story folders and attachment folders both have sub-folders, and the original fix list names both.
- `watchStories` keeps the call for changes to `rowbly.config.json`, `specs/`, `stages/` and `prompts/`. Reason: the current filter accepts all paths outside `runtime/`, and the board shows Stages and Specs. A smaller watch can lose a refresh.
- The registry is in the service layer, not in the TUI hooks. Reason: AGENTS.md rule 1, and the daemon (`supervisor-loop.ts`) also uses `watchStories`.
- `runtime/threads/` is flat. Reason: the live Project has only `<uuid>.json` files in it.
