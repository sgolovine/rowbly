## Goal

The `Attention` list in the main view of the Factory controls (`f`) shows a maximum of five rows. Then it shows `↓ n more`. The user cannot see the other warnings from this list: it has no keys and it does not take the mouse wheel. Also, the user must dismiss each warning one at a time in its detail view.

After this change, the user can scroll the `Attention` list with `↑/↓` and with the mouse wheel, and so see each warning. The user can also dismiss all warnings that can be dismissed with one button.

The attachment of the Story is a screenshot of the problem: the `Attention` list shows five rows and `↓ 2 more`.

## Scope

In scope:

- Scroll of the `Attention` list in the main view of `FactoryModal` with `↑/↓` and the mouse wheel.
- A `↑ n more` row above the list when rows are hidden above, and the existing `↓ n more` row when rows are hidden below.
- A `Dismiss all` button with a key in the main view, a confirmation dialog, and a service function that dismisses a list of attention entries.
- Key hints, docs and tests for these changes.

Not in scope:

- A daemon command or a CLI command that dismisses all entries in one command.
- Changes to the `Factory › Attention` list view (`w`). It uses `SelectList`, which already scrolls.
- Changes to the `Hosts` and `Queue` lists. They keep the five-row cut with no scroll.
- Dismissal of warnings that are not `attention` entries (`heartbeat`, `issue`, `provider`, `watchdog`).

## Acceptance criteria

- [ ] With more than five warnings, `↓` in the main view of the Factory controls moves the five-row window of the `Attention` list down by one row, and `↑` moves it up by one row. The window stops at the first and at the last row.
- [ ] A wheel notch over the `Attention` list scrolls the window in the direction of the wheel. The window stops at the first and at the last row.
- [ ] When rows are hidden above the window, a `↑ n more` row shows above the rows. When rows are hidden below the window, the `↓ n more` row shows below the rows. Each `n` is the correct count.
- [ ] With five warnings or fewer, `↑/↓` and the wheel do not change the list.
- [ ] When warnings go away and the window is past the end, the window moves back so that it shows the last rows.
- [ ] A click on a row and a click on a selected row still work as before, also after a scroll.
- [ ] When the live factory has a minimum of one dismissible warning, the main view shows a `Dismiss all` button with the key `d`, and the key hints show `d dismiss all`. With no dismissible warning, the button and the hint do not show, and `d` does nothing.
- [ ] `d` or a click on `Dismiss all` opens a confirmation dialog. Cancel closes the dialog and changes nothing.
- [ ] Confirm sends one `dismiss` command for each dismissible warning, one after the other. A pending toast shows during the work. Then an info toast tells how many warnings were dismissed. If one or more commands fail, an error toast shows, and the warnings that were not dismissed stay in the list.
- [ ] A second `d` while a dismiss of all is in progress sends no more commands.
- [ ] Warnings that cannot be dismissed stay in the list after a dismiss of all.
- [ ] A Vitest test for the new service function shows that it sends one `dismiss` command for each key, that it continues after a failed command, and that it returns the dismissed and the failed keys.
- [ ] `docs/architecture/tui.md` and `docs/architecture/native-factory/controls.md` describe the scroll and the `Dismiss all` button in STE. The sentence "The `Attention` list has no keys." is removed.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
- [ ] A person examines the list in a real terminal with more than five warnings (see the `rowbly-screenshots` skill). Only a person can examine this criterion.

## Technical notes

- `src/tui/screens/factory/factory-list/factory-list.tsx`: `FactoryList` cuts the rows at `LIST_LIMIT = 5`. Add an optional scroll mode (for example an `offset` prop and an `onWheel` prop, or a `scrollable` prop with the offset state in the parent), so that only the `Attention` list scrolls. Use `clampOffset` from `src/tui/components/scroll-offset.ts` to keep the offset in range. Use `useMouse` from `src/tui/hooks/mouse.ts` with `onWheel` on the `Box` of the list. Only a list that scrolls takes the wheel; see `use-select-list.ts` for the pattern. The wheel is active only while the main view is idle (`clickable`).
- `src/tui/screens/factory/factory-overview/factory-overview.tsx` renders the `Attention` list from `factoryProblems(status)`.
- `src/tui/screens/factory/factory-modal/use-factory-modal.ts` and `factory-run.ts`: `handleFactoryKey` takes the keys of the main view (`s`, `x`, `w`, `h`, `a`) while `idle`. Add `↑/↓` for the scroll and `d` for `Dismiss all`. Keep the offset state in the modal model or in the attention hook, so that the keys and the wheel change the same state.
- `src/tui/screens/factory/factory-modal/use-factory-attention.ts` and `factory-attention-actions.ts`: `dismissProblem` dismisses one warning with `runExclusive` and the `dismissing` ref. Add a `dismissAll` action with the same guard and the same toast pattern.
- `src/tui/screens/factory/factory-buttons/factory-buttons.tsx`: add the `Dismiss all` button (`keyName="d"`, `compact`, `clickable={idle}`).
- `src/tui/screens/factory/factory-modal-text.ts`: add `{ key: "↑/↓", description: "scroll" }` when the list can scroll, and `{ key: "d", description: "dismiss all" }` to `factoryHints` when a dismissible warning exists.
- `src/tui/screens/factory/factory-modal/factory-modal.tsx`: add a second `ConfirmDialog` for `Dismiss all` (title `Factory › Dismiss all`), the same as the stop confirmation.
- `src/services/factory/factory.ts`: add a service function, for example `dismissFactoryAttentions(keys, input, ctx)`. It calls `dismissFactoryAttention` for each key in sequence, catches the error of each key, and returns `{ dismissed: string[]; failed: { key: string; error: unknown }[] }`. Add tests in `src/services/factory/factory.test.ts`. The service does not print, prompt or exit.
- `FactoryProblem.dismissible` and `FactoryProblem.attentionKey` in `src/tui/screens/factory/factory-status.ts` give the keys to dismiss.
- The daemon removes an entry in `dismissAttention` of `src/services/factory-manager/factory-manager.ts`. No daemon change is necessary.
- Obey the `rowbly-tui-design` skill and the `rowbly-code-style` skill. Use only the colours in `theme`. Do not write tests for the TUI.

## Assumptions

- `↑/↓` scroll the five-row window by one row and do not move the click selection. Reason: the story asks for a scroll, and the click selection of the list already has its own rules. This is the smallest change.
- A wheel notch scrolls by one row, not by `WHEEL_LINES`. Reason: the window has only five rows, and three rows for each notch skip too many warnings.
- The key of `Dismiss all` is `d`. Reason: `d` dismisses one warning in the detail view, and `d` is free in the main view.
- `Dismiss all` asks for confirmation. Reason: it removes many entries at one time and the user cannot undo it. The stop action already uses the same `ConfirmDialog` pattern.
- The TUI sends one `dismiss` command for each entry through a new service function, and no new daemon command. Reason: the daemon already has the `dismiss` command. A new command type changes the control protocol and makes the Story larger.
- Only the `Attention` list scrolls. The `Hosts` and `Queue` lists keep the five-row cut. Reason: the story is about the factory alerts only.
- `Dismiss all` shows only in the main view, not in the `Factory › Attention` list view. Reason: the story points to the list in the main view.
