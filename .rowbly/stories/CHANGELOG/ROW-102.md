## Goal

The TUI shows the worker hosts and the remote Threads, with their connection. The user can apply or discard the held entries of an abandoned remote Thread from the TUI.

Read the Spec `remote-worker-hosts`, sections "Status and TUI" and "Abandoned Threads". Read the `rowbly-tui-design` skill.

## Scope

In scope:

- **Hosts in Factory controls.** `FactoryOverview` (`src/tui/screens/factory/factory-overview/`) shows a `Hosts` list (a `FactoryList`) when the live factory status has a worker host (a `hosts` entry that is not `local`). Each row shows the host id, the connection state, `<used>/<max>` slots and, for a host that is not `connected` or `degraded`, the time since the last contact (`contactText`), or `no contact`.
- **The `▶` marker.** The `▶` marker of a Story with an `active` activity on a worker host shows the host after the agent label (for example `▶ opus @ws1`). When the host of the activity has a lost connection in the live `hosts` list (the same rule as `threadConnection`: state not `connected` or `degraded`, or not in the list), the marker shows `connection lost` in `theme.danger`. A Story on `local` shows the marker as before.
- **Host column in `ThreadRow`.** `ThreadRow` (used by the Threads tab of a Story and the Factory view) shows the host of the Thread in a column on the right, before the run time, when the Thread list has at least one remote Thread (`thread.host` is not `local`). Then a `local` Thread shows `local`. A list without remote Threads looks as before.
- **Connection lost in `ThreadRow`.** A remote Thread with a lost connection (`threadConnection` with the live hosts) shows `· connection lost (last contact <duration> ago)` or `· connection lost (no contact)` (the `connectionLostText` text) in `theme.danger` on row 1.
- **Abandoned Threads in the Threads tab.** An abandoned Thread (`isAbandoned`) shows `abandoned` and its number of held entries in its row or detail. In the Threads tab of a Story:
  - `a` applies the held entries of the selected abandoned Thread (`heldAction` with `apply`). A toast gives the number of applied entries and the number of conflicts.
  - `d` asks for a confirmation (`ConfirmDialog`), then discards the held entries (`heldAction` with `discard`). A toast gives the number of discarded entries.
  - The keys do nothing on a Thread that is not abandoned. The key hints show `a` and `d` only for an abandoned Thread with held entries.
- Documentation in STE: `docs/architecture/tui.md` (Factory view rows, `▶`), `docs/architecture/native-factory/controls.md` (Factory controls, Threads tab keys) and the help Modal text of `▶` (`src/tui/shell/help-modal/help-modal.tsx`).

Not in scope:

- Settings. Another Story owns the Hosts section of Settings.
- Held-entry keys in the Thread pane of the Factory view. The Factory view stays read-only (see `controls.md`).
- A new Factory view section for hosts.
- Changes to services other than small pure helpers or new exports (for example to export `threadConnection` and `HostFacts` from `src/services/thread-connection/thread-connection.ts`).

## Technical notes

- **Base.** ROW-99 (#300), ROW-100 (#297) and ROW-101 (#298) are on the base of this worktree.
- **Host facts.** `HostSlots` (`src/services/factory-manager/host-slots.ts`) has `id`, `state`, `max`, `used`, `free`, `lastSeenAt` and `latencyMs`. `FactoryStatus.hosts` gives the list. Use `liveHosts(status)` of `src/services/thread-connection/thread-connection.ts`: it gives `undefined` when the factory is not live, and then nothing shows as lost.
- **Pure rules.** `threadConnection`, `connectionLostText`, `contactText` and `lastContactMs` are in `src/services/thread-connection/connection-lost.ts`. Export what the TUI needs through `thread-connection.ts`. The TUI must not compute its own lost rule.
- **Factory status in the TUI.** The shell polls the status in `src/tui/shell/shell/use-shell-data.ts` and shares it with `useSharedFactoryStatus` (`src/tui/hooks/factory-status-context.ts`). The Threads tab already reads it (`useTabStatus` in `use-threads-tab.ts`). The Factory view (`use-factory-view.ts`) and the Story list must use the same shared status.
- **`▶` marker.** `StoryActivity` (`src/services/factory-activity/factory-activity.ts`) already has `host` for `active`. `StoryRow` (`src/tui/screens/stories/story-row/story-row.tsx`) renders the marker. Pass the live hosts (or a computed lost flag) from `StoryList`. Keep `AGENT_LABEL_MAX` for the label part.
- **Thread rows.** `ThreadRow` (`src/tui/screens/stories/thread-row/thread-row.tsx`) is shared by the Threads tab and the Factory view (`factory-view.tsx`). Add props for the host column and the connection; the lists decide if any Thread is remote.
- **Held entries.** `heldAction`, `listHeldEntries` in `src/services/outbox-apply/held-actions.ts`. `isAbandoned` in `src/services/thread/thread-types.ts`. Read the held count with `listHeldEntries` only for abandoned Threads. The apply and the discard take the Project write lock in the service; the TUI calls the service only, and does not need a running factory.
- **Keys.** Add `a` and `d` to `handleActionKey` in `src/tui/screens/stories/threads-tab/threads-tab-actions.ts`, next to `x` and `r`. Use `runExclusive` and the toasts as `sendCommand` does. Add a second confirm state (or a union) for the discard dialog, as `setConfirm` does for the interrupt. Add the hints in `threads-tab-view.ts`.
- **Screenshots.** Use the `rowbly-screenshots` skill. Write a test Project with a `status.json` that has a live owner and a `hosts` list, and Thread files with `host` and `abandoned`, so that no real host or SSH is necessary.

## Assumptions

- "The Factory view shows each host" means the Factory controls Modal (`FactoryOverview`), next to the `Workers` row. Reason: the TUI "Factory view" is the read-only Thread list; Factory controls already show the factory status and the worker counts, and a host list there is the smallest change.
- The keys for held entries are in the Threads tab of a Story only, as `a` (apply) and `d` (discard, with confirmation). Reason: `controls.md` says that the Factory view is read-only and that the Threads tab has the Thread actions; `a` and `d` are free in the Threads tab.
- The host column shows only when the list has a remote Thread. Reason: the TUI without worker hosts must look as before.
- The `▶` marker shows `connection lost` without the duration. Reason: the Story row has little room; the Threads tab shows the duration.
- The lost rule comes from the services of ROW-100 (`threadConnection`). Reason: one rule for the CLI and the TUI.
- The Story stays one pull request. Reason: all parts are small TUI changes on top of existing services.
