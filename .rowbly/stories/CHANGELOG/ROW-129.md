## Goal

An idle TUI renders again without a reason. This costs CPU and can make the terminal flicker.

- The Factory view (`src/tui/screens/threads/factory-view/use-factory-view.ts`), the Thread pane (`src/tui/screens/threads/thread-pane/use-thread-pane.ts`) and the Threads tab (`src/tui/screens/stories/threads-tab/use-threads-tab.ts`) each have a private `useNow` clock. The clock sets `now` each second while a running Thread is in the data. Each tick renders the whole pane and its rows, which have no memo. The clock also ticks while a full-screen view covers the pane.
- `useFactoryChanges` (`src/tui/hooks/use-thread-changes.ts`) reads the factory status again each 5 s. `useAsync` (`src/tui/hooks/use-async.ts`) always sets a new state object with the new data, so the shell and each consumer of `FactoryStatusContext` render again, also when the status did not change.

The result: an idle board, with the factory stopped, makes no React commits between user actions. A 5 s poll that reads the same status causes no render.

## Scope

In scope:

- One shared clock hook in `src/tui/hooks/` that replaces the three private `useNow` copies.
- The clock ticks only while the pane shows a running Thread and no full-screen view or overlay covers the pane.
- An optional equality check in `useAsync`. When a run gives data that is equal to the current data, the state does not change.
- An equality function for `FactoryStatus`, and its use in the shell factory status read and the standalone status read of the Threads tab.

Not in scope:

- A memo for the rows of the panes. The clock stops, so the rows do not render when idle.
- Changes to the board read (`useStoryChanges`) or the activity read (`useFactoryStateChanges`). They read only after a file event.
- Changes to the 5 s poll interval or to the file watchers.
- The profile of the TUI after all performance fixes. That is ROW-137.

## Acceptance criteria

- [ ] `src/tui/hooks/` has one clock hook, for example `useClock(enabled: boolean): number`. The three files above use it and have no private `useNow`.
- [ ] The Factory view clock ticks only while a running worker Thread is in the active groups and the main overlay is closed.
- [ ] The Thread pane clock ticks only while the Thread is live and its full-screen conversation is closed (`!full.isOpen`) and the main overlay is closed.
- [ ] The Threads tab clock ticks only while the tab is selected, a Thread runs, its full-screen conversation is closed, the tab is not covered (`useCovered()` is false) and the main overlay is closed.
- [ ] When the clock starts again, it sets `now` to `Date.now()` immediately, so that the run time is correct at once.
- [ ] `useAsync` accepts an optional third argument `{ isEqual?: (a: T, b: T) => boolean }`. When a successful run gives data that `isEqual` reports as equal to the current data, and the state has no error and is not loading, the state object stays the same. Without `isEqual`, the behaviour does not change.
- [ ] `src/services/factory/factory.ts` exports a pure function `sameFactoryStatus(a, b)` (it accepts `undefined`). `src/services/factory/factory.test.ts` tests it: equal statuses give `true`; a different `phase`, `heartbeatAt`, `owner`, `attention` or `undefined` against a status gives `false`.
- [ ] `useShellData` (`src/tui/shell/shell/use-shell-data.ts`) and `useTabStatus` (`use-threads-tab.ts`) pass `sameFactoryStatus` to `useAsync`.
- [ ] A person examines the TUI with the `rowbly-screenshots` skill: the run time of a running Thread still counts up each second in the Factory view, the Thread pane and the Threads tab, and it is correct after the full-screen view closes.
- [ ] A person examines an idle board with the factory stopped, with a temporary React `<Profiler>` `onRender` counter around the shell (not committed): no commit occurs in 15 s with no user action.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- `OverlayHost` (`src/tui/components/overlay-host/overlay-host.tsx`) knows when the main overlay is open. Today it shows this only through `ActiveContext`, which also changes with the focus. Add a boolean context, for example `OverlayOpenContext` with a `useOverlayOpen()` hook in `src/tui/hooks/shell.ts`, and provide it from `OverlayHost`. Outside the shell the value is `false`.
- `useFullScreenConversation` gives `isOpen`. The Thread pane already reads `full.isOpen`. The Threads tab gets `full` from `useTabSelection`; compute the clock flag after `full` exists.
- `useCovered()` is in `src/tui/components/modal-layer.ts`.
- `useAsync`: compare in `settleData` with a `setState` updater. Return `prev` when `prev.data !== undefined`, `!prev.loading`, `prev.error === undefined` and `isEqual(prev.data, data)`. React then skips the render. Keep `isEqual` in a ref, so that a new function on each render does not run the effect again.
- `sameFactoryStatus` can compare `JSON.stringify` of the two values. `getFactoryStatus` builds the object in a fixed key order. A running factory changes `heartbeatAt` and `responsive`, so a live factory still renders; this is correct.
- `FactoryStatus` is in `src/services/factory/factory.ts`. The TUI may import a pure function from a service (service-layer rule 1).
- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` before the change.
- Do not load Pi from these files.

## Assumptions

- The story asked to update `use-async.test.ts` and the hook tests. These files do not exist, and `docs/architecture/testing.md` forbids tests in `src/tui/`. The equality logic goes into a service function with a service test, and the hooks get a manual check. Reason: obey the repository test rules.
- The equality check is opt-in in `useAsync` and is used only for the factory status. Reason: smallest scope; other reads change only after a file event or a user action.
- "Hidden" means not mounted, or the Threads tab is not selected, or a Modal or the main overlay covers it. The Factory view mounts only while the Story panel shows it, and the Thread pane mounts only while the sidebar shows it. Reason: this is the existing behaviour in `story-panel.tsx` and `story-sidebar-form.tsx`.
- The "no React commits" criterion is a manual check with a temporary `<Profiler>`. Reason: the repository has no profile tool, and TUI tests are forbidden. ROW-137 records the numbers.
- A memo for the rows is not part of this Story. Reason: the Fix list of the author does not ask for it, and a stopped clock removes the idle renders.
