## Goal

`ThreadPanel` (the Threads tab of the Story modal) and `ThreadPane` (the Story sidebar of the Factory view) render the same Thread body inside a different frame. The code is duplicated, so a change to one copy can miss the other copy. Make one `ThreadBody` component for the shared part. Each screen keeps its own outer frame and its own differences. The user sees no change.

## Scope

In scope:

- A new component `ThreadBody` that renders the shared body: `ThreadDetail`, then a `Box marginTop={1}` with a `ConversationView`, then a `ThreadSteerInput`.
- An optional `header` slot (above `ThreadDetail`) and an optional `beforeConversation` slot (between `ThreadDetail` and the conversation).
- Props and flags for the differences between the two screens (see Technical notes).
- `ThreadPanel` and `ThreadPane` use `ThreadBody`.

Not in scope:

- A change to the outer frame of each screen: `Panel` and the empty text in `ThreadPanel`; the outer `Box`, `full.inline`, the key hints and the row calculation in `ThreadPane`.
- A change to `ThreadDetail`, `ThreadSteerInput`, `ConversationView`, `ThreadChecks` or `useThreadPane`.
- A change to the visible behaviour, the keys or the layout of either screen.
- Tests for the TUI (AGENTS.md: do not write tests for the TUI).

## Technical notes

Files:

- `src/tui/screens/stories/thread-panel/thread-panel.tsx` (lines 91-120, the body inside `Panel`).
- `src/tui/screens/threads/thread-pane/thread-pane.tsx` (lines 73-110, the body inside the outer `Box`).
- New: `src/tui/screens/stories/thread-body/` (`thread-body.tsx`, `index.ts`). Put it in `stories/` next to `thread-detail/` and `thread-steer-input/`, because `screens/threads/` already imports these from `../../stories/index.js`. The `stories` screen must not import from `screens/threads/`, so `ThreadChecks` goes in through a slot and not by an import.

Differences between the two screens, now:

| Item | `ThreadPanel` | `ThreadPane` |
| --- | --- | --- |
| Above `ThreadDetail` | nothing | `Open Story` Button |
| `ThreadDetail` props | `connection`, `held` | none |
| Between detail and conversation | nothing | `ThreadChecks` |
| Conversation shows | `selected && shownId === current.id` | always |
| `ConversationView` `key` | `current.id` | none |
| `active` | `viewing && !steering` | `active && !steering` |
| `wheel`, `onWheelFocus` | not set | `props.clickable && !full.isOpen`, `props.onFocus` |
| Width / height | `threadWidth`, `conversationHeight` | `layout.width`, `conversationHeight(layout.height, head)` |
| Steer input shows | `status === "running"` | `status === "running" && role === "worker"` |
| Steer name | `${storyId} ${threadName}` | `${current.storyId ?? "Factory"} ${threadName}` |
| Steer `clickable` | `listing \|\| viewing` | `props.clickable && active` |
| Steer `onFocus` / `onLeave` | `onFocusSteer` / `onLeaveSteer` | `setSteering(true)` / `setSteering(false)` |

Suggested `ThreadBody` props (all `readonly`):

- `ctx: ServiceContext`, `thread: ThreadRecord`, `now: number`, `compact: boolean`.
- `connection?: ThreadConnection`, `held?: number` (passed to `ThreadDetail`).
- `header?: ReactNode`, `beforeConversation?: ReactNode`.
- `showConversation: boolean`, `conversationActive: boolean`, `wheel?: boolean`, `onWheelFocus?: () => void`.
- `width: number | undefined`, `conversationHeight: number | undefined`.
- `steerable: boolean`, `steerName: string`, `steering: boolean`, `steerClickable: boolean`, `onFocusSteer: () => void`, `onLeaveSteer: () => void`.

Constraints:

- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` before the change.
- Use `.js` extensions in relative imports and dash-case file names.
- `ThreadPane` keeps its `headRows` calculation, `FULL_DETAIL_MIN_HEIGHT`, the key hints and `{full.inline}` after `ThreadBody`.
- `ThreadSteerInput` keeps `key={thread.id}`.

## Assumptions

- `ThreadBody` lives in `src/tui/screens/stories/thread-body/` and not in `src/tui/components/`. Reason: it depends on `ThreadDetail` and `ThreadSteerInput`, which are in `screens/stories/`, and `screens/threads/` already imports them from there.
- The pane-only parts (`Open Story` Button and `ThreadChecks`) go in through two slots, `header` and `beforeConversation`, and not through flags. Reason: the Story asks for a `header` slot, `ThreadChecks` comes after `ThreadDetail` so it needs a second position, and `stories/` must not import from `threads/`.
- The steer condition and the steer name are computed by each screen and passed as `steerable` and `steerName`. Reason: the rules are different (worker-only in the pane; the fallback "Factory" in the pane), and the caller already has the data.
- `ThreadBody` always sets `key={thread.id}` on `ConversationView`. Reason: the panel already does it, and a remount when the thread changes is safe for the pane; it keeps one code path. If the developer finds a visible change in the pane (for example the scroll position), make the key optional and keep the old behaviour of each screen.
- No new tests. Reason: AGENTS.md says not to write tests for the TUI; the existing checks (`lint`, `typecheck`, `test`, `build`) cover the change.
