## Goal

Add end-to-end tests of the remote factory, from the launch to the board. The tests run the
factory manager on the main machine with a faux Pi provider. They also run one or two in-process
worker hosts that use the real host services behind the fake transport. The tests show that the
features of ROW-93, ROW-98, ROW-99 and ROW-101 work together. These tests do not test each part
alone.

Read the Spec `remote-worker-hosts`.

## Scope

In scope. Each item is one or more `it` cases at the factory manager level (`createFactoryManager`).
Each case uses `createFakeHostAgent` with `createHostRunner` and a faux provider:

1. **Full run on a host:** the launch, the outbox entry of the Stage move, the completion, and the
   canonical commit of the result.
2. **Disconnect and reconnect during a run:** each outbox change arrives on the board one time.
3. **Cancel while offline:** the stop goes first on reconnect, and the entries are held. Then
   `heldAction` with `apply` on one Thread, and with `discard` on a second Thread.
4. **Inbound update while a remote worker runs:** a canonical change gets to the copy on the host.
   A field that the worker changed keeps the value of the worker.
5. **Placement:** run `reserveWorker` without a `host` for each policy (`prefer-local`,
   `most-free`, `prefer-remote`). Use the main machine and two worker hosts. Also do a case with a
   full host.
6. **Attachments in both directions:** a PNG that a remote worker adds gets to the canonical
   Story. A PNG of the canonical Story gets to the cache of the host.

Not in scope:

- Tests with real SSH, a real network or live credentials.
- Tests of the real daemon process (`factory-runner`) or of the TUI.
- The same per-step cut matrix that `remote-reconnect.test.ts` already has.
- Changes to the unit tests that already exist for each part (`remote-executor/*.test.ts`,
  `placement.test.ts`, `outbox-apply/*.test.ts`).
- Documentation. ROW-105 does it.

## Acceptance criteria

- [ ] A new test file `src/services/factory-manager/remote-factory-e2e.test.ts` has at least one
  `it` case for each of the items 3 to 6 of the scope.
- [ ] The full-run case (item 1) checks that, after the Thread completes and the commit step runs,
  `git -C <root> log -1 --format=%s` gives the canonical commit message, and that the commit
  contains the Story file in the new Stage. This case can be in the new file or in
  `remote-full-run.test.ts`.
- [ ] Item 2: after a disconnect during a run and a reconnect, the Story has the change of the
  worker. Each outbox `seq` of the Thread is applied one time (a spy on the apply or the
  last-applied `seq` shows this). The Thread completes one time. An existing case in
  `remote-reconnect.test.ts` can satisfy this criterion. If it does, add a reference to it in a
  comment in the new file.
- [ ] Item 3: on reconnect, the first command to the host is `stop-thread` (or `cancel-thread`) of
  the abandoned Thread. The canonical Story does not change before the user action. `apply` writes
  the held changes to the Story. `discard` removes the held folder and does not change the Story.
- [ ] Item 4: while the remote worker runs, a change to a canonical Story field (for example the
  title) is in the copy of the Thread on the host after the next `reconcile`. A field that the
  worker changed in the copy keeps the value of the worker.
- [ ] Item 5: with one free slot on each machine, `prefer-local` gives `local`, `prefer-remote`
  gives a worker host, and `most-free` gives the machine with the most free slots. A full host gets
  no worker, and the reservation goes to a machine with a free slot.
- [ ] Item 6: a PNG that a remote worker adds with `rowbly add-attachment <story> <file>` is in the canonical
  Story after the outbox apply, with the same id and `sha256`. A PNG of the canonical Story gets to
  the host cache with one upload, and a second launch does not send it again.
- [ ] The tests use no network and no live credentials. `PI_OFFLINE=1`, `allowModelNetwork: false`
  and `InMemoryCredentialStore` are set, as in `remote-full-run.test.ts`.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- Copy the pattern of `src/services/factory-manager/remote-full-run.test.ts` and
  `remote-reconnect.test.ts`. They have a temporary Project with a Git repository, a bare `origin`,
  and a clone of the host at `$HOME/.local/share/rowbly/projects/remote/repo`. They also have a
  faux provider `worker`, `createCliShim` and `writeCliShim` with tsx, and `createFakeHostAgent` with
  `createHostRunner`.
- `FactoryDependencies.hostConnection(host)` takes the host id. Return a different
  `FakeHostAgent.transport` for each host. Give each fake host its own `home` folder. Return the
  hosts from `workerHosts`, each with `maxWorkers`, `state: "connected"` and
  `providers: ["worker"]`.
- Disconnect and reconnect: `FakeHostTransport.disconnect()` and `reconnect()`
  (`src/services/test-project/fake-host-transport.ts`). Recorded commands: `FakeHostAgent.calls`.
  The `cutting` wrapper in `remote-reconnect.test.ts` cuts the connection at a run step.
- Cancel and abandon: `manager.cancelWorker(id, runId)` while the host is disconnected. Held
  entries: `heldAction` in `src/services/outbox-apply/held-actions.ts` and the held folder
  `runtime/hosts/<host>/held/<threadId>/`. Use `abandoned-threads.test.ts` as an example. It uses a
  scripted host, and the new test must use the fake host agent.
- Inbound updates: the scan in `reconcile` compares the canonical files with
  `runtime/hosts/<host>/threads/<threadId>/base.json`. The host applies the updates with
  `applyHostInbound` (`src/services/host-agent/host-inbound.ts`). The copy is
  `threadPaths(host.paths, threadId).copy`. To keep the worker busy while the test changes the
  board, use a faux response that waits for a promise. `FauxResponseStep` can be a function.
- Placement: `src/services/factory-manager/placement.ts` and `worker-placement.ts`. Set the policy
  with `updateFactorySettings({ placement })`. `manager.snapshot().hosts` shows the used and
  maximum slots.
- Attachments: outbox `attachment.add` entries and blobs (`src/services/outbox/`), `rowbly host
  blob`, and the cache (`host-agent-cache.ts`, `remote-attachment.test.ts`).
  `FakeHostTransport` records the uploads.
- Canonical commit: `commitCanonicalProject` in `src/services/project-write/project-write.ts`. The
  manager calls it in `runSideSteps` (`supervisor-steps.ts`). The default message is
  `DEFAULT_COMMIT_MESSAGE`.
- Each case starts a CLI shim with tsx and is slow. Use a timeout of 60 s for each case, as the
  existing remote tests do. Use `vi.waitFor` and do not use fixed sleeps.
- Obey `.agents/skills/rowbly-code-style/SKILL.md`. Test files have the relaxed rules. A helper
  that more than one test file uses goes into `src/services/test-project/`. Knip must not report an
  unused export.

## Assumptions

- "Daemon tests" means tests of the factory manager in the test process (`createFactoryManager`),
  not of a spawned daemon process. Reason: the existing remote tests use this pattern. A spawned
  daemon cannot use the faux provider, and the project rules do not permit a faux-provider flag in
  production.
- The existing cases in `remote-full-run.test.ts` and `remote-reconnect.test.ts` can satisfy items
  1 and 2 when they show all of the criterion. Only the missing checks are added. Reason: this
  gives the smallest scope and does not duplicate slow tests.
- A test with two worker hosts is necessary only for placement. The other cases use one host.
  Reason: the Story says "one or two worker hosts", and the other features work for each host
  alone.
- If a test finds a defect in the production code, the developer repairs the defect in the same
  pull request when the repair is small. If the repair is large, the developer creates a new Story
  for the defect and marks the case with `it.skip` and a comment that gives the Story id. Reason:
  the Story must not stop, and one pull request must hold the work.
