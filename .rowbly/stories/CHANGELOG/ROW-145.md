## Goal

The TUI is slow when a list has many rows, for example a list of more than 500 Threads. The Thread lists render a component for each Thread, also for the Threads that are not on the screen. The author asked for a virtualized list (only the rows in view render) for the Story list and the Thread lists, and gave https://github.com/archcorsair/ink-virtual-list as the model.

The result: the Thread lists render only the rows that are in view, so that the TUI stays fast with 500 or more Threads. The visible behaviour of the lists does not change.

## Scope

In scope:

- A shared virtualized list component in `src/tui/components/` that renders only the rows in its window. Rows can have different heights in lines.
- The Thread list of the Threads tab of a Story (`src/tui/screens/stories/thread-list-panel/thread-list-panel.tsx`) uses it.
- The Factory view of the Threads screen (`src/tui/screens/threads/factory-view/factory-view.tsx`) uses it. This view shows the Threads of all Stories, so it gets the largest lists.
- A check that the Story list (`src/tui/screens/stories/story-list/story-list.tsx`) renders only the rows in view. It already does this with `listWindow` and `visibleItems`. Change it only if the check finds a path that renders all rows when the height is known.

Not in scope:

- The `ink-virtual-list` npm package as a dependency. See Assumptions.
- Other lists that use `ScrollBody` (attachments, settings, models, onboarding, modal bodies).
- The speed of the service code that reads the Threads (`thread` service, file watchers).
- A change to how a Thread row or a section heading looks.

## Technical notes

- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` first. Use only colours from `theme`.
- `ScrollBody` (`src/tui/components/scroll-body/scroll-body.tsx`) renders all children and moves them with `marginTop={-start}` inside a box with `overflow="hidden"`. This is the cause of the slow render: each Thread row renders, also when it is hidden. Its `ScrollFocusContext` reveals a focused row through `measureElement`. A windowed list cannot measure rows that do not render, so it must compute the window from the row heights and the cursor.
- Row heights:
  - `ThreadRow` (`src/tui/screens/stories/thread-row/thread-row.tsx`): 1 line when `compact`; else 2 lines, plus 1 line when the Thread has an outcome (`threadOutcome`). Each row truncates its text (`wrap="truncate-end"`), so a row does not wrap.
  - `ThreadSectionRow` (`src/tui/screens/threads/thread-section-row/`): 1 line, plus 1 empty line above when `spaced` is true.
  - Put a pure function that gives the height of a row next to the row component, so that the list and the row agree.
- Window logic: keep a first-row offset in state. When the cursor goes out of the window, move the offset by the smallest amount that brings the cursor row into view (the `ScrollBody` behaviour). The wheel and `pgup`/`pgdn` change the offset and do not move the cursor. Clamp the offset when the rows or the height change. `story-list-window.ts` and `scroll-offset.ts` (`clampOffset`, `wheelOffset`) have logic to reuse or generalize.
- Mouse: use `useMouse` from `src/tui/hooks/` and `WHEEL_LINES`, as `ScrollBody` and `StoryList` do.
- The Factory view gets its rows from `factoryViewRows` and its cursor from `factoryViewCursor` (`src/tui/screens/threads/factory-view-rows.ts`, `use-factory-view.ts`). The Threads tab gets its cursor from `threads-tab.tsx`.
- `ThreadListPanel` reduces the inner height by 1 for the queue note (`scrollHeight`). Keep that.
- Tests: do not add tests in `src/tui/` (see `docs/architecture/testing.md`). If the window math goes in a pure module outside `src/tui/`, a test can go next to it, but this is not necessary.
- Update `docs/architecture/tui.md` if it describes the list components, in STE.

## Assumptions

- Do not add `ink-virtual-list`. Write a small virtualized list in `src/tui/components/` that uses the same technique. Reason: version 0.3.0 of the package has the peer dependency `ink ^6 || ^7`, and Rowbly uses `ink ^8`. Its `dist/index.js` imports `jsxDEV` from `react/jsx-dev-runtime`. Rowbly loads React with `NODE_ENV=production` (`src/services/react-mode/`), and in that mode `jsxDEV` is `undefined`. A test with Ink 8 and `NODE_ENV=production` failed with `ERROR jsxDEV is not a function`. The package also supports only one fixed height for all rows, and the Thread lists have rows of 1 to 3 lines.
- The Story list does not need a new component. Reason: `StoryList` already renders only `visibleItems(rows, listWindow(...))`, and its drag-and-drop and gap logic depend on that window. A move to the shared component would change working code without a gain.
- The wheel and `pgup`/`pgdn` keep their current behaviour (they scroll and do not move the cursor). Reason: the smallest change to the behaviour that the user sees.
- The keys and the hints of the lists do not change. Reason: the Story asks only for a faster render.
