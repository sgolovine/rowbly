## Goal

A remote Thread continues correctly after a restart of the factory daemon, and a remote Thread resumes only on its own worker host.

Read the Spec `remote-worker-hosts`, section "Disconnects".

- The recovery after the death of the local owner (`recoverFactory` in `src/services/factory-recovery/factory-recovery.ts`) does not mark a remote run (`thread.host` is not `local`) as interrupted with `OWNER_DIED`.
- At start, the daemon asks each worker host for its runs, adopts each active remote Thread into the remote executor (without a new `launch` command), sends the durable command queue of ROW-97 first, and then reads the run states, the results and the outbox.
- A remote Thread resumes only on its own host (`thread.host`). A resume does not use the placement rules to select a different host. When the host is not `connected` or has no free slot, the resume gives a `ConflictError` and tries again later.
- The automatic network resume of `NETWORK` Threads (`resumeNetworkThreads` in `src/services/factory-manager/network-resume.ts`) works for remote Threads on their host, only while the host is `connected`.

Tests use the fake transport (`createFakeHostTransport`). No test uses real SSH.
