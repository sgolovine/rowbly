## Goal

The factory status shows the connection of each worker host and of each remote Thread.

Read the Spec `remote-worker-hosts`, section "Status and TUI".

## Scope

In scope:

- A `hosts` list in `status.json` and in `rowbly factory status --json`: the id, the state, `lastSeenAt`, the latency and the used and maximum slots.
- The attention entry `host:<id>` when a host stays disconnected. It goes away on reconnect.
- A remote Thread whose host is not connected shows `connection lost` and the time since the last contact, in `rowbly thread` and in `rowbly status`.
- The `connectivity` field of the provider stays as it is.

Not in scope:

- The TUI. Another Story adds it.

## Acceptance criteria

- The status read does not load Pi and does not open SSH.
- Tests cover each host state and a remote Thread with a lost connection.
