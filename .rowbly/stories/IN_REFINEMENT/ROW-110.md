## Goal

When a remote worker reads a PNG attachment that is not on its worker host, the host gets the PNG from the main machine. If the host is offline, the read fails with a clear error.

Read the Spec `remote-worker-hosts`, section "The copy and inbound updates".

ROW-92 puts the PNG files of the Story and of its upstream Stories into the copy of the Thread, through the PNG cache of the host. This Story adds the other PNG files on demand:

- The read path of the CLI in the copy finds a PNG that is in the manifest but not in the copy or the cache.
- The host asks the main machine for the PNG on the attach channel, puts it in the cache and gives it to the worker.
- Without a live attach channel, or after a time limit, the read fails with a clear error that tells the worker that the host is offline.
- The main machine answers the request on the channel (with the dispatch of ROW-96).

Not in scope: inbound updates (ROW-98).
