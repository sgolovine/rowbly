## Problem
`src/tui/components/scroll-focus.ts:9` calls Ink's `useBoxMetrics` in every SelectionRow, SelectListRow and FieldRow. That hook runs an effect after every render of the row and a root layout listener after every commit, each calling `measureElement`. So each commit lays out the whole tree and then measures every mounted row. In the production-mode profile, Ink's output renderer, Yoga and `string-width` took 2.6 s of a 12 s session.

## Fix
- Gate the measurement behind `focused`: only the selected row or the active field measures, or track the selected row in the list parent and measure one node.
- Keep the behaviour of `useScrollFocus`: the active row still scrolls into its viewport after the first layout.
- Check the story list, the select list, the forms, the thread lists and the settings sections.

## Done when
A commit with 100 mounted rows calls `measureElement` for at most one row. Profile with the PTY method of the `rowbly-screenshots` skill and `NODE_OPTIONS=--cpu-prof`.
