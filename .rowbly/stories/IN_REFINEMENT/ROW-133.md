## Problem
`src/tui/shell/shell/story-changes.ts:51,114,120,179` and `shell-selection.ts:126,133` call `env.reload()` after each move, save or delete. `use-shell-data.ts:57` then runs `hasProject`, `repairDuplicates`, the project, the stages, all Story files and the factory activity. The file watcher at `use-shell-data.ts:153` fires 100 ms later and reads everything again, so each action reads and renders the whole board twice.

## Fix
- After a service call returns the changed Story, apply it to the board state in place (replace, move or remove the Story) and let only the watcher do the full read.
- Run `repairDuplicates` on the first load only, not on each refresh.
- Keep the error paths: a failed write still reloads.
- Update the shell hook tests.

## Done when
A Stage move of one Story reads the Story files one time at most (the watcher echo), and the list updates before the read finishes.
