## Goal

When a Story file changes, read only that Story again, and not the full board.

## Context

A change in a watched `.rowbly/` folder calls `data.refresh` in `src/tui/shell/shell/use-shell-data.ts`. This reads the full board again, parses the front matter of all Stories, and renders all of the board again. While the factory runs, agents write Story files frequently, so this occurs frequently. The watcher in `src/services/story-watch/story-watch.ts` already receives the name of the changed file.

## Scope

- Send the changed file names from the watcher to the TUI, after the quiet time of `project-watch`.
- Add a service function that reads one Story by its file. A front end must not parse Story files.
- When only Story files changed, read each changed Story and put it into the board in memory, with the same method as `patchBoard` and `boardWithStory`. Remove a Story whose file was deleted.
- Read the full board again when a change has no file name, when a change is not a Story file (for example the project config, a Stage file, a Spec or an attachment folder), or when a read of one Story fails.
- Keep object identity for the Stories that did not change, so that memoised rows do not render again.
- Update the tests next to each changed service.

## Acceptance criteria

- [ ] An edit of one Story file from a different process reads only that Story, and the board shows the change.
- [ ] A new Story file and a deleted Story file show correctly on the board.
- [ ] A change of the project config, a Stage file or a Spec still reads the full board again.
- [ ] A change with no file name still reads the full board again.
- [ ] The Stories that did not change keep the same objects after the update.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
