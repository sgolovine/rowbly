Read the Spec `deterministic-factory`.

## Goal

The user can select a worker model for the Stories with a tag. For example, the Stories with the tag `bug` get a different model. A rule in the factory settings replaces a model rule in a prompt.

## Now

`factory.storyWorkerModels` and `factory.stageWorkerModels` set a model for one Story or for one Stage. The Project prompt of this Project tells the supervisor which model to use for bug fixes, but the supervisor did not obey it.

## Scope

In scope:

- A new setting `factory.tagWorkerModels`: a map from a tag value to a model choice.
- The order of priority: the Story override, then the tag rule, then the Stage override, then `factory.workerModel`.
- When a Story has more than one tag with a rule, the first of these tags in the tag order of the Story applies.
- A rule must name a tag of the Project. `rowbly doctor` shows a warning for a rule of an unknown tag.
- A CLI option sets and clears a rule, for example `rowbly factory configure --tag bug --worker openai/gpt-sol`.
- Tests of the selection, and the docs of the factory settings.

Not in scope:

- A TUI control for the setting.
- A mix of models by count or by rotation.

## Acceptance criteria

- A Story with the tag `bug` and a rule for `bug` starts with the model of the rule.
- A Story override still has priority over the tag rule.
