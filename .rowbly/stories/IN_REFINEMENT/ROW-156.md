## Goal

Make each keypress in the TUI do less React work, so that the TUI shows each keypress quickly on a large board.

## Context

Only 6 files in `src/tui/` use `memo`. The board state is near the top of the tree, in `use-shell` and `use-shell-data`. Thus a cursor move can render the full board again. Ink also sends each keypress to each active `useInput` handler. The TUI has 96 `useInput` calls.

## Scope

- Measure first. Run the TUI with `node --cpu-prof` and the React Profiler on a large board. Record the render counts and the time from a keypress to a frame, before and after the change.
- Memoise the rows and panels that the board shows many times: `story-row`, `story-list-item`, the sidebar rows and the panels.
- Keep the callbacks stable. Give each row only the data that it shows, for example `selected={id === cursorId}`, and not the full board.
- Make sure that hidden screens and inactive panes set `isActive: false` on `useInput`.
- Examine `concurrent: true` in the Ink `render()` options. If it helps, use `useDeferredValue` or `useTransition` for slow output, for example fuzzy search results and the Markdown detail view. Concurrent mode changes the timing of renders, so some tests can need `act()`.
- Do not change the service layer or the storage format.

## Acceptance criteria

- [ ] The Story records the measurements before and after the change, on the same large board.
- [ ] A cursor move in the story list does not render the rows that did not change.
- [ ] No hidden screen or inactive pane receives keypresses.
- [ ] The Story records the decision about concurrent mode, with the reason.
- [ ] The keys, focus and mouse behaviour of the TUI do not change.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
