Read the Spec `deterministic-factory`.

## Goal

The manager starts the workers itself, from the decisions of the policy. The factory does not open a supervisor session. After this Story, no LLM makes a dispatch decision.

## Now

`superviseOnce` in `src/services/factory-manager/supervisor-loop.ts` reconciles the Project, then sends a digest to a Pi supervisor session. The supervisor calls `start_worker` for the `start` and `retry` decisions of the policy. It also keeps holds, notes and report acknowledgements, and the manager rotates its session and applies a backoff to its turns.

## Scope

In scope:

- On each pass, after the reconcile, the side steps and network resume, the manager reserves a worker for each `start` and `retry` decision, in the launch order of the policy.
- The manager selects the model from the factory settings (ROW-121, ROW-123) and the host with `placeWorker`.
- Each start has a fixed request ID, for example `<story-id>:<stage>:<attempt>`. Thus a second pass cannot start the same work two times.
- A `ConflictError` for one Story, for example a full host or a paused provider, skips only that Story. A different error sets the attention entry `dispatch`, and the pass continues.
- A retry starts a new Thread. Network resume does not change.
- A user command releases a parked Story, for example `rowbly factory release <story-id>`, because `release_story` goes away. A Story that the user moves or changes is released, as now.
- Remove the supervisor session, its rotation, its backoff and its Thread, `supervisor-tools.ts`, `src/services/supervisor-digest/`, `supervisorMessage()`, the holds, the notes and the report acknowledgements. An old `state.json` with `holds`, `notes` or report flags stays valid.
- The status no longer has a supervisor Thread. The TUI and the CLI must build and work without it.
- Old supervisor Threads stay valid, and the history shows them.
- Daemon tests with the faux provider: workers start without a supervisor session, one start for each decision, and a conflict for one Story does not stop the others.
- Update the docs of the native factory.

Not in scope:

- The removal of the supervisor settings, CLI options, prompts and TUI views (ROW-125).

## Acceptance criteria

- `rowbly factory start` starts workers for eligible Stories, and no supervisor session opens.
- The factory uses no model calls when no worker runs.
