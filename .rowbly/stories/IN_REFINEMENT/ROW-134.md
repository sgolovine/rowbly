## Problem
`src/services/factory-activity/factory-activity.ts:164` filters all attempts for each Story, O(stories × attempts). On this data root that is 125 Stories × 512 attempts. The state file is 856 KB and is parsed on each refresh; the state watcher in `use-shell-data.ts:155` triggers a refresh whenever the factory writes. The profile showed 156 ms per load, 90 ms of it in `JSON.parse`.

## Fix
- Group the attempts by Story ID one time, then look each Story up.
- Cache the parsed and checked state by path, `mtimeMs` and size, so an unchanged file is not parsed again. Keep the cache in the service module, not in the TUI.
- Update `factory-activity.test.ts`.

## Done when
`getFactoryActivity` for 125 Stories and 512 attempts runs in under 10 ms after the first read, and the match is linear.
