## Goal

At this time, the only way to add a worker host is the CLI (`rowbly host add <id> --ssh <target> --max-workers <n>`). The Hosts section of Settings (Settings › Factory › Hosts) shows only the text "No worker hosts. To add a worker host, run rowbly host add …" (see the attached screenshot). The user wants to add a worker host from the TUI also.

Result: in the Hosts section, the user pushes `a` (or clicks an "Add host" Button), types the host ID, the SSH target and the worker limit in a form, and submits. The TUI calls the same `addHost` service as the CLI. The new host shows in the list.

## Scope

In scope:

- An "Add host" control in the Hosts section, with the key `a` and a clickable `Button`. It is available with or without hosts.
- A `FormModal` with three fields: ID (text), SSH target (text) and Workers (number). All fields are mandatory.
- A call to `addHost` of `src/services/host/host.ts`. The form stays open and busy while the service checks Node, installs the Rowbly build and runs the check.
- After a success: close the form, show a toast, read the rows again, and show the items of the check under the list (the same view as `c`).
- The text without hosts changes: it tells the user to push `a` to add a host. It can keep the CLI command as a second option.
- Updates to the key hints, the code comments that say "The TUI does not add hosts", and `docs/architecture/tui.md`.

Not in scope:

- Remove a host from the TUI (`removeHost`).
- Log in to a host from the TUI (`host login`). It needs a terminal.
- A change to the `addHost` service or to the CLI command.
- `--purge`, or `host use --path`.

## Technical notes

- Files of the section: `src/tui/screens/settings/hosts-section/hosts-section.tsx`, `use-hosts-section.ts`, `hosts-actions.ts`, `hosts-view.ts`. Controls of the selected host are in `src/tui/screens/settings/host-actions-bar/host-actions-bar.tsx`.
- Service: `addHost(input: HostInput, ctx)` in `src/services/host/host.ts`. `HostInput` is `{ id, ssh, maxWorkers }`. It validates the input (`validateHostInput` in `host-rules.ts`: `VALIDATION` with one issue for each bad field, paths `id`, `ssh`, `maxWorkers`), refuses an existing ID (`CONFLICT`), installs the build over SSH, writes `~/.rowblyrc.json`, runs the check and returns `AddedHost` (`Host` plus `install` and `check: HostCheck`). Do not change the service.
- `hosts-actions.ts` already imports `updateHost` from `host.ts`, so the import of `addHost` adds no new module to the Settings path. Keep the Pi boundary.
- Extend `HostsTask` in `hosts-view.ts` with `{ kind: "add" }`. Add an `addForm()` (or a list of fields) next to `placementForm` and `workersForm`. `HostsTaskView` now uses one field; for the add form, give the three fields. The field names must be `id`, `ssh` and `maxWorkers`, so that the issues of a `ValidationError` show under the correct field.
- `FormModal` (`src/tui/components/form-modal/`) awaits an async `onSubmit`. A `ValidationError` shows its issues under the fields; a different error shows as a toast. The form is busy while `onSubmit` runs and ignores keys (`form-input.ts`).
- On success, call `finishChange` (toast, close, reload rows and settings, `onChange`) and `env.setCheck(added.check)`.
- In `handleHostsKey`, handle `a` before the check for a selected row, so that it works without hosts. Do not open the form while `env.busy` is set; show the same warning toast as `startRemote`.
- Add `{ key: "a", description: "add host" }` to `hostsHints` for both cases (with and without rows).
- Replace or remove `ADD_HOST_COMMAND` and the comments "The TUI does not add hosts".
- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` before the change. Use only components of `src/tui/components/` and colours of `theme`. Do not write TUI tests (AGENTS.md rule 4).
- Use the `rowbly-screenshots` skill to examine the result in a real terminal, if possible.

## Assumptions

- Only "add" is in scope. Remove and login stay in the CLI. Reason: the Story asks only to add a host. `host login` needs an interactive terminal, and remove was not requested. This is the smallest scope.
- The key is `a` and the form uses `FormModal`. Reason: `a` is free in the Hosts section, and the other values of the section (placement, worker limit) already use `FormModal`.
- The form stays open and busy during the install and the check, which can take minutes. Reason: `FormModal` already has a busy state, and this keeps the validation errors under the fields. A background operation with a spinner in the row is not possible, because the host has no row before the write.
- The TUI does not change the `addHost` service and does not add a "use for this Project" step after the add. Reason: the CLI `host add` does not do this either; the user pushes `u` after the add.
- The new host is not automatically selected. Reason: smallest scope; the new host is the last row of the list.
