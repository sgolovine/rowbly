## Goal

A Story can keep attachments of PNG images only. The author wants more file formats: any file that a user copies to the clipboard must be attachable to a Story.

This Story is the first part: a Story can keep a file of any type, from a file path (CLI and TUI). The user gets a Story attachment for a PDF, a JPEG, a text file, a log, a ZIP or a different file, and can list, open and remove it like a PNG today.

## Scope

In scope:

- The storage of an attachment of any file type in `.rowbly/attachments/<story ID>/`, with the 10 MiB limit that applies today.
- `rowbly add-attachment <story> <file>` accepts a file of any type.
- The Attachments tab of the TUI accepts a path to a file of any type.
- `list-attachments`, `open-attachment`, `remove-attachment`, `rowbly doctor`, the remote-worker outbox (`attachment.add` / `attachment.remove`) and the outbox apply work with all file types.
- Existing PNG attachments (manifest records with `type: "image/png"` and files `<id>.png`) continue to work without a migration.
- Documentation and help text that say "PNG" for a Story attachment.

Not in scope:

- The read of a copied file (or of an image type that is not PNG) from the clipboard. This is ROW-109. The clipboard paths (`--from-clipboard`, TUI `ctrl+v` / `alt+v`) continue to read a PNG image only in this Story.
- A preview of a file in the TUI.
- A change of the 10 MiB limit.

## Acceptance criteria

- [ ] `rowbly --json add-attachment <story> notes.txt` succeeds for a text file of 10 MiB or less. The manifest record has `name: "notes.txt"`, a MIME `type` (for example `text/plain`) and the correct `size`. A test examines this.
- [ ] A PDF, a JPEG and a file with an unknown extension (or no extension) attach with success. A file with no known type gets `type: "application/octet-stream"`. A test examines this.
- [ ] A file that is larger than 10 MiB fails with a `ValidationError` ("Attachment exceeds 10 MiB"). An empty file (0 bytes) attaches with success. A test examines this.
- [ ] A file with PNG bytes gets `type: "image/png"` and is stored at `<id>.png`, as today. A test examines this.
- [ ] The stored file of a non-PNG attachment keeps the extension of its name (`<id>.pdf`, `<id>.txt`). A name with no safe extension gives `<id>` with no extension. A test examines the path rule.
- [ ] A manifest that a previous version wrote (PNG records only) reads with no change and no error. A test examines this.
- [ ] `open-attachment` and `remove-attachment` work for a non-PNG attachment, and a failed remove restores the file and the manifest. A test examines this.
- [ ] `rowbly doctor` reports a manifest entry without its file and a file without an entry for all file types, and keeps the orphan file. A test examines this.
- [ ] A remote worker `attachment.add` of a non-PNG file is recorded in the outbox and applied on the main machine with the same bytes, name and type. A test examines this.
- [ ] `--from-clipboard` and the TUI paste key still accept only a PNG image. The existing clipboard tests pass.
- [ ] The help text of the attachment commands and the Attachments tab (button "New file", modal "Attach file", field "File path", empty-list text) do not say that only a PNG is accepted. A person examines the TUI.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- `src/services/attachment-files/attachment-files.ts`
  - `Attachment.type` changes from the literal `"image/png"` to a MIME type string. `isAttachment` accepts a string that agrees with `^[a-z0-9.+-]+/[a-z0-9.+-]+$` (lower case), a `size` from 0 to `MAX_ATTACHMENT_BYTES`, and keeps the other checks.
  - Replace `validatePng` with a general check (for example `validateAttachmentBytes`) that examines only the size. Keep a PNG signature check for the clipboard path.
  - Add a function that gives the MIME type of the bytes and the name: PNG signature → `image/png`; else a small table of extensions (for example `.jpg`/`.jpeg`, `.gif`, `.webp`, `.svg`, `.pdf`, `.txt`, `.md`, `.json`, `.csv`, `.log`, `.html`, `.zip`, `.gz`, `.tar`); else `application/octet-stream`. Do not add a new dependency for this.
  - Add one function that gives the file name of a record on disk: `<id>.png` when `type` is `image/png`; else `<id>` plus the lower-case extension of `name` when it agrees with `^\.[a-z0-9]{1,16}$`; else `<id>`. Use this function in all places that now build `` `${id}.png` ``: `attachment.ts` (`selected`, `removeAttachment`), `writeImage` in `attachment-files.ts`, `outbox-apply/apply-attachments.ts` (`currentHash`), and `doctor/attachment-checks.ts`.
  - The `PendingImage` type and `prepareImages` can keep their names or get general names (`PendingAttachment`). The TUI paste hook and the Story forms use them.
- `src/services/attachment/attachment.ts`: `readPngFile` becomes a general file read with the same 10 MiB guard. The error "Supply exactly one PNG file or --from-clipboard" changes to "Supply exactly one file or --from-clipboard". The `openAttachment` hint says "Open the file at …".
- `src/services/doctor/attachment-checks.ts`: an orphan is a file in the folder whose name agrees with `^a[0-9a-f-]{36}(\.[a-z0-9]{1,16})?$` and that no record owns. Temporary files (`.*.tmp`, `*.removed`) are not orphans. `manifest.json` is not an orphan.
- Outbox (`src/services/outbox/outbox-file.ts`, `outbox.ts`, `outbox-apply/*`, `attachment-cache`): the blob file name `blobs/<sha256>.png` and the cache name `<id>.png` stay unchanged, for compatibility with outbox folders of an older version. Only the content checks change: replace `validatePng` with the size check. The conflict copy in `host-files.ts` (`keepConflictPng`) can keep its name. Change only the user text that says "PNG" when it applies to any file.
- `src/commands/attachment/attachment.ts`: change the descriptions ("Attach a file to a Story", "List the attachments of a Story", "Open an attachment with the associated application", "Remove an attachment and its file"). Keep `--from-clipboard` as "read a PNG image from the clipboard".
- TUI: `src/tui/screens/stories/attachments-tab/` and `attachment-list/`: change the labels and the empty text. Read `.agents/skills/rowbly-tui-design/SKILL.md` first. Do not write TUI tests.
- `src/services/clipboard/clipboard.ts`: no change in behavior. `clipboardFailure` hint can say `rowbly add-attachment <story> <file>`.
- Documentation (STE): `docs/architecture/storage.md` (Attachments section and the tree line `<id>.png`), `docs/architecture/cli.md` (attachment text), and `skills/rowbly-reference.md` if it describes attachment commands. After a change to `skills/rowbly-reference.md`, copy it to each `skills/<name>/references/rowbly-reference.md`.
- Update the tests next to each changed service: `attachment.test.ts`, `open-attachment.test.ts`, `attachment-files.test.ts`, `attachment-cache.test.ts`, the doctor tests, the outbox and outbox-apply tests.

## Assumptions

- The first part of the work is the storage of any file type; the clipboard read of copied files is ROW-109. Reason: the clipboard read needs code for each platform, and it cannot work before a Story can keep a file that is not a PNG. Both parts together are too large for one pull request.
- Any file type is accepted; there is no allow-list or block-list. Reason: the author said "any file".
- The limit stays 10 MiB for each file. Reason: the author did not ask for a different limit, and the outbox and the cache use the same limit.
- An empty file is accepted. Reason: it is a valid file, and "any file" includes it.
- The MIME type comes from the PNG signature and a small extension table, with `application/octet-stream` as the fallback. Reason: smallest scope, no new dependency, and the `type` key of the manifest stays meaningful.
- The stored file keeps a safe extension of its name, and a PNG keeps `<id>.png`. Reason: `open-attachment` uses `xdg-open` / `open` / `rundll32`, which select the application from the extension; and existing PNG attachments need no migration.
- Outbox blob names and cache file names stay `<sha256>.png` and `<id>.png`. Reason: a worker host with an older version can have an outbox folder with these names; the names are internal and no user opens these files.
- The clipboard paths still accept a PNG only in this Story. Reason: the clipboard work is in ROW-109.
