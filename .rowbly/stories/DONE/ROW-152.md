## Goal

The TUI writes the status line of a Thread two times: in `ThreadRow` and in `ThreadDetail`. The outcome line (the error in `danger`, or the result summary) is also copied. The two copies can drift apart. Make one shared `ThreadStatusText` component and one shared `ThreadOutcomeText` component, and use them in both places. The user sees no change.

## Scope

In scope:

- A new `ThreadStatusText` component for the status line.
- A new `ThreadOutcomeText` component for the outcome line.
- Use of the two components in `thread-row.tsx` and `thread-detail.tsx`.

Not in scope:

- A change to the text, the colours or the layout that the user sees.
- Changes to `thread-text.ts` or `thread-host-view.ts`, other than the imports that the move needs.
- Other parts of the row or the detail (story id, host column, run time, model line, `DetailView` rows).

## Acceptance criteria

- [ ] `src/tui/screens/stories/thread-status-text/thread-status-text.tsx` exports `ThreadStatusText({ thread, now, held?, connection?, bold?, extra })`. It renders, in one `<Text wrap="truncate-end">`: the glyph from `THREAD_GLYPHS` in its colour with a space after it, `thread.status` in `theme.danger` when the status is `failed` (else `theme.ink`) and bold when `bold` is true, `extra` in `theme.inkMuted`, ` · waiting for network` in `theme.stageBoard` when `threadWaitsForNetwork(thread)`, `abandonedText(thread, held)` in `theme.stageBoard`, and `lostText(connection, now)` in `theme.danger`.
- [ ] `src/tui/screens/stories/thread-outcome-text/thread-outcome-text.tsx` exports `ThreadOutcomeText({ outcome, color })`. It renders `outcome.text` in `<Text wrap="truncate-end">`, in `theme.danger` when `outcome.error` is true, else in `color`.
- [ ] Each new folder has an `index.ts` with `export * from "./<name>.js";`.
- [ ] `ThreadRow` uses `ThreadStatusText` with `extra={` ${threadName(thread, stages)}`}` and `bold={selected}`, inside the existing outer `<Text wrap="truncate-end">` after the optional story id. Its row 3 uses `ThreadOutcomeText` with `color={secondary}` inside the existing `Box`.
- [ ] `ThreadDetail` uses `ThreadStatusText` with `extra={runsNote(thread)}` and no `bold` for its `status` value, and `ThreadOutcomeText` with `color={theme.ink}` for its `result` value (it keeps `"—"` when there is no outcome).
- [ ] `thread-row.tsx` and `thread-detail.tsx` no longer reference `THREAD_GLYPHS`, `threadWaitsForNetwork`, `abandonedText` or `lostText` directly (`grep` finds them only in the new component and in their source modules).
- [ ] The Threads tab of a Story and the Factory view show the same text, colours and bold state as before, for a running, failed, abandoned, network-waiting and connection-lost Thread. Only a person can examine this (for example with the `rowbly-screenshots` skill).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- Current copies: `src/tui/screens/stories/thread-row/thread-row.tsx` lines 72-79 (status) and 98-104 (outcome); `src/tui/screens/stories/thread-detail/thread-detail.tsx` lines 77-86 (status) and 87-93 (outcome).
- Differences that the props must keep:
  - The middle part: the row shows ` ${threadName(thread, stages)}` (with a leading space); the detail shows `runsNote(thread)` (that starts with ` · ` or is empty). Both are in `theme.inkMuted`. `extra` is a string that the caller gives with its own leading separator.
  - The row makes the status bold when it is selected. The detail does not.
  - The non-error outcome colour: `secondary` (`theme.inkMuted` or `theme.inkFaint`) in the row, `theme.ink` in the detail.
- `threadOutcome`, `THREAD_GLYPHS` and `threadWaitsForNetwork` are in `src/tui/screens/stories/thread-text.ts`. `abandonedText` and `lostText` are in `src/tui/screens/stories/thread-host-view.ts`. `ThreadConnection` is in `src/services/thread-connection/thread-connection.ts`.
- `ThreadRow` is used by `thread-list-panel` and by `src/tui/screens/threads/factory-view/factory-view.tsx`. `ThreadDetail` is used by `thread-panel`. Their props do not change.
- Follow `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md`. Give each component a doc comment. Use `.js` extensions in relative imports.
- Do not write TUI tests (AGENTS.md rule 4).

## Assumptions

- The two components are internal to `src/tui/screens/stories/` and are not added to the `stories/index.ts` barrel. Reason: only two sibling components use them; the smallest scope.
- `ThreadOutcomeText` takes the `outcome` from `threadOutcome(thread)`, not the thread, and the caller decides what to show when there is no outcome. Reason: the row hides the line and the detail shows `—`.
- Each component gets its own folder. Reason: the code style rule of one concern for each file and one folder for each component.
- No new tests. Reason: AGENTS.md says not to write tests for the TUI; the change has no service code.
