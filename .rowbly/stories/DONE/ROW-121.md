Read the Spec `deterministic-factory`.

## Goal

When the provider of the worker model is paused, the manager starts the worker with the next model in a fallback list. The supervisor does not select a different provider. This is decision 3 of the Spec, and ROW-124 depends on it.

## Now

`workerModelFor` in `src/services/factory-manager/worker-reservation.ts` selects the Story or Stage override, then the model from the supervisor, then `factory.workerModel`. `assertWorkerModel` refuses a model whose provider is paused (`Worker provider is paused`). `startWorkerRun` in `worker-launch.ts` does the same check again before the prompt. The supervisor prompt (`src/config/prompts/SUPERVISOR.md`, line "Use another available provider when a provider pause prevents a start.") tells the model to select a different provider. `isProviderPaused` in `manager-state.ts` tells if a pause still holds. `nextDeadline` in `manager-status.ts` already wakes the manager when a pause ends.

## Scope

In scope:

- A new setting `factory.fallbackWorkerModels`: an ordered list of `ModelChoice` values. It is optional. An absent key means no fallback.
- The manager first selects the model as now (Story override, Stage override, supervisor model, `factory.workerModel`). If the provider of that model is paused, it selects the first model of the list whose provider is not paused.
- The same selected model is used for the placement (`placeStory`), the validation, the Thread `model` and the launch.
- If the provider of the selected model is paused and no fallback model has a provider that is not paused, the `scan` in `manager-status.ts` changes each `start` and `retry` decision of that Story to `skip` with the reason `provider paused`. The status (`status.json`, `rowbly factory status`) and the supervisor tool `factory_snapshot` show this reason, because they read the decisions of `scan`.
- The `provider` of each queue entry (`queueEntry` in `manager-status.ts`) is the provider of the selected model, with the fallback.
- A resumed Thread keeps its model. Network resume (`network-resume.ts`) does not change.
- CLI options of `rowbly factory configure`:
  - `--fallback-worker <provider/model>` (repeat). It replaces the full list with the given models, in the given order. Each model is validated with `validateModelChoice`, as `--worker` is.
  - `--clear-fallback-workers`. It removes the key `fallbackWorkerModels`.
- Remove the line "Use another available provider when a provider pause prevents a start." from `src/config/prompts/SUPERVISOR.md`. Tell the supervisor that the manager applies the fallback models.
- Tests of the selection, of the settings validation, of the CLI options, and the docs of the factory settings.

Not in scope:

- A TUI control for the list.
- A fallback for the supervisor model.
- A thinking level option for each fallback model.
- The tag rule of ROW-123 and the dispatch of ROW-124.

- [ ] With the providers of the selected model and of all fallback models paused, `reserveWorker` starts no worker, and the decision of the Story in `scan` is `skip` with the reason `provider paused`.
- [ ] With no provider paused, the selected model is the same as before this change.
- [ ] A fallback model applies also when the selected model is a Story override, a Stage override or the model from the supervisor.
- [ ] A resumed Thread keeps its model, also when its provider is paused. The network resume tests pass with no change.

## Technical notes

- Settings: add `fallbackWorkerModels?: readonly ModelChoice[]` to `FactorySettings` in `src/services/factory-settings/factory-settings.ts`. Validate it in `validSettings` (an array of entries that pass `validModel`). Add the configure input keys and the flag rules (`overrideProblem` rejects the new flags with an override). Parse each value with `parseChoice` and validate with `chooseRole`-style `validateModelChoice`, with one shared auth runtime.
- Selection: add a pure function in `src/services/factory-settings/worker-overrides.ts`, for example `selectWorkerModel(settings, storyId, stage, model, isPaused)`. It gives `{ choice, paused }`: the resolved model, else the first fallback model whose provider is not paused. `paused` is true when the resolved model and all fallbacks have a paused provider. Test it in `worker-overrides.test.ts`.
- Manager: use the function in `workerModelFor` and in `assertSlotAvailable` of `worker-reservation.ts`, with `isProviderPaused(manager, provider)`. Keep the `Worker provider is paused` `ConflictError` for the case with no model available. Keep the check in `startWorkerRun` of `worker-launch.ts`.
- Status: in `scan` (`manager-status.ts`), add the skip reason `provider paused` for `start` and `retry` decisions when the selection gives `paused`. The supervisor model is not known in `scan`, so `scan` uses the settings only (Story override, Stage override, `workerModel`). Use the function in `queueEntry` too.
- CLI: `src/commands/factory/factory.ts` (`ConfigureOptions` and the `configure` command). Use a `collect` function for the repeat flag, as `factory-check.ts` does. Update `src/commands/factory/factory.test.ts`.
- The fallback list is a factory setting, so the manager reads it from `getState(manager).settings`.
- Do not load Pi in the settings or status paths. `agent-auth` stays a lazy import.
- Update `skills/rowbly-reference.md` only if it documents `factory configure` flags. If you change it, copy it to each `skills/<name>/references/rowbly-reference.md`.

## Assumptions

- The fallback applies to the selected model from any source: Story override, Stage override, supervisor model or `workerModel`. Reason: the Spec says "When its provider is paused, the first model of `factory.fallbackWorkerModels` ... applies" after the full priority list.
- If no model resolves (no override, no supervisor model, no `workerModel`), the manager does no pause check and does not use the fallback list. Reason: Pi selects the model then, and the manager does not know its provider. This is the current behaviour.
- `--fallback-worker` replaces the full list, and there is no option to add or remove one entry. Reason: smallest scope; it agrees with how `--worker` replaces the model.
- Fallback entries have no thinking level option. Reason: smallest scope. A user can write `thinkingLevel` in the config by hand, and validation accepts it.
- The model selection happens before the placement, and the placement uses the selected model. Reason: `placeStory` filters hosts by the provider of the choice.
- In `scan`, the supervisor model is not used for the `provider paused` reason. Reason: `scan` does not know it. ROW-124 removes the supervisor model.
- The skip reason text is exactly `provider paused`. Reason: the text of the original Story.
