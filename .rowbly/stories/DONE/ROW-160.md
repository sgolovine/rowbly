## Goal

The author likes the `Depends on` field of the Story form: it shows each chosen Story on one line, and a fuzzy picker adds Stories. The `Tags` field is a row of checkboxes (`[x] label`) with all the tags of the Project. A Project can have many tags, and a long row of checkboxes is hard to use.

Give the `Tags` field the same UI as `Depends on`: a searchable multiselect (`SearchableMultiSelect`). The user sees the chosen tags one on each line with a `✕`, a `+ add` line, and a fuzzy picker (`Add Tags`) that adds one tag at a time.

Original text of the author:

> I really like the "depends on" field and how we can add stories to it.
> Give the same UI treatment to the "Tags" input. A user may have many many tags.

## Scope

In scope:

- The `Tags` field of the new Story form (the request of the author).
- The `Tags` field of the General tab (edit form). Both forms use the same `storyFormFields` function in `src/tui/screens/stories/story-form.ts`, so the change applies to both.
- An update of the `Tags` field text in `docs/architecture/tui.md` (section "Story tags").

Not in scope:

- The creation of a new tag from the picker. Tags are added in Settings › Tags only.
- Changes to the tag service, to `createStory` / `updateStory`, to the tag sidebar, or to the tag slot of the Story row.
- Changes to the `Depends on` field or to the shared `SearchableMultiSelect` / picker components.

## Acceptance criteria

- [ ] In `storyFormFields`, the `tags` field is a `multiselect` with `searchable: true`. Its options and labels come from `tagChoices`, as before.
- [ ] When the Project has no tags, the `Tags` field does not show (no change).
- [ ] Manual check (a person, or the `rowbly-screenshots` skill): in the new Story form, the `Tags` field shows `none` and a `+ add` line when no tag is chosen. `enter`, typed text or a click on `+ add` opens a picker with the title `Add Tags`. The picker shows the tag labels, fuzzy search finds a tag by its label or its value, and `enter` adds the tag.
- [ ] Manual check: each chosen tag shows on its own line with its label and a `✕`. `←/→` select a chosen tag and `backspace` removes it. A click on `✕` removes it. The picker does not show a tag that is already chosen.
- [ ] Manual check: in the General tab of an existing Story, the same field shows the saved tags. A saved value that is not a tag of the Project shows as its value and the user can remove it.
- [ ] Save works as before: the new Story form gives the list to `createStory` as `tags`; the edit form gives the full list to `updateStory` only when the list changes. The chosen order of the tags is the saved order.
- [ ] `docs/architecture/tui.md` ("The `Tags` field" item) tells that the field is a searchable `multiselect` (`SearchableMultiSelect`) with the same behaviour as `Depends on`. The text is in ASD-STE100.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- The main change is one line in `tagsFormField` in `packages/cli/src/tui/screens/stories/story-form.ts`: add `searchable: true` to the `tags` field, the same as the `dependsOn` field.
- `FieldValue` (`src/tui/components/field-value/field-value.tsx`) renders a `multiselect` with `searchable: true` as `SearchableMultiSelect`. The form keys (`use-form-keys.ts`, `use-form.ts`) already give the `enter add` / `backspace remove` hints for a searchable multiselect.
- The picker title is `Add ${field.label}`, thus `Add Tags`.
- The picker search uses the option value and its label when the field has no `optionSearchText` (`searchable-select-picker.tsx`, `optionSearch`). Thus a tag is found by its value and its label without an `optionSearchText`. Add `optionSearchText` only if the check shows a problem.
- `tagChoices` and `tagsValue` in `src/tui/screens/stories/story-tag-view.ts` need no change: the form value stays a `string[]`.
- Do not write TUI tests (AGENTS.md). Follow the `rowbly-tui-design` and `rowbly-code-style` skills.

## Assumptions

- The edit form (General tab) also gets the new UI. Reason: both forms build the field with the same `storyFormFields` function, and two different UIs for one field would confuse the user.
- The picker does not create new tags. Reason: the `Depends on` picker only selects existing Stories, and tags are managed in Settings › Tags. This is the smallest scope.
- A stale tag value (not a tag of the Project) stays in the options as now, so the user can see and remove it. Reason: keep the current `tagChoices` behaviour.
