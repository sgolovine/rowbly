## Goal

When the user drags the edge of a sidebar in the TUI to change its size, the size is lost when Rowbly quits. The next launch shows the default sizes again. The user wants Rowbly to remember the sidebar sizes between launches.

The original request: "Remember the height and width of the sidebars on the right hand side between launches."

## Scope

In scope:

- Keep the three sizes that a mouse drag sets in the shell, between launches of the TUI:
  - the width of the Story sidebar (`storyWidth`, the sidebar at the right of the Story list, left edge drag),
  - the width of the Stage sidebar (`sidebarWidth`, right edge drag),
  - the height of the tag sidebar (`tagsHeight`, top edge drag).
- Save the sizes in `~/.rowblyrc.json` and read them when the TUI starts.
- A new service that reads and writes the sizes, with a test.
- Update `docs/architecture/storage.md` (the `.rowblyrc.json` section) and `docs/architecture/tui.md` (resize behaviour), in STE.

Not in scope:

- The expanded/collapsed state of the Story sidebar and the `storySidebar` display option (`regular`, `expanded`, `remember`). They do not change.
- The visible/hidden state of the Stage sidebar (`ctrl+b`).
- Sizes for each Project or each terminal size. One set of sizes applies to all Projects.
- A Settings entry or a key to reset the sizes.

## Acceptance criteria

- [ ] A new service (for example `src/services/layout-prefs/layout-prefs.ts`) has a read function and a write function for the sidebar sizes in `~/.rowblyrc.json`, under one new top-level key (for example `"layout": { "sidebarWidth": 30, "tagsHeight": 8, "storyWidth": 70 }`). It uses `readRc`, `writeRc` and `rcPath` from `src/services/user-rc/user-rc.ts`.
- [ ] A write keeps all other keys of `~/.rowblyrc.json` (for example `projects`, `hosts`, `deviceId`). A test examines this.
- [ ] A write changes only the sizes that it gets, and keeps the other saved sizes. A test examines this.
- [ ] A read of a file with no `layout` key, a missing file, or a size that is not a positive integer gives no value for that size (the default applies). It does not throw for a bad `layout` value. A test examines this.
- [ ] If Rowbly cannot read `~/.rowblyrc.json` (invalid JSON or not an object), the write does not write the file. A test examines this.
- [ ] A test uses `ctx.home` with a temporary directory. No test reads or writes the real home directory.
- [ ] At TUI start, `useSizeState` in `src/tui/shell/shell/use-shell-state.ts` starts from the saved sizes. A size that was not saved keeps its current default (`SIDEBAR_WIDTH`, `null`, `null`).
- [ ] The existing clamps in `src/tui/shell/shell/shell-frame.ts` still apply to a saved size. A saved size that is too large for the terminal shows at the largest size that fits, and does not break the layout. (A person examines this in a real terminal, or a test of `shell-frame.ts` examines it.)
- [ ] The TUI does not write the file at each step of a drag. It writes at most one time after the drag stops (for example with a debounce of about 300–500 ms after the last `onResize`), and it writes only if a size changed.
- [ ] A failed write or read does not stop the TUI. A failed write shows an error toast, as `recordOpenProject` in `use-shell-data.ts` does. A failed read uses the defaults.
- [ ] A person drags each of the three sidebar edges, quits Rowbly and starts it again: each sidebar shows the dragged size. (A person examines this, for example with the `rowbly-screenshots` skill.)
- [ ] `docs/architecture/storage.md` and `docs/architecture/tui.md` describe the new key and the behaviour, in STE.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- Current state: `useSizeState()` in `src/tui/shell/shell/use-shell-state.ts` holds `sidebarWidth` (default `SIDEBAR_WIDTH` = 22), `tagsHeight` (`null` = default) and `storyWidth` (`null` = 40% of the terminal width) in React state only.
- The drag handlers are in `src/tui/shell/shell/shell-handlers.ts`: `resizeStages`, `resizeTags`, `resizeStory`. They call the setters of `ShellEnv` (`src/tui/shell/shell/shell-state.ts`).
- `ResizeEdge` (`src/tui/components/resize-edge/resize-edge.tsx`) calls `onResize` at each pointer move of a drag. `useMouse` (`src/tui/hooks/mouse.ts`) has `onPull`, but no "pull ended" event. Use a debounce in the TUI hook, or add a pull-end event to `useMouse`. The developer selects the method.
- Limits: `SIDEBAR_MIN_WIDTH`, `SIDEBAR_MIN_HEIGHT`, `STORY_SIDEBAR_MIN_WIDTH`, `MAIN_MIN_WIDTH` in `src/tui/components/shell-layout.ts`. `shownWidthOf`, `besideTagsHeightOf` and `storyWidthOf` in `shell-frame.ts` clamp the sizes to the terminal. Save the size that the user dragged (the state value), not the clamped value.
- `~/.rowblyrc.json` rules (AGENTS.md safety rules): do not write the file if Rowbly cannot read it, and keep all other keys. `readRc` throws a `ValidationError` for a bad file; `writeRc` writes atomically and through a symlink. See `src/services/known-project/known-project.ts` for an example service on this file.
- Services must not import `react` or `ink`, and must not print. The TUI calls the service. The read can occur before the first render (load the sizes, then give them as initial state) or in an effect that sets the state one time after the read. Do not let a late read replace a size that the user dragged already.
- Write the service test next to the service. Do not write TUI tests.
- Keep the Pi SDK out of this path. The TUI start path must not load Pi.

## Assumptions

- "The sidebars on the right hand side" means the sidebars that the user can resize. Only the Story sidebar is on the right, and it has only a width. The "height" in the request applies only to the tag sidebar, which is on the left with the Stage sidebar. So all three dragged sizes are in scope. Reason: the request names both height and width, and the three sizes share one state hook and one storage method. The extra work is small.
- The sizes go in `~/.rowblyrc.json`, not in `.rowbly/rowbly.config.json`. Reason: sidebar sizes are a preference of one user and one terminal. The Project config is in Git and all users of the Project share it.
- One set of sizes applies to all Projects. Reason: smallest scope; the sizes depend on the terminal of the user, not on the Project.
- The saved value is the size that the user dragged, and the existing clamps apply at render. Reason: a smaller terminal at a later launch must still give a correct layout, and a larger terminal gets the size back.
