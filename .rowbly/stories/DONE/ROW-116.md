## Goal

ROW-96 gives the manager a remote executor. But only tests give the manager its worker hosts (`workerHosts`) and the connection of each host (`hostConnection`). This Story gives the factory daemon (`rowbly factory run`) the real values from the host registry. Then a user can use a worker host in production.

Read the Spec `remote-worker-hosts`, sections "Setup of a worker host", "Version" and "Placement".

## Scope

In scope:

- **A new service `src/services/worker-hosts/worker-hosts.ts`.** It makes the two manager dependencies of ROW-96 from the host registry: `createWorkerHostSource(ctx, deps)` gives `{ workerHosts, hostConnection }`. `deps` has injectable `transportFor(target)` (default `createSshTransport({ target })`), `build()` (default `localBuild`), the clock and the check interval, in the same way as `HostCheckDeps`.
- **`workerHosts()`** gives one `WorkerHostView` for each host of `listHosts` (`src/services/host/host.ts`) that is `enabled` and that has a record for the current Project (`hostProjectFor` in `src/services/host-project/host-project.ts`, or the same data from one read of `~/.rowblyrc.json`). A host that is not `enabled`, or that does not use the Project, is not in the list. `maxWorkers` comes from the registry.
- **The state and the providers of each host** come from the last check of the host:
  1. `ensureHostVersion(transport, { build })` (`src/services/host-install/host-install.ts`). It installs the exact Rowbly build when the host has a different version. The result `version-mismatch` gives the state `wrong-version`.
  2. Then `quickHostCheck(transport, build)` (`src/services/host-check/host-check.ts`). `ready: true` gives `connected` with the `providers` of the check. `ready: false` gives `not-ready`.
  3. A transport failure (SSH cannot connect) or a thrown error gives `disconnected`.
- **The check does not block the supervisor loop.** `workerHosts()` gives the last known views at once. A host that has no completed check yet has the state `not-ready`. When the last check of a host is older than the check interval (default 60 seconds), and no check of that host runs, `workerHosts()` starts a new check in the background. The checks of different hosts run in parallel. A new host in the registry, or a host that is on again, gets a check at the next call. The source gets the local build one time, and only when one or more hosts are in the list.
- **`hostConnection(host)`** gives `{ transport, rowbly, clone }`: the SSH transport of the host (one transport for each host, made one time and used again), `remoteRowblyPath(build.id)` as `rowbly`, and the `path` of the host Project record as `clone`. It also gives the connection of a host that is not `enabled` now, so that active remote Threads can complete and their outbox can sync. It throws a `ConflictError` when the host is not in the registry or does not use the Project.
- **The daemon.** `createManager` in `src/commands/factory-runner/factory-runner.ts` makes the source with the daemon context and gives `workerHosts` and `hostConnection` to `createFactoryManager`. The command stays thin.
- Tests in `src/services/worker-hosts/worker-hosts.test.ts` with a temporary home folder, a fake build and the fake transport. No test uses real SSH.
- Documentation in STE: `docs/architecture/native-factory/README.md` (the "Hosts" item and the "Connection" item, which now says "only tests give it") and `docs/architecture/native-factory/host-agent.md` if it describes where the hosts come from.

Not in scope:

- The heartbeat, the reconnect, the command queue of each host, the states `degraded` and `auth-failed`, and the `hosts` list in `status.json` (ROW-97). When ROW-97 adds the heartbeat, the heartbeat gives the state.
- A change to the placement, the remote executor or the policy of ROW-95 and ROW-96.
- The TUI.

## Technical notes

- Manager dependencies (from ROW-96): `FactoryDependencies.workerHosts?: () => Promise<readonly WorkerHostView[]>` and `hostConnection?: (host: string) => Promise<HostConnection>` in `src/services/factory-manager/manager-state.ts`. `WorkerHostView` is in `src/services/factory-manager/host-slots.ts` (states `connected`, `disconnected`, `not-ready`, `wrong-version`). `HostConnection` is in `src/services/remote-executor/remote-types.ts`.
- The manager calls `workerHosts()` at the start (`recoverAndConfigure`), at each supervisor turn (`refreshWorkerHosts` in `supervisor-steps.ts`) and at each placement (`worker-placement.ts`). Thus a call must be fast and must not run SSH in the foreground.
- `hostConnection` is called at each launch and at each scan sync of a host with an active remote Thread (`remote-dispatch.ts`).
- `ensureHostVersion` can run an install of up to 10 minutes (`DEFAULT_INSTALL_TIMEOUT_MS`). This is why the check runs in the background.
- `listHosts`, `hostProjectFor` and the rc readers use `ServiceContext` for the home folder (`rcPath`). Use the context of the daemon (`run.ctx`).
- Never write `~/.rowblyrc.json` in this service. The service only reads it. (Do not record `lastCheck` from the background check.)
- The service does not import `commander`, `ink` or `react`, and does not print.
- **Base branch.** On 2026-11-16 the worktree was at `b419a4da`, which does not have the merge of ROW-96 (`50c2da9e`, PR #292). Merge or rebase onto `origin/main` before the work starts. The files of ROW-96 (`remote-dispatch.ts`, `src/services/remote-executor/`) are not in the worktree before that.

## Assumptions

- The new code is a new service `worker-hosts/`, not a part of `factory-manager/`. Reason: the manager gets its hosts as dependencies by design (ROW-96), and the registry and SSH code stay out of the manager.
- The check runs in the background, with a 60-second interval, and a host without a completed check is `not-ready`. Reason: the manager calls `workerHosts()` often, and an install can take minutes. ROW-97 replaces the interval with the heartbeat.
- `ensureHostVersion` runs at each check of a host, before `quickHostCheck`, not only before the first launch. Reason: the Spec says "On each connection, the main machine compares the versions", and `quickHostCheck` makes a host with a different version not ready, so a host would otherwise never get its first launch. `ensureHostVersion` does not install when the version is correct.
- `hostConnection` also serves a host that is off. Reason: the Spec says that the host setting controls new work only; active remote Threads must complete and sync.
- The service does not record `lastCheck` in `~/.rowblyrc.json`. Reason: the safety rules limit writes to that file, and the daemon is not a front end of `rowbly host check`.
- The SSH transport has no close operation. The source does not close transports at the stop of the daemon. Reason: `HostTransport` has no `close`; SSH connection reuse ends by itself.
