## Goal

Each commit of the TUI measures too many rows. `useScrollFocus` (`src/tui/components/scroll-focus.ts:9`) calls Ink's `useBoxMetrics` in each `SelectionRow`, `SelectListRow` and `FieldRow`. That hook (Ink 8.0.0, `build/hooks/use-box-metrics.js`) runs an effect after each render of the row, and it also adds a root layout listener that runs after each commit. Both call `measureElement`. Thus each commit lays out the full tree and then measures each mounted row. In the production-mode profile, Ink's output renderer, Yoga and `string-width` took 2.6 s of a 12 s session.

The result for the user: the TUI does less work on each key press, and only the focused row is measured. The focused row continues to scroll into its viewport.

## Scope

In scope:

- Change `src/tui/components/scroll-focus.ts` so that only a row with `focused === true` measures its box. A row that is not focused does not call `useBoxMetrics` and does not add a layout listener.
- Keep the callers `SelectionRow`, `SelectListRow` and `FieldRow` working. Change them only if the new API needs it.
- Keep the behaviour of `useScrollFocus`: the active row scrolls into its viewport after the first layout, and again when the focus moves.
- Do a manual check of the story list (board), the select list, the forms (`Form`, `FormModal`), the thread lists and the settings sections.
- Update the `useScrollFocus` row in `.agents/skills/rowbly-tui-design/SKILL.md` if the API changes.

Not in scope:

- The mouse hit test in `src/tui/hooks/mouse.ts`. ROW-135 has that work.
- The `useBoxMetrics` call of `ScrollBody` (`src/tui/components/scroll-body/scroll-body.tsx:72`). It is one call for each viewport, not for each row.
- The full profile after all performance Stories. ROW-137 has that work.

## Technical notes

- Current code:
  ```ts
  export function useScrollFocus(ref, focused) {
    const reveal = useContext(ScrollFocusContext);
    const { hasMeasured } = useBoxMetrics(ref);
    useLayoutEffect(() => { if (focused && hasMeasured && ref.current) reveal?.(ref.current); }, [focused, ref, reveal, hasMeasured]);
  }
  ```
  `hasMeasured` is the only value that is used. It delays the reveal until Ink has a layout for the node.
- A hook cannot call `useBoxMetrics` on a condition (rules of hooks), and Ink has no option to turn it off. Ink does not export `addLayoutListener` or `RootNodeContext`. Recommended solution: move the measure into a small component, for example `<ScrollFocus target={ref} />`, that the row renders only when it is focused. That component calls `useBoxMetrics(target)` and does the reveal in `useLayoutEffect`. It renders `null`. Because only one row is focused in each list, only one root layout listener exists for each list.
- A different solution is acceptable if it agrees with the acceptance criteria, for example a hook that uses `useLayoutEffect` and a check of `ref.current?.yogaNode` only when `focused` is true.
- `ScrollBody` gives `reveal` through `ScrollFocusContext`. `reveal` calls `measureElement` on the node and the viewport only when it is called. Do not change it.
- Callers of `useScrollFocus`: `src/tui/components/selection-row/selection-row.tsx:36`, `src/tui/components/select-list-row/select-list-row.tsx:24`, `src/tui/components/field-row/field-row.tsx:43`. Screens that use these rows include `src/tui/screens/stories/`, `src/tui/screens/threads/`, `src/tui/screens/settings/`, `src/tui/screens/factory/` and `src/tui/shell/story-finder/`.
- Read the `rowbly-tui-design` and `rowbly-code-style` skills before the change. Do not add tests in `src/tui/` (see `docs/architecture/testing.md`).
