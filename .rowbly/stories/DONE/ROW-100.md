## Goal

The factory status shows the connection of each worker host and of each remote Thread. A person can see from `status.json`, `rowbly factory status --json`, `rowbly thread` and `rowbly status` that a host is offline, when the main machine had its last contact with the host, and which remote Threads have lost their connection. The status read never opens SSH and never loads Pi.

Read the Spec `remote-worker-hosts`, section "Status and TUI".

## Scope

In scope:

- **Host facts in the `hosts` list.** `status.json` and `rowbly factory status --json` already have a `hosts` list (`id`, `state`, `max`, `used`, `free`, from `managerSlots`). Add `lastSeenAt` (ISO text) and `latencyMs` (number) from the heartbeat facts (`ManagerState.hostHealth`) of each worker host, when the heartbeat has them. The `state` is the heartbeat state (`connected`, `degraded`, `disconnected`, `version-mismatch`, `auth-failed`) or `not-ready` from the list of worker hosts. `local` has no `lastSeenAt` and no `latencyMs`. Keep the existing field names `max` and `used` (the TUI and the docs use them).
- **The attention entry `host:<id>`.** When the heartbeat gives a worker host the state `disconnected`, `version-mismatch` or `auth-failed`, the manager sets the attention entry `host:<id>`. Its text gives the host, the state and the last contact time (or `never`). When the heartbeat gives the host the state `connected` or `degraded` again, the manager removes the entry.
- **`connection lost` for a remote Thread.** A remote Thread is a Thread whose `host` is not `local` and whose status is `running` or `pending`. When the `hosts` list of the factory status gives its host a state other than `connected` or `degraded`, or does not have its host, the Thread has a lost connection. Then:
  - `rowbly thread list` shows `connection lost (last contact <duration> ago)` at the end of its line, or `connection lost (no contact)` without `lastSeenAt`.
  - `rowbly thread show` and `rowbly thread list --json` give a `connection` field for that Thread: `{ "state": "lost", "host": <id>, "hostState": <state>, "lastSeenAt"?: <ISO text> }`. A Thread without a lost connection has no `connection` field.
  - `rowbly status` shows one line for each such Thread under the Threads line, with the Thread ID, the Story ID, the host and the time since the last contact. `rowbly status --json` gives the same facts in a `connectionLost` list of `ProjectStatus`.
- **The `connectivity` field** of the provider in `status.json` stays as it is.
- Documentation in STE: the new host fields and the `host:<id>` entry in `docs/architecture/native-factory/README.md` (Placement, Status) and `runtime-and-locks.md` (`status.json`), and the `connection lost` output in `docs/architecture/cli.md`.

Not in scope:

- The TUI (Factory view, `▶` marker, Threads host column, Settings). ROW-102 adds it.
- The session mirror (ROW-101), the restart recovery (ROW-117), abandoned Threads (ROW-99), inbound updates (ROW-98) and the SSH transport in the daemon (ROW-116).
- A change of the heartbeat state function or its limits (ROW-97).

## Assumptions

- The attention entry `host:<id>` is set for `disconnected`, `version-mismatch` and `auth-failed`, not for `degraded`. Reason: "stays disconnected" in the Spec is the state after three failed heartbeats; `version-mismatch` and `auth-failed` also do not heal without a person, and `degraded` is a short state that can heal.
- The entry goes away when the host is `connected` or `degraded` again. Reason: both states come only from an answered heartbeat (or fewer failures than the limit), so the host is reachable.
- A remote Thread has a lost connection when its host is not `connected` or `degraded`, or is not in the `hosts` list. Reason: `degraded` hosts still answer; a host that is not in the list cannot be reached.
- Without a running factory (no `hosts` list in the status), no Thread shows `connection lost`. Reason: the status read must not open SSH, and without the daemon there are no heartbeat facts. ROW-117 handles remote runs after a daemon restart.
- `rowbly thread` means the `thread list` and `thread show` subcommands. Reason: they are the subcommands that show the status of a Thread.
- The latency field is `latencyMs` and the slot fields stay `max` and `used`. Reason: the names agree with `HostHealth` and with the existing `hosts` entries.
- The `connectionLost` list of `rowbly status --json` is absent when no Thread lost its connection. Reason: the output without worker hosts must not change.
- A host that is not in the `hosts` list gives `hostState: "unknown"`. Reason: the field must have a value, and the state of the host is not known.
- The status read uses the `hosts` list only when the factory status has a live owner. Reason: a stale `status.json` of a stopped factory must not show `connection lost`.
- The supervisor digest keeps the `hosts` list without `lastSeenAt` and `latencyMs`. Reason: these values change at each heartbeat, and a change of the digest wakes the supervisor.
