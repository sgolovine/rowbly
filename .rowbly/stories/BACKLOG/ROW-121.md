Read the Spec `deterministic-factory`.

## Goal

When the provider of the worker model is paused, the manager starts the worker with the next model in a fallback list. The supervisor does not select a different provider.

## Now

`workerModelFor` in `src/services/factory-manager/worker-reservation.ts` selects the Story or Stage override, then the model from the supervisor, then `factory.workerModel`. `assertWorkerModel` refuses a model whose provider is paused (`Worker provider is paused`). The supervisor prompt tells the model to select a different provider.

## Scope

In scope:

- A new setting `factory.fallbackWorkerModels`: an ordered list of model choices.
- The manager first selects the model as now. If the provider of that model is paused, it selects the first model of the list whose provider is not paused.
- If all providers are paused, the policy skips the Story with the reason `provider paused`. The status and `factory_snapshot` show this reason.
- A resumed Thread keeps its model. Network resume does not change.
- CLI options to set and clear the list in `rowbly factory configure`.
- Tests of the selection, and the docs of the factory settings.

Not in scope:

- A TUI control for the list.

## Acceptance criteria

- With the provider of `factory.workerModel` paused and a fallback model of a different provider, a new worker starts with the fallback model.
- With all providers paused, no worker starts and the Story shows `provider paused`.
