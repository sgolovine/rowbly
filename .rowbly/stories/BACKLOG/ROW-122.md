Read the Spec `deterministic-factory`.

## Goal

When a worker reports a problem, the manager shows it to the user as an attention entry. The supervisor does not read worker summaries to find problems.

## Now

The worker tool `report_result` (`src/services/factory-worker/factory-worker.ts`) records `outcome`, `summary`, `blockers` and `problems`. Only the supervisor reads them, and it calls `raise_attention` when it thinks that a person must act. Examples from this Project: a flaky CI suite, a merge race, and a manual check of the TUI layout.

## Scope

In scope:

- When a worker Thread ends with one or more `blockers` or `problems`, the manager sets the attention entry `worker:<story-id>`. The text has the Story, the Stage, the Thread ID and the first items, in the limits of the other attention entries.
- When a worker Thread fails, the manager sets the same entry with the error. A failure of the connectivity type does not set it, because network resume handles it.
- The manager removes the entry when the Story leaves the Stage, when a later Thread of the Story ends without blockers, problems or failure, or when the Story is deleted.
- The same rules apply to a remote worker Thread.
- Tests of the manager, and the docs of the attention entries.

Not in scope:

- A change to the fields of `report_result`.
- New TUI views. The TUI shows the entry like all other attention entries.

## Acceptance criteria

- A worker that reports a blocker makes an attention entry for its Story.
- The entry goes away after the Story moves to the next Stage.
