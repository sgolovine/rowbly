Read the Spec `deterministic-factory`.

## Goal

The word "supervisor" no longer appears where a user can see it: the settings, the CLI, the TUI, the prompts and the docs.

## Scope

In scope:

- Settings: remove `factory.supervisorModel`. A config that still has the key stays valid. `rowbly doctor` shows a warning, and `--fix` removes the key.
- CLI: remove `--supervisor` and `--supervisor-thinking` of `rowbly factory configure`. `rowbly prompt get supervisor` and `rowbly prompt set supervisor` give a usage error with a hint.
- Prompts: delete `src/config/prompts/SUPERVISOR.md`. `rowbly doctor` does not show a warning for a missing `.rowbly/prompts/SUPERVISOR.md`. When the file exists, doctor tells the user that Rowbly does not use it. Rowbly never deletes this user file.
- `rowbly init` and the onboarding steps do not make a Supervisor prompt.
- TUI: remove the supervisor conversation of the Factory modal and the supervisor model in the AI settings. The Thread history still shows old supervisor Threads.
- Docs: update `docs/architecture/` (the overview, the native factory pages and `prompts.md`), the Prompts section of `AGENTS.md`, and `skills/rowbly-reference.md`. Copy the reference to each `skills/<name>/references/rowbly-reference.md`.
- Update the tests of the changed services.

Not in scope:

- A change to the files of this Project in `.rowbly/prompts/`. The user deletes them.

## Acceptance criteria

- `grep -ri supervisor src/ skills/ docs/` finds only the support for old supervisor Threads and old config keys.
- `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.
