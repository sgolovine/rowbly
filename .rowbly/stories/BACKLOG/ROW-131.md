## Problem
`src/tui/screens/stories/story-list-rows.ts:43` calls `waitingFor` for each Story, and `src/services/story-dependency/story-dependency.ts:153` builds a new Map of all Stories on each call, so the row build is O(n²). `src/tui/shell/shell/shell-view.ts:75` recomputes the rows with no `useMemo`, so each keypress pays for it. The profile showed 128 ms in `storyListRows` in a short session with 125 Stories.

## Fix
- Add a form of `waitingFor` that takes a prepared index (a `byId` Map or a graph object), and build the index once in `storyListRows`.
- Keep the public `waitingFor`, `isBlocked` and `searchStories` behaviour; `story-read.ts:238` can use the same index.
- Memoize `shellView` in `use-shell.ts` on `[stories, stages, collapsed, stage, ...]`.
- Update `story-dependency.test.ts` and the row tests.

## Done when
`storyListRows` builds one index per call, and an arrow key does not rebuild the rows.
