## Goal

The dependency picker of the Story form is slow on a large board. `dependencyCandidates` (`src/services/story-dependency/story-dependency.ts`) calls `dependencyError` for each candidate Story. Each call builds a new graph, a new set of known IDs and a cycle search, so the candidate list is O(n³) in the worst case. `dependencyChoices` (`src/tui/screens/stories/story-dependency-view.ts`) calls `dependencyCandidates`, and `edit-story-form.tsx` and `new-story-form.tsx` call `dependencyChoices` in each render. The profile showed 170 ms for each open of the edit form on a board with 125 Stories.

The result: the picker candidates are computed in linear time (O(Stories + dependency edges)), and only one time for each change of the Stories or of the Story.

## Scope

In scope:

- A new implementation of `dependencyCandidates` that builds the graph one time and tests each candidate against it in constant time.
- `useMemo` for the choices of the `Depends on` field in `edit-story-form.tsx` and `new-story-form.tsx`.
- Tests in `src/services/story-dependency/story-dependency.test.ts`.

Not in scope:

- `dependencyError` and its callers (`src/services/story/story-dependencies.ts`). Its signature and results do not change.
- `dependencyLists` and `dependencyItem` in `story-dependency-view.ts`. They look up only the IDs of one Story.
- The new profile of the TUI. ROW-137 does this work.

## Acceptance criteria

- [ ] `dependencyCandidates` does not call `dependencyError` for each candidate. It calls `dependencyError` (or an equivalent check) a maximum of one time for the current `dependsOn` list, and does a maximum of one graph search for each call (`grep -n "dependencyError(stories, id, \[...dependsOn" src/services/story-dependency/story-dependency.ts` finds nothing).

- [ ] A new unit test shows that when the current `dependsOn` list already has a problem (an unknown ID, or a cycle through `id`), the result is the same as the old rule (an empty list).

## Technical notes

- `src/services/story-dependency/story-dependency.ts`:
  - The old rule: a candidate `C` is valid when `dependencyError(stories, id, [...dependsOn, C])` is `undefined`.
  - An equivalent rule in linear time:
    1. If `dependencyError(stories, id, dependsOn)` is not `undefined`, no candidate is valid. The problem of the current list (an unknown ID, an ID of a different Project, a self reference or a cycle through `id`) stays when the list gets one more ID.
    2. Build the reverse graph one time: for each Story `S` and each `D` in `S.dependsOn`, an edge `D → S`. Ignore the edges out of `id` (they are `dependsOn`, and a path stops when it gets to `id`).
    3. Do one breadth-first search from `id` on the reverse graph. The result is the set of the Stories that have a path to `id`. A candidate in this set makes a cycle.
    4. A candidate `C` is valid when `C !== id`, `C` is not in `dependsOn`, `C` is not in the set of step 3, and `keyOf(C)` is `undefined` or the same as `keyOf(id)` (the `otherProject` rule of `idProblem`).
  - Keep the order of `stories` in the result. Keep the `id === undefined` path (a new Story) as it is.
  - The upstream Story ROW-131 added `dependencyIndex` (`byId`). Use it if it helps (for example, for the known IDs), but a reverse adjacency Map is also necessary for step 3.
  - Obey the strict style (`.agents/skills/rowbly-code-style/SKILL.md`): no `for`/`while` loops if the style forbids them, `readonly` types, and a recursive search like `searchLevel` is acceptable.
- `src/tui/screens/stories/edit-story-form/edit-story-form.tsx` (about line 161) and `src/tui/screens/stories/new-story-form/new-story-form.tsx` (about line 127): add `useMemo` from `react`. Call the hooks before the `return`, in the same order on each render.
- `story-dependency-view.ts` needs no change. `dependencyChoices` keeps its labels and search text for all Stories.
- Do not write tests for the TUI (AGENTS.md).

## Assumptions

- The "under 10 ms in dependency code" condition of the author is not a unit test, because a time limit in a test is not stable on CI. The linear algorithm and the 125-Story test replace it, and ROW-137 measures the time in the profile. Reason: ROW-137 is the Story that profiles the TUI after the performance fixes.
- The edit form keeps the saved `story.dependsOn` as the input of `dependencyChoices`, not the value that the user changes in the form. Reason: this is the current behaviour, and the author asked only for a faster computation.
- The `useMemo` key of the edit form uses `story.dependsOn` (the array reference). Reason: the author gave the key `[stories, story.id, dependsOn]`, and the board gives a new Story object only when the Story changes.
