## Goal

The Story list of the TUI is slow on a large board. `storyListRows` (`src/tui/screens/stories/story-list-rows.ts:43`) calls `waitingFor` for each Story. `waitingFor` (`src/services/story-dependency/story-dependency.ts:153`) builds a new Map of all Stories on each call, so the row build is O(n²). `shellView` (`src/tui/shell/shell/shell-view.ts:75`) builds the rows again on each render, and `useShell` (`src/tui/shell/shell/use-shell.ts:44`) calls `shellView` with no memoization, so each keypress pays for the build. The profile showed 128 ms in `storyListRows` in a short session with 125 Stories.

The result: the rows build in linear time, and a key that only moves the cursor does not build the rows again.

## Scope

In scope:

- A dependency index in `story-dependency.ts` that is built one time, and a form of `waitingFor` (and of `isBlocked`) that uses the index.
- `storyListRows` builds one index for each call.
- `searchStories` (`matchesDependency` in `src/services/story/story-read.ts:319`) builds one index for each search, not one for each Story.
- `getStoryDetails` (`story-read.ts:238`) can use the same index. This is optional, because it makes only one call.
- Memoization of the rows in `use-shell.ts`, so that a cursor move does not build the rows again.
- Tests in `story-dependency.test.ts`.

Not in scope:

- `dependencyCandidates` and the dependency picker. ROW-132 does this work, and it uses the index of this Story.
- The callers in `src/services/factory-manager/` and `src/services/factory-policy/`. They can change to the index later; they keep the public `waitingFor`.
- The new profile of the TUI. ROW-137 does this work.

## Acceptance criteria

- [ ] `story-dependency.ts` exports a function that builds a dependency index (for example `dependencyIndex(stories)`, with a `byId` Map), and a form of `waitingFor` that takes the index. A unit test in `story-dependency.test.ts` shows that the indexed form gives the same result as `waitingFor` for the existing fixtures (a waiting upstream Story, a complete upstream Story, an unknown upstream ID, an unknown Story ID).
- [ ] The public signatures and results of `waitingFor`, `isBlocked` and `searchStories` do not change. The existing tests of these functions pass with no change to their expectations.
- [ ] `storyListRows` builds the index one time for each call, and does not call the public `waitingFor` (`grep -n "waitingFor(all" src/tui/screens/stories/story-list-rows.ts` finds nothing).
- [ ] `matchesDependency` in `story-read.ts` does not build a new Map for each Story: `searchStories` builds the index one time for each search.
- [ ] `use-shell.ts` computes the Story list rows in a `useMemo` with dependencies on only the board (`data.data`), `stageKey` and `collapsed`. `shellView` gets these rows as input and does not call `storyListRows`. A change of `selectedId`, `marked`, `anchor`, `overlay` or `pane` does not build the rows again. A person can examine this in the code.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

## Technical notes

- `src/services/story-dependency/story-dependency.ts`: add a type for the index (for example `DependencyIndex` with `byId: ReadonlyMap<string, DependencyStory>`) and a builder. Change the private `isWaiting` to use the index. Implement the public `waitingFor` as "build the index, then call the indexed form", so that its behaviour stays the same. Obey the strict style (`.agents/skills/rowbly-code-style/SKILL.md`).
- `src/tui/screens/stories/story-list-rows.ts`: build the index from `all` in `storyListRows` and pass it to `storyRow` and `sectionRows` in place of `all`.
- `src/tui/shell/shell/shell-view.ts`: move the row build to a separate exported function (for example `shellRows(board, stageKey, collapsed)`) and add `rows` to `ShellViewInput`. Keep `visibleStories` and the `stage ? undefined : collapsed` rule in that function.
- `src/tui/shell/shell/use-shell.ts`: call the row function in `useMemo(..., [data.data, stageKey, collapsed])`, then pass the rows to `shellView`. `data.data` and `collapsed` come from `useState`, so their references are stable between renders.
- The rest of `shellView` (cursor, marks, flags) is cheap and can run on each render.
- ROW-132 will use the index of this Story. Give the index a name and a shape that a graph search can also use (the `dependsOn` of each Story is on the `DependencyStory` in `byId`).

## Assumptions

- The Story asks to "update the row tests", but no test exists for `story-list-rows.ts` or `shell-view.ts`, and `AGENTS.md` says not to write tests for the TUI. The service test in `story-dependency.test.ts` covers the new index. A developer can add a pure-function test for `storyListRows` if it is easy, but it is not required. Reason: smallest scope that obeys the repository rules.
- The Story asks to memoize `shellView` on `[stories, stages, collapsed, stage, ...]`. A memo of the full `shellView` would run again on each arrow key, because `selectedId` changes. So only the rows get the memo. Reason: the "Done when" condition says that an arrow key must not build the rows again.
- `searchStories` gets the index too. Reason: the Story says to keep its behaviour and `isBlocked` in it has the same O(n²) cost; the change is small.
- The factory-manager and factory-policy callers of `waitingFor` stay unchanged. Reason: they are not in the TUI hot path, and the Story does not name them.
