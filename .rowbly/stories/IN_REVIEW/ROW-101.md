## Goal

Peek, `rowbly thread log` and `inspect_worker` work for remote Threads, also while the host is offline. They show the last session lines that arrived.

Read the Spec `remote-worker-hosts`, section "Session mirror".

The host channel already sends `session` frames (ROW-111). This Story adds the mirror on the main machine, and the read of missing lines from the host.

## Scope

In scope:

- **The mirror.** The main machine keeps a byte-exact copy of the complete lines of the session file of each remote Thread. The mirror path is the `session.file` value of the Thread (`sessions/<thread-id>/<name>.jsonl`) below the local runtime folder (`runtime/sessions/<thread-id>/`). The Thread record already has this value from the `session` field of the `run` frame. Thus the `conversation/` service, `rowbly thread log`, `inspect_worker` and Peek read the mirror with no change of their read code.
- **Live lines.** The remote executor takes each `session` frame of the `host attach` channel and adds its lines to the mirror. A line that arrives two times is in the mirror one time.
- **Missing lines.** The main machine reads the missing bytes from the host with a new hidden bytes command, `rowbly host session-bytes <project-id>`. It does this:
  - when a frame starts after the end of the mirror (a gap, for example after a reconnect),
  - for a gap frame of an oversize line (`lines: []`),
  - after a reconnect, for each active remote run that has a session,
  - when a run ends on the host, before the manager completes the Thread.
- Tests and documentation (see "Acceptance criteria").

Not in scope:

- A change to the Pi session format, to `run.json` or to the `session` frame of ROW-111.
- A frame from the main machine that gives its mirror offset to the host.
- The adoption of remote runs after a restart of the daemon (ROW-117). ROW-117 can call the catch-up function of this Story for each adopted run.
- The removal of old mirror files.
- The `connection lost` notice in the status or the TUI (ROW-100, ROW-102).
- A change to the TUI.

## Technical notes

- **Base branch.** At the time of refinement, the worktree is on a detached `HEAD` (`97857930`) without the merge of ROW-97 (PR #296, `08369fdb`). Make the branch `story/ROW-101`, then merge `origin/main` first, so that `remote-reconnect.ts`, `remote-commands.ts`, `remote-sync.ts` and the heartbeat exist.
- **The frame.** `SessionFrame` is in `src/services/host-agent/host-session-lines.ts`: `{ type: "session", threadId, file, offset, end, lines }`. `offset` is the byte offset of the first line, `end` is after the newline of the last line. A frame with `lines: []` marks an oversize line. When a channel opens, the host starts each session file that exists at its current size. Thus a reconnect always gives a gap when the host wrote lines while it was offline.
- **Dispatch.** In `dispatchFrame` of `src/services/remote-executor/remote-channel.ts`, give a `session` frame to the mirror of its Thread only when the Thread is an active run of the same host. Ignore a frame of a different Thread or host.
- **New module.** Put the mirror in `src/services/remote-executor/session-mirror.ts` (with a test next to it). Keep one chain of writes for each Thread in the `Store` of the executor (for example a `mirrors` map in `RemoteState`), so that a live frame and a catch-up never write at the same time. Keep pure functions (for example the decision for one frame against the mirror size) apart from the file I/O, and test them.
- **Rules for one frame**, with `size` the current size of the mirror file (0 when it does not exist):
  - `end <= size`: skip the frame.
  - `offset <= size < end`: add only the bytes after `size`. Encode the lines as UTF-8, each with `\n`. Byte offsets, not character offsets.
  - `offset > size`, or a frame with `lines: []`: do a catch-up from `size`, then apply the frame again with the rules above. If the catch-up fails, drop the frame. The mirror never has a gap.
  - When `frame.file` is different from the file of the mirror of the Thread, write the new file. Do not delete the old file.
- **Catch-up.** Read from the host with `transport.bytes([rowbly, "host", "session-bytes", projectId], { threadId, file, offset }, { limit })` in a loop, until the answer is empty. Append each answer to the mirror. Use `targetOf(env, host)` of `remote-commands.ts` for the connection. Call it: in `runReconnect` of `remote-reconnect.ts` after `reopenLink`, for each open run whose `sent.session` is set; and before the end event of a run (in `remote-run.ts`, where `runEnd` gives the completion or the failure). A catch-up failure does not stop the reconnect, the outbox sync or the end of the run.
- **Host command.** Add `rowbly host session-bytes <project-id>` in `src/commands/host/host-run-commands.ts`, with a service function in `src/services/host-agent/` (for example `host-session-bytes.ts`, with a test). Input on stdin: `{ threadId, file, offset }`, read with `readBoundedInput` and `parseJsonInput`. Output: the raw bytes on stdout (the same form as `host blob`). Rules:
  - `file` must start with `sessions/<threadId>/`, end with `.jsonl`, and must not be absolute or have a `..` part. Resolve it below `hostAgentPaths(projectId).runtime` with the same checks as `readSessionChunk` in `host-session-lines.ts`.
  - Read with a `FileHandle` from `offset`, a maximum of 4 MiB (`MAX_SESSION_READ_BYTES`, export it).
  - Give the bytes up to and including the last newline of the window. When the window has no newline and the file continues after the window, give the full window (a part of a long line). When the window reaches the end of the file, a part line at the end waits.
  - An `offset` at or after the end of the file gives no bytes. A missing file gives a `NotFoundError`.
- **Mirror files.** Write through `checkRuntimeDir(paths, "sessions")` and `runtimeChild` of `src/services/runtime-files/runtime-files.ts`. Create the Thread folder with mode 0700. Open the mirror file with mode 0600 and append. Do not write the mirror atomically with a full copy for each frame, because a session can be many MiB. A mirror write takes no Project write lock and no state lock.
- **The read side.** `openConversation` (`src/services/conversation/conversation.ts`) resolves `thread.session.file` with `runtimePath(paths, file)`, and `checkSessionIn` (`src/services/thread/thread-files.ts`) accepts `sessions/<thread-id>/*.jsonl`. Thus the read side needs no code change. `inspectWorker` in `src/services/factory-manager/supervisor-tools.ts` uses `getThreadLog`. The session scanner indexes only complete lines.
- **Protocol.** The `session` frame does not change. `session-bytes` is a new command of the same Rowbly version, and the handshake compares the Rowbly versions. Do not change `HOST_PROTOCOL_VERSION`.
- **Safety.** Do not load Pi in the mirror, the executor or the host command. Never take the Project write lock while you hold the state lock. Services do not import `commander`, `ink` or `react`, and do not print. Follow the `rowbly-code-style` skill. Use `.js` extensions in relative imports.

## Assumptions

- The mirror uses the same relative path as the `session.file` of the host, below the local runtime folder. Reason: the Thread record already has this value, and the conversation service, `thread log`, `inspect_worker` and Peek then read the mirror with no change.
- The main machine reads missing bytes with a new hidden bytes command `rowbly host session-bytes`. Reason: ROW-111 left the read of missing lines and gaps to this Story, and the channel sends only the lines after it opened.
- The mirror never has a gap. A frame after a gap that the main machine cannot fill is dropped, and a later catch-up gets the bytes. Reason: a mirror with a gap gives wrong byte offsets for all later frames.
- A frame that overlaps the mirror adds only the bytes after the mirror end. The main machine does not compare the overlapped bytes. Reason: Pi session files are append-only in normal use, and a resume continues the same file. A file that the host truncates or replaces is not in scope.
- The catch-up runs after a reconnect, for a gap frame, and at the end of a run. Reason: the Spec says that the main machine gets the missing lines after a reconnect, and the last lines of a run must be in the mirror when the Thread completes.
- A catch-up failure does not fail the run or the reconnect. Reason: the mirror is for Peek and `inspect_worker` only. The result and the outbox of the run do not depend on it.
- `HOST_PROTOCOL_VERSION` does not change. Reason: no frame changes, and both machines run the same Rowbly version.
- The mirror files stay after the Thread ends. Reason: local session files also stay, and Peek of an old Thread must work.
