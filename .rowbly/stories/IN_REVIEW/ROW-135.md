## Goal

Each pointer move in the TUI does too much work. `src/tui/mouse.ts:8` (`MOUSE_ON`) turns on `?1003h`, so the terminal reports every pointer move. `dispatchMove` in `src/tui/hooks/mouse.ts:186-197` calls `hit()` two times for each move (one time in `dragOver` and one time in `hover`). `hitArea` (`:117-127`) calls `measureElement` on every registered target before it examines whether the target wants the event. `insideClip` (`:106-114`) also measures the clip viewport of a clipped target. All of this runs on the thread that handles keys and renders.

The result for the user: a pointer move measures only the targets that handle it, and each box is measured a maximum of one time for each layout commit. Clicks, drag and drop, pull (resize), hover and the wheel continue to operate as before.

## Scope

In scope:

- In `src/tui/hooks/mouse.ts`, examine `wants(target.handlers.current)` before any call to `measureElement` in `hitArea`. A target that does not want the event is not measured, and its clip viewport is not measured.
- Add a box cache to the mouse registry: a map from `DOMElement` to its measured box, for the target nodes and the clip viewport nodes. Each node is measured a maximum of one time until the cache is cleared.
- Clear the cache at each layout commit (see "Technical notes"), and when a target registers or unregisters.
- `dispatchMove` calls `hit()` a maximum of one time for each move when it is not pulling. Use one `wants` that accepts a drop target (`onDrop`) or a hover target (`onEnter` or `onLeave`), or compute one pass that gives both results. `dragOver` and `hover` use the result of that pass. The behaviour must stay the same: the drop target is the smallest box under the pointer with `onDrop`, and the hover target is the smallest box under the pointer with `onEnter` or `onLeave`. These can be two different targets.
- Update the `mouse.ts` rows in `docs/architecture/tui.md` if the API of the registry changes.

Not in scope:

- A change from `?1003h` to `?1002h`. `Button` (`src/tui/components/button/button.tsx:53`) uses `onEnter` and `onLeave` for hover, and hover needs all pointer moves. Keep `MOUSE_ON` and `MOUSE_OFF` as they are.
- The row measurement of `useScrollFocus`. ROW-127 did that work.
- The full profile after all performance Stories. ROW-137 has that work.
- A test file in `src/tui/`. See "Assumptions".

## Technical notes

- Files: `src/tui/hooks/mouse.ts` (registry, `hitArea`, `insideClip`, `hit`, `dispatchMove`, `dragOver`, `hover`, `useMouseSource`), `src/tui/terminal.ts` (`runFullScreen`, the `render` options), `src/tui/tui-providers.tsx` (creates the registry with `createMouseRegistry` and calls `useMouseSource`), `src/tui/mouse.ts` (`MouseStdin`, `MOUSE_ON`).
- Ink 8 does not export `addLayoutListener` or `RootNodeContext`, and the `exports` of the `ink` package block a deep import of `ink/build/dom.js`. Thus the TUI cannot add a root layout listener directly. Recommended solution: use the public `onRender` option of `render` (Ink calls it after each frame that it draws, also after a resize). In `runFullScreen`, pass `onRender: () => stdin?.mouse.emit("layout")`. In `useMouseSource`, also listen to `"layout"` on the source and call a new `registry.invalidate()` (or a similar name) that clears the box cache. Remove both listeners on unmount.
- Ink throttles `onRender` (30 fps by default). Between a commit and the next frame, the cache can hold the boxes of the frame that is on the screen. This is correct, because the user clicks on the frame that is on the screen.
- Keep the cache in the `Store` of the registry, or in a `WeakMap` that the registry owns. Obey the `Store` rules of the `rowbly-code-style` skill.
- `measureElement` gives `x`, `y`, `width` and `height` from the Yoga layout. A node without a layout gives a zero area. Cache that result too, so that a node without a layout is not measured again before the next commit.
- Read `.agents/skills/rowbly-code-style/SKILL.md` and `.agents/skills/rowbly-tui-design/SKILL.md` before the change.

## Assumptions

- No `mouse.test.ts` is added, and the original text asked to update it. Reason: no such file exists, and `docs/architecture/testing.md` says "Do not put a test in `src/tui/`" and "Do not write tests for the TUI". The measurement criterion is examined with a temporary counter in a real terminal, as in ROW-127.
- The cache is cleared from the `onRender` option of Ink, not from a root layout listener. Reason: Ink 8 does not export the root layout listener API. `onRender` is public and runs after each drawn frame.
- `?1003h` stays. Reason: `Button` uses hover (`onEnter`/`onLeave`), and the original text says to keep hover if the controls use it. A change of the mouse mode at run time is a larger change than this Story needs.
