## Goal

`StoryFinder` copies most of `SearchableSelectPicker`. Both keep query and cursor state, run `fuzzySearch` in a `useMemo`, clamp the selection, compute the same window of rows, reset the cursor when the query changes, and handle `esc` / `↑` / `↓` / `enter` with `useKeyCapture` and `useInput`. Both render a `TextInput`, an empty text, a slice of `SelectListRow` and a counter.

Make one generic `FuzzyPicker<T>` component that holds this shared logic. Then each of the two components becomes a thin wrapper. The user sees no change in behaviour. Expected saving: about 70 lines.

## Scope

In scope:

- A new generic component `FuzzyPicker<T>` in `src/tui/components/fuzzy-picker/` (`fuzzy-picker.tsx` and `index.ts`), exported from `src/tui/components/index.ts`.
- `SearchableSelectPicker` becomes a thin wrapper around `FuzzyPicker<string>`. Its props and its public export stay the same.
- `StoryFinder` becomes `Modal` + `FuzzyPicker<Story>`.
- Update the component table in `.agents/skills/rowbly-tui-design/SKILL.md` to list `FuzzyPicker`.

Not in scope:

- Changes to `SearchableSelect`, `SearchableMultiSelect`, `ModelPickerModal` or `story-overlays.tsx`. They keep their current use of `SearchableSelectPicker` and `StoryFinder`.
- Changes to `fuzzySearch` or `SelectListRow`.
- New features (for example, `ctrl+l` or wheel scroll in a component that does not have it now).
- TUI tests (AGENTS.md: do not write tests for the TUI).

## Technical notes

Files:

- `src/tui/shell/story-finder/story-finder.tsx` (134 lines). Used by `src/tui/shell/story-overlays/story-overlays.tsx`.
- `src/tui/components/searchable-select-picker/searchable-select-picker.tsx` (156 lines). Used by `searchable-select/searchable-select.tsx`, `searchable-multi-select/searchable-multi-select.tsx` and `screens/settings/model-picker-modal/model-picker-modal.tsx`.
- `src/tui/components/fuzzy-search.ts` (the search function).

Differences that `FuzzyPicker` must support through props:

| Behaviour | StoryFinder | SearchableSelectPicker |
| --- | --- | --- |
| Search fields and tie order | id, title, Stage label, description; `a.number - b.number` | value + search text or label; `localeCompare` numeric |
| Input prefix | `🔎 ` in `theme.accent` | none |
| Placeholder | `Find Stories…` | `Type to search…` |
| Input width | `body.width - 5` | `layout.width - 2` |
| Header line | count line `N Story/Stories[ · i/N]` | `Selected: …` (unless `hideSelected`) |
| Footer counter | none | `i/N` below the list if the list is longer than the window |
| Row limit | `min(10, body.height - 6)` from `modalSize(useLayout(), { footer: true })` | `min(8, layout.height - 5)` |
| Wheel scroll | yes, `useMouse` + `WHEEL_LINES` on the list | no |
| `ctrl+l` clears the query | no | yes |
| `enter` with `ctrl` | picks | ignored |
| Initial query / cursor | `""` / 0 | `initialQuery` / index of `value` if the query is empty |
| Empty text | depends on whether there are Stories | depends on whether there are options |

Suggested props for `FuzzyPicker<T>`: `items`, `searchText(item)`, `compare(a, b)`, `itemKey(item)`, `renderItem(item)`, `onSelect(item)`, `onCancel()`, `initialQuery?`, `initialCursor?`, `limit` (or a function of the selected row and results count), `inputWidth`, `placeholder`, `prefix?`, `header?(state)`, `footer?(state)`, `emptyText`, `wheel?`, `clearKey?`. The header and footer slots need `results.length`, `selected` and `limit`, so they can be functions of that state. The developer can change these names.

## Assumptions

- `FuzzyPicker` goes in `src/tui/components/fuzzy-picker/`, one folder per component, as the other components do. Reason: the folder pattern of `src/tui/components/`.
- Each component keeps its current keys and look. `ctrl+l` and wheel scroll are options of `FuzzyPicker`, not new features of the other component. Reason: the Story is a refactor with no behaviour change; this is the smallest scope.
- A line count less than before is the measurable form of "about 70 lines saved". Reason: an exact number depends on the code style and is not a useful test.
- `enter` with `ctrl` can stay ignored in the picker and accepted in the finder through an option, or both can ignore it. The developer selects. Reason: no known key binding uses `ctrl+enter` in the finder.
