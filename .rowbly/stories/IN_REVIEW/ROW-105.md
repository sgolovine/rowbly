## Goal

Document the remote worker hosts for contributors and for users. The upstream Stories (ROW-82 to ROW-104) already wrote detailed pages for each part: `host-transport.md`, `host-install.md`, `host-check.md`, `host-agent.md`, the Placement, Dispatch, Session mirror, Inbound updates, Disconnects and Abandoned Threads sections of `docs/architecture/native-factory/README.md`, the outbox sections of `storage.md`, the `host` and `thread held` parts of `cli.md`, and the Hosts parts of `tui.md`. This Story adds the missing overview page and the user guide, removes old text that says that more than one machine is not supported, and adds the links between the pages.

Read the Spec `remote-worker-hosts`. Write all Markdown in STE (`docs/contributing/documentation-language.md`).

## Scope

In scope:

1. A new page `docs/architecture/native-factory/remote-hosts.md`. It is the start page for a contributor. It has these parts:
   - The terms of the Spec: main machine, worker host, host agent, copy, outbox, inbound update.
   - A short flow of one remote worker: placement, `host prepare` with the copy, launch in the host agent, the outbox and its apply, inbound updates, the session mirror, the end of the Thread (`waiting for host sync`), disconnect and reconnect, abandoned Threads and held entries.
   - The limits of version 1 (from "Not in version 1" of the Spec, and the remote-worker refusals: a new Story, Stage, Spec or a config change gives `CONFLICT` "A remote worker cannot …").
   - A table that tells which page and which module in `src/services/` has the details of each part. Do not copy the details. Link to the existing pages and sections.
2. `docs/architecture/native-factory/README.md`:
   - Add a row for `remote-hosts.md` to "Map of the sub-pages", as the first of the host rows.
   - Add a link to `remote-hosts.md` at the start of the "Placement" section or of "Dispatch to a worker host".
   - Update "Prerequisites and limits": the main machine needs the current prerequisites. Each worker host needs Linux, Git, util-linux `flock`, Node 22.19.0 or later, SSH access with a key and without a password, and its own logins (Pi, `gh`, Git push and the Git identity). Change the line about hosts so that it says that the daemon ownership has no guarantee across machines, NFS, PID namespaces or copied runtime folders, and that worker hosts are supported only through the host agent.
3. `runtime-and-locks.md`: add a link to `remote-hosts.md`. Make sure that the file tree lists each file and folder that the code makes under `runtime/hosts/<host>/` (compare with `src/services/` modules that write there, for example `host-commands`, `inbound`, `outbox-apply`, held entries). State the lock rule of the outbox apply: it holds the Project write lock and not the state lock.
4. `recovery.md`: add a short paragraph near the top (or a "Remote Threads" summary) that a disconnect is not an interruption, that recovery does not mark remote runs interrupted, and that a remote Thread resumes only on its own host. Link to `remote-hosts.md`, "Adopt remote Threads at start" and "Abandoned Threads".
5. `docs/architecture/cli.md`: add a link to `remote-hosts.md` in the "Worker hosts" section. Make sure that `factory configure --placement`, `factory status` with `hosts`, and `thread held` have a link to their details.
6. `docs/architecture/tui.md`: add a link to `remote-hosts.md` near the Hosts list of the Factory view and the Hosts section of Settings.
7. `docs/architecture/storage.md`: add a link to `remote-hosts.md` in "Outbox of a remote worker" and in the `hosts` item of `~/.rowblyrc.json`.
8. `README.md` (the user guide):
   - In "Prerequisites", replace "Multi-host … are not supported" with text that agrees with item 2: worker hosts over SSH are supported, and shared runtime folders, NFS and copied runtime folders are not.
   - Add a section "Remote worker hosts" after "Factory controls" (or after "Stop, resume and recovery"). It has: the prerequisites of a worker host; `rowbly host add <id> --ssh <target> --max-workers <n>`; the logins on the host (`rowbly host login <id>`, then `gh auth login`, Git push access and the Git identity on the host, and the note that SSH agent forwarding is not sufficient); `rowbly host use <id> [--path <dir>]`; `rowbly host check <id>`; the placement setting (`rowbly factory configure --placement prefer-local|most-free|prefer-remote`, and Settings › Hosts in the TUI); what the user sees when a host disconnects (`connection lost`) and `rowbly thread held <id> --apply|--discard` for an abandoned Thread; `host update`, `host unuse` and `host remove`.
   - Add a "Worker hosts" row to the table of "Files and compatibility".
9. `skills/rowbly-reference.md`: in the Host section, add the placement setting (`rowbly factory configure --placement <policy>`) and a short note for an agent that runs as a remote worker: it writes to a copy, Story field changes, Stage moves and attachments go through the outbox, and a new Story, Stage, Spec or config change gives `CONFLICT`. Then copy the file to each `skills/<name>/references/rowbly-reference.md` (`develop`, `refine`, `review`).

Not in scope:

- Code changes.
- A change to the detailed text of the existing host pages, except to fix a fact that is wrong compared with the code.

## Assumptions

- The new page is an overview with links, not a copy of the detailed pages. Reason: the upstream Stories already documented each part in detail, and two copies of a fact can become different.
- The user guide goes in `README.md` as a new section, not in a separate file. Reason: the Story names `README.md`, and the other user topics are sections of that file.
- The `rowbly-reference.md` update is small: placement and the remote-worker rules. Reason: the reference already has a full Host section, and agents use the reference for board commands, not for factory operation.
- The acceptance criteria add `typecheck`, `test` and `build` to `pnpm lint`. Reason: AGENTS.md requires all four checks before a commit.
