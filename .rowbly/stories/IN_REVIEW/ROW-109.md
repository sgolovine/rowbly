Split from ROW-108. The goal of this part: attach a file that the user copied to the clipboard.

## Goal

A user copies a file in a file manager (for example Nautilus, Dolphin, Finder or Explorer). Then the user pushes the paste key in the TUI (`ctrl+v`, or `alt+v` on Windows) or runs `rowbly add-attachment <story> --from-clipboard`. Rowbly attaches that file to the Story, with its name and its bytes. Today the clipboard paths accept only a PNG image (`src/services/clipboard/clipboard.ts`).

An image of a different type on the clipboard (for example `image/jpeg` from `wl-paste`) also attaches.

ROW-108 (DONE, PR #283) lets a Story keep a file of any type from a file path. This Story uses that work.

## Scope

In scope:

- A clipboard read that finds a copied file (a list of file paths) on Linux Wayland, Linux X11, macOS and Windows.
- A clipboard read of image types other than PNG through `wl-paste` on Wayland: `image/jpeg`, `image/gif`, `image/webp`.
- One shared service function that gives the attachment from the clipboard. The CLI (`--from-clipboard`) and the TUI paste hook both use it.
- The error messages, hints, help text, key hint, toasts and documentation that say "PNG" or "image" for a clipboard paste.
- Tests for the clipboard service and the attachment service.

Not in scope:

- More than one copied file in one paste. See `## Assumptions`.
- A copied folder. It fails with an error.
- A file that is not local (a URI that does not start with `file://`).
- Other image types through `xclip`, `osascript` or PowerShell. On X11, macOS and Windows, the native binding continues to give the image as PNG.
- A preview of a file in the TUI.
- A change of the 10 MiB limit.
- Text on the clipboard (a terminal can paste text itself).

## Acceptance criteria

- [ ] On Wayland, when `wl-paste --list-types` includes `text/uri-list` and `wl-paste --type text/uri-list` gives `file:///tmp/a%20b/report.pdf`, the clipboard read gives the file `/tmp/a b/report.pdf`. A test with a mocked `execFile` examines this.
- [ ] On X11 (`DISPLAY` set, no `WAYLAND_DISPLAY`), when `xclip -selection clipboard -t TARGETS -o` includes `text/uri-list`, the read uses `xclip -selection clipboard -t text/uri-list -o`. A test examines this.
- [ ] On macOS (`process.platform === "darwin"`) the read uses `osascript`. On Windows (`win32`) the read uses `powershell` with `Get-Clipboard -Format FileDropList`. A test examines the command and its arguments for each platform.
- [ ] The URI-list parser ignores empty lines and lines that start with `#`, accepts `\r\n` and `\n`, decodes percent escapes with `fileURLToPath`, and ignores URIs that do not start with `file://`. Unit tests examine this.
- [ ] `rowbly --json add-attachment <story> --from-clipboard` with a copied `notes.txt` makes a record with `name: "notes.txt"`, `type: "text/plain"`, the correct `size`, and a stored file `<id>.txt` with the same bytes. A test with a mocked clipboard reader examines this.
- [ ] A copied file larger than 10 MiB fails with the `ValidationError` "Attachment exceeds 10 MiB". A copied folder or a path that cannot be read fails with a `ValidationError` or `NotFoundError`, and the Story does not change. A test examines this.
- [ ] When the clipboard holds two or more files, the read fails with the reason `multiple-files` and the message "The clipboard has more than one file; copy one file". A test examines this.
- [ ] When the clipboard has a file list and also an image, the file wins. A test examines this.
- [ ] On Wayland, when the types include `image/jpeg` (and no `image/png` and no file list), the read gives the JPEG bytes. The record gets `type: "image/jpeg"` and a name `image-YYYYMMDD-HHMM.jpg`. The same applies to `image/gif` (`.gif`) and `image/webp` (`.webp`). A test examines this.
- [ ] A PNG image on the clipboard still attaches as today (`image-YYYYMMDD-HHMM.png`, `type: "image/png"`). The existing clipboard tests pass, with changes only for the new result shape and messages.
- [ ] When the file-list command is not installed (`ENOENT`), the read continues with the image read and does not fail because of the missing command. A test examines this.
- [ ] All attempts of one read share the existing three-second deadline. A test examines that a file-list command gets the remaining time as its `timeout`.
- [ ] When nothing that Rowbly can attach is on the clipboard, the error message is "No file or image on the clipboard". The hint names `rowbly add-attachment <story> <file>`, and on Wayland it names wl-clipboard, and on X11 it names xclip. A test examines this.
- [ ] In the TUI, the paste key adds the copied file to the draft as a pending attachment. The toast says "File added to draft; save the Story to keep it". The progress toast says "Reading clipboard…". The key hint says "paste file". The draft summary says "N pending file(s) · B bytes". A person examines the TUI.
- [ ] `src/tui/hooks/use-story-paste.ts` does not call `readClipboardImage`, `clipboardName` or `clipboardFailure`. It calls the shared service function. A person or `grep` examines this.
- [ ] The help of `add-attachment --from-clipboard` says "read a copied file or an image from the clipboard". `docs/architecture/storage.md`, `service-layer.md`, `README.md` and `tui.md` describe the new behaviour in STE.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass.

  - Rename `readClipboardImage` to `readClipboard` (or add `readClipboard` and remove the old export, so that Knip passes).
  - Order of one read, with one deadline of three seconds: (1) the file list for the platform; (2) the native PNG read as today; (3) on Wayland, `wl-paste` for `image/png`, then `image/jpeg`, `image/gif`, `image/webp`, in that order.
  - File-list commands (use `execFile` with `timeout` = remaining time, `killSignal: "SIGKILL"`, a small `maxBuffer` such as 64 KiB):
    - Wayland (`WAYLAND_DISPLAY`): `wl-paste --list-types`. If it includes `text/uri-list`, run `wl-paste --type text/uri-list`. Else if it includes `x-special/gnome-copied-files`, run `wl-paste --type x-special/gnome-copied-files` and drop the first line (`copy` or `cut`).

    - macOS: `osascript -e 'POSIX path of (the clipboard as «class furl»)'`. A non-zero exit means no file.
    - Windows: `powershell -NoProfile -NonInteractive -Command "Get-Clipboard -Format FileDropList | ForEach-Object { $_.FullName }"`. One path on each line.

  - Put the URI-list parser in a pure function (for example `parseUriList(text): string[]`) and export it only if a test needs it (Knip).
  - The clipboard service gives a path only. It does not read the file.
  - `clipboardFailure(reason, story?)`: add the message for `multiple-files`. Make the install hint depend on the session: wl-clipboard for Wayland, xclip for X11.

## Assumptions

- One copied file per paste. Two or more files fail with `multiple-files`. Reason: `addAttachment` returns one attachment and the Story says "attach that file". This is the smallest scope. A later Story can add more files.
- When the clipboard has a file list and an image, Rowbly attaches the file. Reason: a file manager can also offer a thumbnail image, and the user copied the file.
- Other image types come only from `wl-paste` on Wayland. Reason: the Story names `image/jpeg` from `wl-paste`. On the other platforms the native binding already converts an image to PNG.
- The reason code `no-image` stays the same and only its message changes. Reason: `--json` users can read the code; a new code is not necessary.
- A missing `xclip`, `osascript` or `powershell` does not fail the read; Rowbly continues with the image read. Reason: the PNG paste must work as today on a system without these commands.
- A copied folder is an error and not an archive. Reason: smallest scope.
- The developer merges `main` first. Reason: the worktree base at refinement time did not have the ROW-108 changes.
